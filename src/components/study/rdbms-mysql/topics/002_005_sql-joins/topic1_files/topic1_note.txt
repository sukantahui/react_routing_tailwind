1. WHAT IS AN INNER JOIN?
--------------------------------------------------------------------------------
An `INNER JOIN` is the most widely used relational join operation in SQL.
It returns ONLY those rows from both tables that satisfy the specified join condition 
in the `ON` clause. Any row from either table that does NOT have a corresponding match 
is excluded from the final result set.

Mathematical Definition:
Given relations $R_1$ and $R_2$, the equi-inner join on attribute $A$ ($R_1 \bowtie_{R_1.A = R_2.A} R_2$) is:
      $R_1 \bowtie R_2 = \{ t_1 \circ t_2 \mid t_1 \in R_1, t_2 \in R_2 \land t_1.A = t_2.A \}$


2. SQL SYNTAX VARIATIONS FOR INNER JOIN
--------------------------------------------------------------------------------

1. Explicit ANSI SQL-92 Standard (RECOMMENDED & INDUSTRY BEST PRACTICE):
```sql
SELECT 
    s.student_id,
    s.student_name,
    c.course_name,
    c.course_fee
FROM students s
INNER JOIN courses c ON s.course_id = c.course_id;
```

2. Implicit "JOIN" Keyword (Default Inner Join):
```sql
-- The "INNER" keyword is optional; "JOIN" defaults to INNER JOIN
SELECT s.student_name, c.course_name
FROM students s
JOIN courses c ON s.course_id = c.course_id;
```

3. Legacy Comma Syntax with WHERE Filter (DISCOURAGED):
```sql
-- Obsolete ANSI-89 syntax (error-prone, hard to distinguish join from row filters)
SELECT s.student_name, c.course_name
FROM students s, courses c
WHERE s.course_id = c.course_id;
```


3. THE ANATOMY OF THE `ON` PREDICATE
--------------------------------------------------------------------------------
The `ON` clause defines the logical criteria for matching tuples across tables:
• Equi-Join Condition: `ON s.course_id = c.course_id` (matches exact values).
• Compound / Multi-Column Condition: `ON s.batch_id = c.batch_id AND s.semester = c.semester`
• Expression Condition: `ON s.student_code = UPPER(c.enrolled_code)`

Crucial Rule on `WHERE` vs `ON`:
• `ON` determines how rows are MATCHED during the join.
• `WHERE` filters rows AFTER the join has occurred.
• In an `INNER JOIN`, placing filtering conditions in `ON` or `WHERE` produces identical results, 
  but placing table matching in `ON` and business filters in `WHERE` improves code clarity!


4. THE BENCHMARK ACADEMY EXAMPLE
--------------------------------------------------------------------------------
Table: `students`
| student_id | student_name  | course_id |
| ---------- | ------------- | --------- |
| 101        | Mamata Hui    | C101      |
| 102        | Debangshu Roy | C102      |
| 103        | Susmita Sen   | NULL      |
| 104        | Mahima Shaw   | C105 (N/A)|

Table: `courses`
| course_id | course_name    | fee     |
| --------- | -------------- | ------- |
| C101      | MySQL Master   | ₹4,500  |
| C102      | React Architect| ₹5,500  |
| C103      | Python AI      | ₹6,000  |

INNER JOIN Query Result:
| student_id | student_name  | course_name    | fee     |
| ---------- | ------------- | -------------- | ------- |
| 101        | Mamata Hui    | MySQL Master   | ₹4,500  |
| 102        | Debangshu Roy | React Architect| ₹5,500  |

Why other rows are excluded:
• Susmita Sen has `course_id = NULL` (does not match any course).
• Mahima Shaw has `course_id = C105` (does not exist in courses table).
• Course `C103 (Python AI)` has zero enrolled students.


5. COMMON PITFALLS & DANGER ZONES
--------------------------------------------------------------------------------
1. Expecting Unmatched Rows:
   If you need students with NULL courses or courses with zero enrollments, use `LEFT JOIN` or `RIGHT JOIN`.
2. Missing Table Aliases:
   Always alias tables (`FROM students s INNER JOIN courses c`) to avoid repetitive SQL code.
3. Joining on Incompatible Data Types:
   Joining `VARCHAR` to `INT` disables index usage and causes silent type conversions.


6. SUMMARY CHECKLIST
--------------------------------------------------------------------------------
[x] `INNER JOIN` returns ONLY rows with valid matches in BOTH tables.
[x] The `INNER` keyword is optional (`JOIN` is identical to `INNER JOIN`).
[x] Always use explicit ANSI `INNER JOIN ... ON` syntax rather than comma joins.
[x] Discards rows with `NULL` or non-matching foreign keys.
[x] Use composite `ON` conditions (`AND`) when joining on composite primary/foreign keys.
