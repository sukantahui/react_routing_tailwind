1. WHAT IS A FULL OUTER JOIN?
--------------------------------------------------------------------------------
A `FULL OUTER JOIN` (or `FULL JOIN`) combines the results of both `LEFT JOIN` and `RIGHT JOIN`.
It returns:
1. ALL matching rows from both tables.
2. ALL unmatched rows from the Left table (with `NULL`s for Right table columns).
3. ALL unmatched rows from the Right table (with `NULL`s for Left table columns).

Mathematical Definition:
Given relations $R_1$ (Left) and $R_2$ (Right), the Full Outer Join ($R_1 ⟗ R_2$) is:
      $R_1 ⟗ R_2 = (R_1 ⟕ R_2) \cup (R_1 ⟖ R_2)$


2. THE MYSQL LIMITATION: WHY NO NATIVE FULL OUTER JOIN?
--------------------------------------------------------------------------------
Unlike PostgreSQL, SQL Server, and Oracle, MySQL does NOT support native `FULL OUTER JOIN` syntax!
Writing `SELECT * FROM students FULL OUTER JOIN courses ...` in MySQL will immediately throw:
`ERROR 1064 (42000): You have an error in your SQL syntax`.

The Solution:
In MySQL, we emulate a FULL OUTER JOIN using the Set Union operator:
      $\text{FULL OUTER JOIN} \equiv (\text{LEFT JOIN}) \cup (\text{RIGHT JOIN})$


3. THE STANDARD MYSQL EMULATION PATTERN (LEFT JOIN + UNION + RIGHT JOIN)
--------------------------------------------------------------------------------
```sql
-- Pattern 1: Standard FULL OUTER JOIN Emulation in MySQL:
SELECT 
    s.student_id,
    s.student_name,
    s.city,
    c.course_id,
    c.course_title,
    c.course_fee
FROM students s
LEFT JOIN courses c ON s.course_id = c.course_id

UNION

SELECT 
    s.student_id,
    s.student_name,
    s.city,
    c.course_id,
    c.course_title,
    c.course_fee
FROM students s
RIGHT JOIN courses c ON s.course_id = c.course_id;
```

Why `UNION` (Not `UNION ALL`):
• `UNION` automatically eliminates the duplicate matching rows generated by both the LEFT and RIGHT queries!
• Using `UNION ALL` would output the matching rows TWICE!


4. THE HIGH-PERFORMANCE OPTIMIZED EMULATION PATTERN (UNION ALL + ANTI-JOIN)
--------------------------------------------------------------------------------
For large datasets, the standard `UNION` can be slow because it performs an expensive in-memory 
deduplication sort. Senior database architects use the optimized pattern:

```sql
-- Pattern 2: Optimized FULL OUTER JOIN (No In-Memory Deduplication Sort):
SELECT 
    s.student_id,
    s.student_name,
    c.course_title,
    c.course_fee
FROM students s
LEFT JOIN courses c ON s.course_id = c.course_id

UNION ALL

SELECT 
    s.student_id,
    s.student_name,
    c.course_title,
    c.course_fee
FROM courses c
LEFT JOIN students s ON c.course_id = s.course_id
WHERE s.student_id IS NULL; -- Only append unmatched right rows!
```
Performance Win:
`UNION ALL` avoids duplicate sorting because the anti-join query (`WHERE IS NULL`) returns 
ONLY the unmatched rows that were not present in the first `LEFT JOIN`!
