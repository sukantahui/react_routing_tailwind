2. CORE CONCEPTS & IMPLEMENTATION RUNBOOKS
--------------------------------------------------------------------------------
[1. SEED GENERATION]
Batching inserts inside transactions (5,000 rows per batch) reduces redo log flushes and generates 100,000 records in seconds.

SQL Implementation:
-- ⚡ GENERATING 100,000 SEED RECORDS VIA STORED PROCEDURE:
DELIMITER $$
CREATE PROCEDURE seed_customers(IN num_rows INT)
BEGIN
  DECLARE i INT DEFAULT 1;
  START TRANSACTION;
  WHILE i <= num_rows DO
    INSERT INTO customers (full_name, email, phone, credit_limit)
    VALUES (
      CONCAT('Customer_', i),
      CONCAT('user_', i, '@example.in'),
      CONCAT('+91', LPAD(FLOOR(RAND() * 9000000000) + 1000000000, 10, '0')),
      ROUND(RAND() * 100000 + 10000, 2)
    );
    IF i % 5000 = 0 THEN
      COMMIT;
      START TRANSACTION;
    END IF;
    SET i = i + 1;
  END WHILE;
  COMMIT;
END $$
DELIMITER ;
CALL seed_customers(100000);

Takeaways:
- Avoid auto-committing individual inserts (100x speedup with batch transactions).
- Use mathematical functions (RAND, FLOOR, LPAD) to generate realistic phone numbers and amounts.
- Disable secondary indexes temporarily during multi-million row bulk loading if needed.

[3. BULK LOAD DATA]
LOAD DATA INFILE bypasses SQL query parser overhead, streaming CSV files directly into the InnoDB storage engine at maximum disk speed.

SQL Implementation:
-- 🚀 IMPORTING 1,000,000 ROWS IN 3 SECONDS:
LOAD DATA INFILE '/var/lib/mysql-files/seed_orders.csv'
INTO TABLE orders
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
LINES TERMINATED BY '
'
IGNORE 1 ROWS
(order_id, customer_id, total_amount, order_status, created_at);

Takeaways:
- LOAD DATA INFILE is 20x faster than batch multi-row INSERT statements.
- Configure secure_file_priv to specify permitted CSV file directories.
- Use IGNORE 1 ROWS to skip header lines in generated CSV files.

4. SENIOR PITFALLS & PRODUCTION BEST PRACTICES
--------------------------------------------------------------------------------
Pitfalls to Avoid:
- Pitfall 1: Committing Per Row: Executing COMMIT after each individual INSERT statement causes massive disk I/O write head stalls, taking hours to insert 50,000 rows. (Rule: Wrap bulk inserts in 5,000 to 10,000 row transaction blocks.)
- Pitfall 2: Pure Uniform Distribution: Generating purely uniform random numbers fails to test index clustering on popular products or active customers. (Rule: Model Pareto (80/20) skew to simulate realistic real-world traffic patterns.)

Production Best Practices:
- Best Practice 1: Automate Seeding with Seed Scripts: Store seed scripts in db/seeds/seed_data.sql or a Python generator with a single command runbook. (Allows anyone evaluating the capstone to regenerate the entire database instantly.)
- Best Practice 2: Verify Record Counts Post-Seed: Run SELECT COUNT(*) across all tables to confirm expected row volumes before testing queries. (Ensures no silent foreign key check failure truncated data loads.)
