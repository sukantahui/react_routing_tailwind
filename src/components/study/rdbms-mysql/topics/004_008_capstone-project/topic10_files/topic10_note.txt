4. SENIOR PITFALLS & PRODUCTION BEST PRACTICES
--------------------------------------------------------------------------------
Pitfalls to Avoid:
- Pitfall 1: Empty or Incomplete README: Submitting a GitHub repository with just SQL files and no explanatory README prevents evaluators from understanding your architectural design. (Rule: Treat the README as your project's executive summary and user guide.)
- Pitfall 2: Memorizing Answers Without Understanding: Failing to explain why an index was created or how a trigger works during viva defense damages credibility. (Rule: Understand the underlying B-Tree, MVCC, and transactional mechanics thoroughly.)

Production Best Practices:
- Best Practice 1: Perform a Dry Run Viva with Peers: Have a classmate grill your project with edge-case questions (e.g. deadlock scenarios, backup failures). (Builds spontaneous technical communication skills under pressure.)
- Best Practice 2: Pin the Repository on GitHub: Pin your capstone repository to your GitHub profile and include it in your email signature and resume. (Maximizes visibility to tech leads and hiring managers.)
