[1. ENGINEERING STANDARDS]
Production capstone databases must follow industry-grade conventions including strict data types, UTF8MB4 charset, audit triggers, and explicit naming conventions.

SQL Implementation:
-- 🏢 ENTERPRISE DATABASE STANDARDS IN MYSQL 8.0:
-- 1. Explicit strict schema definitions (NO generic VARCHAR(255) for all fields).
-- 2. UTF8MB4 charset with utf8mb4_0900_ai_ci collation across all tables.
-- 3. Explicit Foreign Key constraints with well-planned referential actions (CASCADE/RESTRICT).
-- 4. Mandatory audit timestamps (created_at, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP).
-- 5. Strict index strategy (every FK indexed, composite indexes aligned with leftmost prefix).

Takeaways:
- Follow consistent snake_case naming for all tables, columns, indexes, and constraints.
- Every table must have an explicit Primary Key with indexed foreign dependencies.
- All monetary and ledger values must use DECIMAL(15,2) or DECIMAL(18,4), never FLOAT.

[4. DISQUALIFYING FLAWS]
Common pitfalls such as CSV columns, lack of indexes, and unconstrained nullability disqualify enterprise database submissions.

SQL Implementation:
-- ⚠️ DISQUALIFYING ANTI-PATTERNS:
-- 1. Unnormalized repeating groups or multi-valued CSV columns (1NF violation).
-- 2. Storing plain-text passwords without SHA-256/bcrypt hashing.
-- 3. Storing currency as FLOAT or DOUBLE causing floating-point rounding errors.
-- 4. Missing foreign key indexes causing full table lock scans during joins.
-- 5. Using SELECT * in production reporting procedures without explicit columns.

Takeaways:
- Never store multiple values in a single delimited string column.
- Always define explicit precision on currency and percentage columns.
- Ensure every foreign key column is supported by an index.

4. SENIOR PITFALLS & PRODUCTION BEST PRACTICES
--------------------------------------------------------------------------------
Pitfalls to Avoid:
- Pitfall 1: Insufficient Seed Data: Testing queries against 20 rows hides query execution bottlenecks. Always seed 100,000+ realistic records to validate B-Tree indexes and EXPLAIN plans. (Rule: Generate realistic multi-thousand row datasets for accurate performance benchmarking.)
- Pitfall 2: Storing Unhashed Credentials: Saving application user passwords in plain text violates data security standards and results in project failure. (Rule: Store only cryptographically salted and hashed passwords (e.g., CHAR(60)).)

Production Best Practices:
- Best Practice 1: Comprehensive Documentation: Maintain a complete repository containing EER diagrams, DDL scripts, seed scripts, query runbooks, and disaster recovery guides. (Ensures seamless auditability, team handover, and viva defense.)
- Best Practice 2: Version-Controlled Migrations: Number and sequence all DDL schema scripts (e.g. V1__init_schema.sql, V2__indexes.sql) for reproducible database deployments. (Prevents environment drift between development and production.)
