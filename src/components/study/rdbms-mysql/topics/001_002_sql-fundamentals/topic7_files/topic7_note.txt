1. WHAT IS THE INSERT INTO STATEMENT?
--------------------------------------------------------------------------------
The `INSERT INTO` statement is the primary DML (Data Manipulation Language) command used
to populate relational tables with new records (tuples). In MySQL InnoDB, each insert acquires
exclusive row-level locks, assigns auto-increment keys if applicable, validates column constraints,
and writes entries to the clustered index and redo log.


2. THE 4 PRIMARY INSERT VARIATIONS
--------------------------------------------------------------------------------
A. SINGLE-ROW INSERT (EXPLICIT COLUMNS):
   INSERT INTO table_name (col1, col2, col3)
   VALUES (val1, val2, val3);

   Example:
   INSERT INTO students (first_name, last_name, email, admission_fee)
   VALUES ('Mamata', 'Hui', 'mamata@codernaccotax.in', 15000.00);

B. MULTI-ROW (BULK / BATCH) INSERT:
   Instead of executing 100 individual INSERT queries over the network, batch multiple rows
   separated by commas into a single query. Multi-row inserts are up to 20x faster!
   
   Example:
   INSERT INTO students (first_name, last_name, email, admission_fee)
   VALUES 
       ('Abhronila', 'Das', 'abhronila@gmail.com', 18500.00),
       ('Susmita', 'Ghosh', 'susmita@kolkata.org', 15000.00),
       ('Debangshu', 'Roy', 'debangshu@fintech.co.in', 20000.00);

C. PARTIAL COLUMN INSERT (LEVERAGING DEFAULTS & NULL):
   Omitting non-mandatory columns allows MySQL to automatically populate them with their
   defined `DEFAULT` value or auto-increment sequence number.
   
   Example:
   -- roll_no and is_active take their default definitions
   INSERT INTO students (first_name, last_name, email)
   VALUES ('Mahima', 'Sengupta', 'mahima@jadavpur.edu');

D. INSERT INTO ... SELECT (SUBQUERY / ETL POPULATION):
   Copies records dynamically from one table to another without passing through client memory.
   
   Example:
   INSERT INTO honor_students (student_id, full_name, gpa)
   SELECT student_id, CONCAT(first_name, ' ', last_name), gpa
   FROM students
   WHERE gpa >= 3.8;


3. ADVANCED INSERT EXTENSIONS IN MYSQL
--------------------------------------------------------------------------------
A. INSERT IGNORE:
   Suppresses duplicate key errors (Error 1062) for PRIMARY or UNIQUE keys, converting them
   into non-fatal warnings and skipping already-existing rows.

B. ON DUPLICATE KEY UPDATE (UPSERT):
   If the row does not exist, it inserts. If a PRIMARY or UNIQUE key collision occurs, it performs an UPDATE instead!
   
   Example:
   INSERT INTO pharmacy_stock (medicine_id, stock_quantity)
   VALUES (101, 50)
   ON DUPLICATE KEY UPDATE stock_quantity = stock_quantity + 50;

C. INSERT INTO ... SET SYNTAX (MYSQL SPECIFIC):
   INSERT INTO students
   SET first_name = 'Mamata',
       last_name = 'Hui',
       email = 'mamata@barrackpore.in';


4. RETRIEVING AUTO-GENERATED PRIMARY KEYS
--------------------------------------------------------------------------------
To obtain the auto-increment ID generated by the most recent INSERT in your connection session:
   SELECT LAST_INSERT_ID();
   -- Thread-safe, returns the ID assigned in the current connection.

6. COMMON PITFALLS & DANGER ZONES
--------------------------------------------------------------------------------
1. Column Count vs Value Count Mismatch (Error 1136):
   - Specifying 4 column names but only providing 3 values in the `VALUES (...)` clause.
2. Missing Mandatory Non-Null Columns (Error 1364):
   - Omitting a column defined as `NOT NULL` with no `DEFAULT` in strict SQL mode.
3. String Delimiter Quotes:
   - Forgetting quotes around strings and dates (`'2026-08-24'`) causes syntax errors.
4. Using Floating Point for Indian Currency (₹):
   - Always verify the destination column is `DECIMAL(10, 2)` to avoid binary precision loss.


7. BEST PRACTICES & SUMMARY CHECKLIST
--------------------------------------------------------------------------------
[x] Always explicitly list column names in `INSERT INTO table_name (col1, col2)` rather than relying on positional inserts.
[x] Use multi-row batch inserts for high throughput bulk loading.
[x] Use `ON DUPLICATE KEY UPDATE` (Upsert) for idempotent inventory and counter updates.
[x] Use `LAST_INSERT_ID()` in application backends to link parent/child relationship records.
[x] Verify dates follow the ISO format: `'YYYY-MM-DD'`.
