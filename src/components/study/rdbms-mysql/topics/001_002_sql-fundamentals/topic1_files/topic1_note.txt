1. WHAT IS A DATABASE (SCHEMA) IN MYSQL?
--------------------------------------------------------------------------------
In MySQL, the terms `DATABASE` and `SCHEMA` are exact synonyms. 
A database is a named logical container (namespace) that houses:
• Tables (Relations) and Columns (Attributes)
• Views (Virtual Tables)
• Stored Procedures and User-Defined Functions
• Triggers and Scheduled Events
• Database-level permissions and default character set/collation configurations

Physically on the server's disk, MySQL creates a subdirectory under the data directory (`datadir`) corresponding to each database name, and records its metadata in the transactional data dictionary.


2. THE CREATE DATABASE STATEMENT
--------------------------------------------------------------------------------
A. BASIC SYNTAX:
   CREATE DATABASE database_name;

B. PRODUCTION-GRADE IDEMPOTENT SYNTAX:
   CREATE DATABASE IF NOT EXISTS database_name
   CHARACTER SET utf8mb4
   COLLATE utf8mb4_0900_ai_ci;

KEY CLAUSES EXPLAINED:
• IF NOT EXISTS:
  - Prevents MySQL from throwing Error 1007: "Can't create database 'db_name'; database exists".
  - Vital for CI/CD deployment pipelines, automated Docker setups, and repeatable SQL migration scripts.
• CHARACTER SET utf8mb4:
  - Specifies 4-byte UTF-8 encoding, supporting English, Indian languages (Bengali, Hindi), and emojis.
• COLLATE utf8mb4_0900_ai_ci:
  - Specifies the collation rules:
    * `0900`: Unicode 9.0 weight keys algorithm.
    * `ai`: Accent-insensitive (e.g. 'e' equals 'é').
    * `ci`: Case-insensitive (e.g. 'Kolkata' matches 'kolkata').


3. THE DROP DATABASE STATEMENT (IRREVERSIBLE DESTRUCTION)
--------------------------------------------------------------------------------
A. BASIC SYNTAX:
   DROP DATABASE database_name;

B. SAFE IDEMPOTENT SYNTAX:
   DROP DATABASE IF EXISTS database_name;

WHAT HAPPENS INTERNALLY WHEN A DATABASE IS DROPPED:
1. All tables, indexes, views, stored procedures, functions, and triggers inside the database are permanently deleted.
2. The physical directory and `.ibd` tablespace files on the host file system are unlinked and wiped from disk.
3. System privileges assigned specifically to this database are orphaned or cleaned.
4. THERE IS NO RECYCLE BIN OR TRASH CAN IN MYSQL!
   Once dropped, data can only be recovered from previous physical/logical backups (`mysqldump`) and binary logs.


4. DEFAULT SYSTEM DATABASES (NEVER DROP THESE!)
--------------------------------------------------------------------------------
When MySQL is installed, 4 critical system databases are created automatically:
1. `mysql`: Contains user accounts, authentication hashes, privileges, time zones, plugin definitions, and internal transactional dictionaries. Dropping or corrupting this will break the entire MySQL server!
2. `information_schema`: Read-only ANSI standard database providing metadata about tables, columns, indexes, data types, and server privileges.
3. `performance_schema`: Low-level diagnostic database that monitors execution events, query latency, lock contention, and memory allocation.
4. `sys`: A collection of user-friendly views and stored procedures built on top of `performance_schema` and `information_schema` for quick DBA troubleshooting.

6. COMMON PITFALLS & BEGINNER MISTAKES
--------------------------------------------------------------------------------
1. Dropping Production Database without an Active Backup:
   - A single typo like `DROP DATABASE prod_db;` instead of `DROP DATABASE test_db;` can cause catastrophic data loss.
2. Forgetting `IF NOT EXISTS` in Automation Scripts:
   - If the database already exists, scripts crash immediately with Error 1007.
3. Using SQL Reserved Words as Database Names without Backticks:
   - E.g., `CREATE DATABASE order;` fails with syntax error because `ORDER` is a keyword.
   - Fix: Use backticks `CREATE DATABASE \`order\`;` or better, use descriptive names like `order_management_db`.
4. Case Sensitivity Confusion on Linux vs Windows:
   - On Windows, database names are case-insensitive.
   - On Linux, database names correspond to Linux directories and ARE CASE-SENSITIVE by default (`lower_case_table_names=0`).
   - Fix: Always use lowercase `snake_case` names (e.g. `student_portal_db`).


7. BEST PRACTICES & SUMMARY CHECKLIST
--------------------------------------------------------------------------------
[x] Always use `IF NOT EXISTS` when creating databases in automated scripts.
[x] Always use `IF EXISTS` when dropping databases in teardown scripts.
[x] Explicitly declare `CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci`.
[x] Standardize on all-lowercase `snake_case` database names to avoid OS cross-platform issues.
[x] Never touch or drop MySQL default system databases (`mysql`, `information_schema`, `sys`, `performance_schema`).
[x] Restrict `DROP` privileges from standard application user accounts in production.
