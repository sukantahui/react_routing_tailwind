1. WHAT IS A JOIN DEPENDENCY (JD)?
--------------------------------------------------------------------------------
A Join Dependency (denoted as $\Join [R_1, R_2, \dots, R_n]$) was introduced by 
Ronald Fagin in 1979 as a generalization of Multi-valued Dependencies.

Formal Definition:
A relation schema R satisfies the Join Dependency $\Join [R_1, R_2, \dots, R_n]$ (where $R_1 \cup R_2 \cup \dots \cup R_n = R$) 
if and only if every legal instance r of R is equal to the Natural Join of its projections on $R_1, R_2, \dots, R_n$:

      $r = \pi_{R_1}(r) \bowtie \pi_{R_2}(r) \bowtie \dots \bowtie \pi_{R_n}(r)$

Key Insight:
A Multi-valued Dependency (MVD) $X \twoheadrightarrow Y$ is simply a BINARY Join Dependency:
$\Join [X \cup Y, X \cup (R - Y)]$.
A general Join Dependency (JD) extends this to 3 or more tables ($n \ge 3$) that CANNOT be 
decomposed losslessly into 2 tables, but CAN be decomposed losslessly into 3 (or more) tables!


2. WHAT IS FIFTH NORMAL FORM (5NF / PJNF)?
--------------------------------------------------------------------------------
Fifth Normal Form (5NF), also known as Project-Join Normal Form (PJNF), represents 
the theoretical limit of lossless decomposition using project-join operators.

Formal Definition of 5NF:
A relation schema R is in Fifth Normal Form (5NF) if and only if:
1. It is in Fourth Normal Form (4NF).
2. For EVERY non-trivial Join Dependency $\Join [R_1, R_2, \dots, R_n]$ holding on R:
   EVERY $R_i$ IS A SUPER KEY OF R.

Plain English Meaning:
A relation is in 5NF if it cannot be decomposed into any number of smaller tables 
without losing information, UNLESS every piece already contains a Candidate Key of the original table.
If a table is in 5NF, it is free of ALL redundancy that could possibly be eliminated by 
relational projection and join!


3. THE BENCHMARK 5NF VIOLATION (THE TERNARY CYCLIC RELATIONSHIP)
--------------------------------------------------------------------------------
Consider an academy consulting partnership table:
`Developer_Company_Project(developer, company, project)`

Domain Rule (The 3-Way Cyclic Constraint):
• If developer D works for company C, AND
• Developer D works on project P, AND
• Company C sponsors project P, THEN
• Developer D MUST work on project P for company C!

Why this table cannot be decomposed into 2 tables:
• Decomposing into 2 tables creates spurious (false) tuples on join!
• BUT decomposing into 3 tables reconstructs the exact original relation losslessly:
  1. $R_1(\text{developer}, \text{company})$
  2. $R_2(\text{company}, \text{project})$
  3. $R_3(\text{developer}, \text{project})$

Natural Join of all 3 tables:
$R_1 \bowtie R_2 \bowtie R_3 = \text{Original Table}$ (Lossless Join!).


4. 5NF IN REAL-WORLD PRACTICAL DATABASE ENGINEERING
--------------------------------------------------------------------------------
1. Rarity in Production:
   True 5NF violations are rare in practice because ternary cyclic constraints are uncommon.
2. Modeling in ER Diagrams:
   Ternary relationships with cyclic constraints should be explicitly modeled as separate 
   binary association tables rather than a single monolithic ternary table.
3. Theoretical Peak:
   5NF is the final normal form for projection-join dependencies. Higher forms (DKNF, 6NF) 
   deal with domain-key constraints and temporal/historized data.
