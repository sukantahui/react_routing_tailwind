2. THEORETICAL FOUNDATION & MATRICES
--------------------------------------------------------------------------------
- Core Concept: Relational normalization ensures that data dependencies are modeled
  strictly according to business invariants, preventing update, deletion, and insertion anomalies.
- Formal Rule: 1. Comma-Separated Values (CSV) Violation in Single Cell
- Decomposition Strategy: Decompose multivalued attributes into a discrete child table where each row contains exactly one scalar value.

3. BEFORE-VS-AFTER SCHEMA TRANSFORMATION
--------------------------------------------------------------------------------
UNNORMALIZED / NON-COMPLIANT STATE:
Student 'Susmita Ghosh' has hobbies stored as 'Coding, Chess, Robotics' in a single VARCHAR column.
Root Cause: Violates 1NF rule: Every column in every row must hold atomic (indivisible) scalar values.

NORMALIZED STATE:
Full 1NF compliance allows direct B-Tree indexing, deterministic GROUP BY aggregations, and standard SQL JOIN operations.

4. SENIOR ARCHITECTURAL PITFALLS & BEST PRACTICES
--------------------------------------------------------------------------------
- PITFALL: Hardcoded column repetitions waste disk space with NULLs and complicate WHERE clause search queries.
- BEST PRACTICE: Full 1NF compliance allows direct B-Tree indexing, deterministic GROUP BY aggregations, and standard SQL JOIN operations.
- ACID INVARIANT: Always declare explicit foreign keys with ON DELETE RESTRICT to protect transactional ledgers.
