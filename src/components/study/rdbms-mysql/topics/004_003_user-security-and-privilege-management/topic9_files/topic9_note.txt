MYSQL 8.0 DATABASE SECURITY & PRIVILEGE MANAGEMENT
TOPIC 9: The Principle of Least Privilege & Secure Service Accounts
================================================================================

1. THE PRINCIPLE OF LEAST PRIVILEGE (PoLP) IN DATABASE DESIGN
--------------------------------------------------------------------------------
The Principle of Least Privilege dictates that an application account or user
must be granted ONLY the minimum necessary permissions required to fulfill its
specific operational role—and nothing more.

Core Objectives:
- Limit Blast Radius: If a web application microservice is compromised via SQL
  injection or supply-chain vulnerability, the attacker cannot drop tables,
  read unrelated schemas, or compromise the server OS.
- Prevent Accidental Data Corruption: Prohibits application code from issuing
  unauthorized DDL statements (`DROP TABLE`, `TRUNCATE`).
- Regulatory Compliance: Satisfies PCI-DSS, SOC 2, HIPAA, and ISO 27001 mandates.

2. SERVICE ACCOUNT PROVISIONING ARCHETYPE (THE 6 RULES)
--------------------------------------------------------------------------------
Rule 1: Dedicated Per-Service Accounts
  - Never share a single `db_user` across multiple microservices.
  - Create `order_svc`, `payment_svc`, `inventory_svc` independently.

Rule 2: Restrict Host Binding to Private Subnets
  - Never use `'svc'@'%'`.
  - Bind to specific VPC CIDR blocks: `'svc'@'10.244.%.%'` or `'svc'@'192.168.10.%'`.

Rule 3: Use Modern NIST-Grade Authentication
  - Use `caching_sha2_password` with strong randomized passwords generated by Vault.
  - Enforce `REQUIRE SSL` on all network accounts.

Rule 4: Explicit DML Only (Never DDL)
  - Applications in production need `SELECT`, `INSERT`, `UPDATE`, `DELETE`.
  - Application accounts should NEVER hold `CREATE`, `DROP`, `ALTER`, or `TRUNCATE`.
  - Database schema migrations (Flyway / Liquibase) must run under a separate,
    isolated migration runner account used only during CI/CD deployments.

Rule 5: Enforce Connection Quotas
  - Configure `WITH MAX_USER_CONNECTIONS N` to prevent pool exhaustion attacks.

Rule 6: Password Expiration Exemption
  - Set `PASSWORD EXPIRE NEVER` to prevent sudden production microservice outages.

3. GOLDEN SERVICE ACCOUNT PROVISIONING TEMPLATE
--------------------------------------------------------------------------------
-- 1. Ingestion / Telemetry Microservice (Append-Only):
CREATE USER 'telemetry_collector'@'10.10.15.%'
  IDENTIFIED WITH caching_sha2_password BY 'VaultGeneratedPass#2026'
  REQUIRE SSL
  PASSWORD EXPIRE NEVER
  WITH MAX_USER_CONNECTIONS 30;

GRANT INSERT ON iot_telemetry.sensor_readings TO 'telemetry_collector'@'10.10.15.%';

-- 2. Core Order Processing Microservice (Read-Write DML):
CREATE USER 'order_service'@'10.10.20.%'
  IDENTIFIED WITH caching_sha2_password BY 'VaultGeneratedPass#2026'
  REQUIRE SSL
  PASSWORD EXPIRE NEVER
  WITH MAX_USER_CONNECTIONS 50;

GRANT SELECT, INSERT, UPDATE ON ecommerce.orders TO 'order_service'@'10.10.20.%';
GRANT SELECT ON ecommerce.inventory TO 'order_service'@'10.10.20.%';

-- 3. Dedicated CI/CD Schema Migration Account (DDL Runner):
CREATE USER 'flyway_migrator'@'10.10.99.10'
  IDENTIFIED WITH caching_sha2_password BY 'EphemeralDeployPass#2026'
  REQUIRE SSL
  PASSWORD EXPIRE NEVER
  WITH MAX_USER_CONNECTIONS 5;

GRANT CREATE, ALTER, DROP, INDEX, REFERENCES ON ecommerce.* TO 'flyway_migrator'@'10.10.99.10';

4. AUDITING LEAST PRIVILEGE COMPLIANCE
--------------------------------------------------------------------------------
-- Audit: Find application accounts with unauthorized DDL rights:
SELECT User, Host, Db, Create_priv, Drop_priv, Alter_priv 
FROM mysql.db 
WHERE (Create_priv = 'Y' OR Drop_priv = 'Y' OR Alter_priv = 'Y')
  AND User NOT LIKE '%migrator%' AND User NOT LIKE '%dba%';
