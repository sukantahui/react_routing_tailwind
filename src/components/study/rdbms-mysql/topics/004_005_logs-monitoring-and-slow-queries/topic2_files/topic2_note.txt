================================================================================
MYSQL 8.0 SERVER LOGS, MONITORING & PERFORMANCE SCHEMA
TOPIC 2: The General Query Log – Enabling, Inspection, Overhead & Debugging
================================================================================

1. WHAT IS THE GENERAL QUERY LOG?
--------------------------------------------------------------------------------
The General Query Log is a comprehensive audit record that writes:
- Every client connection event (User, Host, IP, Thread ID, Timestamp).
- Every client disconnection event.
- Every SQL query received from any connected client, in the exact chronological
  order received by the server BEFORE query execution.

2. RUNTIME CONFIGURATION & TOGGLES
--------------------------------------------------------------------------------
A. Dynamic Runtime Toggle:
   -- Enable for short-term debugging:
   SET GLOBAL general_log = 'ON';
   SET GLOBAL general_log_file = '/var/log/mysql/general_debug.log';

   -- Disable immediately when debugging is complete:
   SET GLOBAL general_log = 'OFF';

B. Storage Destination (`log_output`):
   - `log_output = 'FILE'`: Writes to filesystem text file (Recommended).
   - `log_output = 'TABLE'`: Writes to database table `mysql.general_log`.

3. WHY IT MUST NEVER RUN IN PRODUCTION (15-30% PERFORMANCE DROP)
--------------------------------------------------------------------------------
1. Extreme Disk I/O Saturation:
   - On a server executing 20,000 QPS, the general query log generates over 1.2 million
     disk write events per minute, consuming gigabytes of disk I/O and storage.
2. Security & Compliance Risks (Plaintext Passwords):
   - Unprepared SQL queries containing plaintext passwords (`CREATE USER ... IDENTIFIED BY`)
     or sensitive customer data are recorded unencrypted in the log file.
3. Lock Contention on TABLE Logging:
   - Writing to `mysql.general_log` (CSV engine) creates table lock contention during
     concurrent query bursts.

4. LEGITIMATE DEBUGGING USE CASES
--------------------------------------------------------------------------------
- ORM Query Inspection: Revealing rogue N+1 query patterns generated by Hibernate or Prisma.
- Connection Pool Forensics: Identifying leaky application services that spawn hundreds
  of connection handshakes per second.
- Breach Incident Response: Capturing an active attacker's exact SQL injection payloads
  during an ongoing security incident (temporary 5-10 minute capture window).

5. PRODUCTION BEST PRACTICES
--------------------------------------------------------------------------------
1. Keep `general_log = 'OFF'` permanently in production configuration files.
2. If temporary debugging is mandatory, enable for max 5-10 minutes during low-traffic hours.
3. Always truncate `mysql.general_log` after debugging to reclaim storage space.
4. Use the Slow Query Log or Performance Schema for continuous performance monitoring.
