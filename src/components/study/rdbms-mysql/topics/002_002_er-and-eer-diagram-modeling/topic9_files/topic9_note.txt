1. THE TWO ORTHOGONAL CONSTRAINTS ON SPECIALIZATION / GENERALIZATION
--------------------------------------------------------------------------------
In Extended ER (EER) modeling, any specialization or generalization hierarchy is governed
by TWO independent, orthogonal constraints:

CONSTRAINT 1: DISJOINTNESS CONSTRAINT (DISJOINT 'd' VS OVERLAPPING 'o')
• Specifies whether an entity instance can be a member of MORE THAN ONE subclass simultaneously:
  A. Disjoint Specialization ('d'):
     - An entity instance can belong to AT MOST ONE subclass in the hierarchy.
     - Subclasses are mutually exclusive ($Subclass_1 \cap Subclass_2 = \emptyset$).
     - Notation in EER: Circle containing the letter 'd'.
     - Example: `Vehicle` specialized into `Car`, `Truck`, `Motorcycle` (a vehicle cannot be both a Car and a Motorcycle).
  B. Overlapping Specialization ('o'):
     - An entity instance can belong to MULTIPLE subclasses simultaneously.
     - Subclasses can overlap ($Subclass_1 \cap Subclass_2 \ne \emptyset$).
     - Notation in EER: Circle containing the letter 'o'.
     - Example: `Person` specialized into `Employee` and `Alumnus` (a person can be both an employee and an alumnus).

CONSTRAINT 2: COMPLETENESS CONSTRAINT (TOTAL VS PARTIAL)
• Specifies whether EVERY entity instance in the superclass MUST belong to at least one subclass:
  A. Total Specialization (Mandatory Completeness):
     - Every entity instance in the superclass MUST be a member of at least one subclass.
     - Notation in EER: DOUBLE LINE connecting Superclass to the circle.
     - Example: `Account` specialized into `Savings_Account` and `Checking_Account` (there are no generic accounts; every account must be one or the other).
  B. Partial Specialization (Optional Completeness):
     - An entity instance can exist in the superclass WITHOUT belonging to any subclass.
     - Notation in EER: SINGLE LINE connecting Superclass to the circle.
     - Example: `Employee` specialized into `Engineer` and `Secretary` (other employees like Accountants or Drivers exist in the superclass alone).


2. THE FOUR COMBINATIONS OF SPECIALIZATION CONSTRAINTS
--------------------------------------------------------------------------------
COMBINATION             NOTATION       SEMANTIC MEANING
--------------------------------------------------------------------------------
1. Disjoint, Total      (d, Double)    Must belong to EXACTLY ONE subclass.
2. Disjoint, Partial    (d, Single)    Can belong to AT MOST ONE subclass (or none).
3. Overlapping, Total   (o, Double)    Must belong to AT LEAST ONE subclass (can be both).
4. Overlapping, Partial (o, Single)    Can belong to ZERO, ONE, or MULTIPLE subclasses.
--------------------------------------------------------------------------------


3. RELATIONAL SCHEMA MAPPING STRATEGIES FOR THE 4 COMBINATIONS
--------------------------------------------------------------------------------
A. DISJOINT SPECIALIZATION ('d'):
   • Can use Table-Per-Hierarchy (Single table with a single `type_code` ENUM discriminator column)
     OR Table-Per-Type (separate child tables with mutually exclusive application inserts).

B. OVERLAPPING SPECIALIZATION ('o'):
   • MUST use Table-Per-Type (dedicated table for each subclass) OR Table-Per-Hierarchy with multiple
     boolean flag columns (`is_student TINYINT(1)`, `is_instructor TINYINT(1)`).


4. REAL-WORLD CASE STUDIES (BARRACKPORE & KOLKATA)
--------------------------------------------------------------------------------
CASE 1: Mamata's Barrackpore Academy (Disjoint & Total: Staff vs Student)
CREATE TABLE persons (
    person_id INT AUTO_INCREMENT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    person_role ENUM('Student', 'Faculty') NOT NULL -- Disjoint 'd' + Total
) ENGINE=InnoDB;

CASE 2: Debangshu's Kolkata University (Overlapping & Partial: Alumnus & Staff)
CREATE TABLE university_persons (
    person_id INT AUTO_INCREMENT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    is_employee BOOLEAN NOT NULL DEFAULT FALSE, -- Overlapping 'o' flag 1
    is_alumnus BOOLEAN NOT NULL DEFAULT FALSE   -- Overlapping 'o' flag 2
) ENGINE=InnoDB;


5. COMMON PITFALLS & DANGER ZONES
--------------------------------------------------------------------------------
1. Using Single ENUM for Overlapping Specialization:
   - Defining `role ENUM('Student', 'Employee')` blocks a person from being both a student and an employee! Use separate tables or boolean flags.
2. Forgetting Double Line on Total Specialization:
   - Omitting double line implies partial completeness, allowing orphan superclass entities that business rules forbid.
