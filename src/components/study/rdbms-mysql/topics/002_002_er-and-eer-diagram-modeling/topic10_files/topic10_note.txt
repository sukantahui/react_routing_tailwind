1. WHAT IS TYPE INHERITANCE IN EER SCHEMAS?
--------------------------------------------------------------------------------
In Extended ER (EER) modeling, Type Inheritance is the fundamental mechanism where an entity
instance in a Subclass automatically inherits two essential categories of structural definition:

1. ATTRIBUTE INHERITANCE:
   - A subclass entity inherits ALL attributes of its direct Superclass, as well as attributes
     from all higher-level ancestor superclasses up the hierarchy tree.
   - Most importantly: The Subclass inherits the Primary Key Identifier of the Superclass.

2. RELATIONSHIP INHERITANCE:
   - A subclass entity automatically participates in ALL relationship types in which its superclass participates.
   - Example: If `Person` participates in `Has_Health_Insurance`, then both `Student` and `Instructor`
     subclasses automatically inherit the ability to participate in `Has_Health_Insurance`.


2. MULTI-LEVEL INHERITANCE TREES & ROOT-TO-LEAF PROPAGATION
--------------------------------------------------------------------------------
Specialization hierarchies can extend across multiple hierarchical tiers:
• Level 1 (Root Superclass): `Person(person_id [PK], full_name, email, dob)`
• Level 2 (Subclass of Person / Superclass of Manager): `Employee(person_id [PK, FK], salary, hire_date)`
• Level 3 (Leaf Subclass of Employee): `Engineering_Manager(person_id [PK, FK], team_budget, bonus_percentage)`

INHERITANCE CASCADE AT LEVEL 3:
• `Engineering_Manager` inherits:
  - From Level 1: `full_name`, `email`, `dob`.
  - From Level 2: `salary`, `hire_date`.
  - Local Attributes: `team_budget`, `bonus_percentage`.
  - Primary Key: `person_id` (propagated down all 3 levels).


3. RELATIONAL SCHEMA IMPLEMENTATION (MULTI-TIER JOINED TPT)
--------------------------------------------------------------------------------
In MySQL InnoDB, multi-level inheritance is mapped via multi-table joins on the shared Primary Key:

ROOT TABLE:
CREATE TABLE persons (
    person_id INT AUTO_INCREMENT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE
) ENGINE=InnoDB;

INTERMEDIATE TIER TABLE:
CREATE TABLE employees (
    person_id INT PRIMARY KEY,
    monthly_salary DECIMAL(10, 2) NOT NULL,
    CONSTRAINT fk_emp_person FOREIGN KEY (person_id)
        REFERENCES persons(person_id) ON DELETE CASCADE
) ENGINE=InnoDB;

LEAF TIER TABLE:
CREATE TABLE engineering_managers (
    person_id INT PRIMARY KEY,
    team_budget DECIMAL(12, 2) NOT NULL,
    CONSTRAINT fk_mgr_emp FOREIGN KEY (person_id)
        REFERENCES employees(person_id) ON DELETE CASCADE
) ENGINE=InnoDB;


4. QUERYING MULTI-LEVEL INHERITED ENTITIES IN SQL
--------------------------------------------------------------------------------
To assemble the complete polymorphic view of an Engineering Manager:
SELECT
    p.person_id,
    p.full_name,
    p.email,
    e.monthly_salary,
    m.team_budget
FROM persons p
JOIN employees e ON p.person_id = e.person_id
JOIN engineering_managers m ON e.person_id = m.person_id;


5. COMMON PITFALLS & DANGER ZONES
--------------------------------------------------------------------------------
1. Duplicating Superclass Attributes in Subclass Tables:
   - Creating `full_name` column again in `employees` or `engineering_managers` causes data redundancy and 2NF/3NF violations.
2. Breaking Key Chain Across Tiers:
   - Generating an artificial `manager_id INT AUTO_INCREMENT` in leaf tables breaks the 1:1 polymorphic join path with `persons`.
3. Forgetting Multi-Tier Cascades:
   - Omitting `ON DELETE CASCADE` on intermediate foreign keys leaves orphaned grandchild records.


6. BEST PRACTICES & SUMMARY CHECKLIST
--------------------------------------------------------------------------------
[x] Define common attributes only ONCE at the highest applicable superclass level.
[x] Use the Root Superclass Primary Key as the PK/FK down through all subclass tiers.
[x] Use multi-table `INNER JOIN` queries to retrieve full polymorphic entity profiles.
[x] Configure `ON DELETE CASCADE` across all foreign keys in the hierarchy chain.
[x] Maintain strict 3NF normalization by never duplicating inherited attributes in child tables.
