1. WHAT IS (MIN, MAX) CONSTRAINT NOTATION?
--------------------------------------------------------------------------------
The `(min, max)` notation is a formal, unambiguous method to specify both participation (modality)
and cardinality constraints simultaneously on each entity's participation in a relationship set.

CORE DEFINITION:
• On the line connecting an Entity Set $E$ to a Relationship Set $R$, we write a pair `(min, max)`:
  - `min`: The MINIMUM number of relationship instances each entity in $E$ MUST participate in.
    • `min = 0` ➔ Partial (Optional) Participation.
    • `min >= 1` (usually `min = 1`) ➔ Total (Mandatory) Participation.
  - `max`: The MAXIMUM number of relationship instances each entity in $E$ CAN participate in.
    • `max = 1` ➔ Maximum one association.
    • `max = N` (or `M`) ➔ Unbounded (Many) associations.


2. THE FOUR CLASSIC (MIN, MAX) PAIRS
--------------------------------------------------------------------------------
PAIR       SEMANTIC MEANING                 PARTICIPATION   CARDINALITY   CROW'S FOOT EQUIVALENT
--------------------------------------------------------------------------------
(0, 1)     Optional One (Zero or One)       Partial (0)     One (1)       o| (Circle + Bar)
(1, 1)     Mandatory Exactly One            Total (1)       One (1)       || (Double Bar)
(0, N)     Optional Many (Zero or More)     Partial (0)     Many (N)      >o (Circle + Crow)
(1, N)     Mandatory Many (One or More)     Total (1)       Many (N)      >| (Bar + Crow)
--------------------------------------------------------------------------------


3. CHEN LOOK-ACROSS VS (MIN, MAX) LOOK-HERE SEMANTIC PERSPECTIVE
--------------------------------------------------------------------------------
CRITICAL CONCEPTUAL DISTINCTION:
• Peter Chen Notation uses "Look-Across" semantics:
  - The '1' or 'N' written near Entity B describes how MANY instances of Entity B are associated
    with ONE instance of Entity A.
• (min, max) Notation uses "Look-Here" (Local) semantics:
  - The `(min, max)` written near Entity A describes the participation bounds of Entity A ITSELF.

EXAMPLE: Student (1, N) ───< Enrolls_In >─── (0, M) Course
• Meaning for Student: Every student MUST enroll in at least 1 course, and may enroll in up to N courses.
• Meaning for Course: A course can have 0 enrolled students (min = 0), and may have up to M students.


4. REAL-WORLD CASE STUDIES (BARRACKPORE & KOLKATA)
--------------------------------------------------------------------------------
CASE 1: Mamata's Barrackpore Student & Course Enrollment (min, max)
• `Student` (1, N): A registered student must take at least 1 course, up to N courses.
• `Course` (0, M): A new course can exist with 0 students, up to M students.
• Relational Mapping: Bridge table `student_enrollments(student_id, course_id)`.

CASE 2: Debangshu's Kolkata Company Department Manager (min, max)
• `Employee` (0, 1): An employee manages 0 departments (regular staff) or at most 1 department.
• `Department` (1, 1): Every department MUST have EXACTLY 1 manager.
• Relational Mapping: `departments.manager_emp_id INT NOT NULL UNIQUE`.


5. COMMON PITFALLS & DANGER ZONES
--------------------------------------------------------------------------------
1. Inverting Min and Max Bounds:
   - Writing `(1, 0)` is mathematically invalid; `0 <= min <= max` must always hold.
2. Mixing Look-Across and Look-Here Semantics:
   - Placing Chen 'N' on the opposite entity while writing `(min, max)` locally causes severe confusion.
3. Forgetting Zero Lower Bound on Optional Entities:
   - Forgetting `min = 0` implies mandatory participation, forcing artificial placeholder records.


6. BEST PRACTICES & SUMMARY CHECKLIST
--------------------------------------------------------------------------------
[x] Ensure `0 <= min <= max` and `max >= 1` for all `(min, max)` pairs.
[x] Use `(0, 1)` for optional single associations (e.g. spouse, department manager for employee).
[x] Use `(1, 1)` for mandatory single associations (e.g. department manager for department).
[x] Use `(0, N)` for optional multiple associations (e.g. course enrollments for a new course).
[x] Use `(1, N)` for mandatory multiple associations (e.g. line items on an invoice).
