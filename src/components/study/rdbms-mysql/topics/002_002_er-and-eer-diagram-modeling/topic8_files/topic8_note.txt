1. WHAT IS EXTENDED ENTITY-RELATIONSHIP (EER) MODELING?
--------------------------------------------------------------------------------
Standard Peter Chen ER modeling excels at capturing entities and basic relationships.
However, complex modern enterprise systems (banking, universities, healthcare) require
Object-Oriented data abstractions such as Inheritance, Subclasses, and Superclasses.
Extended ER (EER) incorporates these advanced modeling constructs into conceptual database design.

CORE EER CONCEPTS:
• Superclass (Base / Parent Entity Set):
  - An entity set that includes distinct subgroups of entity instances requiring specific attributes or relationships.
  - Example: `Person`, `Employee`, `Account`.
• Subclass (Derived / Child Entity Set):
  - A specialized subgrouping of entities from a superclass that share common superclass attributes
    but possess specific local attributes or relationships of their own.
  - Example: `Staff_Employee`, `Faculty_Employee`, `Student`.
• Superclass/Subclass Relationship (IS-A Relationship):
  - A 1:1 relationship between an instance of the superclass and an instance of the subclass.
  - Example: "A Secretary IS-A Employee", "A Savings Account IS-A Bank Account".


2. SPECIALIZATION VS GENERALIZATION
--------------------------------------------------------------------------------
A. SPECIALIZATION (TOP-DOWN DESIGN PROCESS):
   - Starting with a high-level Superclass entity and identifying specialized Subclasses
     based on distinguishing characteristics, attributes, or business roles.
   - Example: Starting with `Vehicle` and specializing into `Car`, `Truck`, `Motorcycle`.

B. GENERALIZATION (BOTTOM-UP DESIGN PROCESS):
   - Starting with multiple distinct entity sets that share common features, and synthesizing
     them into a single generalized Superclass to eliminate schema duplication.
   - Example: Synthesizing `Saving_Account` and `Current_Account` into a generalized `Bank_Account`.


3. TYPE INHERITANCE IN EER SCHEMAS
--------------------------------------------------------------------------------
A fundamental property of EER subclassing:
• An entity instance that is a member of a subclass INHERITS ALL:
  1) Attributes of its Superclass (including its Primary Key identifier).
  2) Relationships in which the Superclass participates.
• Plus, the subclass defines its own LOCAL specific attributes and relationships!


4. REAL-WORLD CASE STUDIES (BARRACKPORE & KOLKATA)
--------------------------------------------------------------------------------
CASE 1: Mamata's Barrackpore Academy Staff Specialization Hierarchy
• Superclass: `Person(person_id [PK], full_name, email, phone)`
• Subclasses:
  - `Student(person_id [PK, FK], admission_no, tuition_fee)`
  - `Instructor(person_id [PK, FK], designation, salary)`

RELATIONAL MAPPING (CLASSIC TABLE-PER-TYPE IN MYSQL):
CREATE TABLE persons (
    person_id INT AUTO_INCREMENT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE
) ENGINE=InnoDB;

CREATE TABLE students (
    person_id INT PRIMARY KEY,
    admission_no VARCHAR(20) NOT NULL UNIQUE,
    tuition_fee DECIMAL(10, 2) NOT NULL DEFAULT 15000.00,
    CONSTRAINT fk_student_person FOREIGN KEY (person_id)
        REFERENCES persons(person_id) ON DELETE CASCADE
) ENGINE=InnoDB;

CREATE TABLE instructors (
    person_id INT PRIMARY KEY,
    designation VARCHAR(50) NOT NULL,
    monthly_salary DECIMAL(10, 2) NOT NULL,
    CONSTRAINT fk_instructor_person FOREIGN KEY (person_id)
        REFERENCES persons(person_id) ON DELETE CASCADE
) ENGINE=InnoDB;


5. COMMON PITFALLS & DANGER ZONES
--------------------------------------------------------------------------------
1. Creating Unnecessary Subclasses:
   - Creating a subclass for an entity that has NO specific attributes and NO specific relationships (use a simple ENUM column instead).
2. Forgetting Primary Key Inheritance:
   - Subclass tables in Table-Per-Type mapping MUST share the exact same Primary Key as the Superclass table!
3. Omitting `ON DELETE CASCADE` on Subclass Foreign Keys:
   - Deleting a person should automatically delete their student or instructor record.


6. BEST PRACTICES & SUMMARY CHECKLIST
--------------------------------------------------------------------------------
[x] Use EER Specialization when subclasses have unique specific attributes or unique relationships.
[x] If subclasses have no unique attributes, represent them with a simple discriminator column in the superclass.
[x] Ensure Subclass entities inherit the Primary Key of their Superclass.
[x] Configure `ON DELETE CASCADE` on all subclass foreign keys referencing the superclass.
[x] Use Table-Per-Type (TPT) relational mapping for clean 3NF normalization.
