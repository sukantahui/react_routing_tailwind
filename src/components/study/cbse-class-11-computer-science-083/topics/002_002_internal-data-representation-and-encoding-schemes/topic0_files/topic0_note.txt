1. CHARACTER ENCODING SCHEMES
--------------------------------------------------------------------------------
Computers cannot store human alphabets directly; every character glyph is mapped
to a unique numeric code (code point) stored as binary bits.

A. ASCII (American Standard Code for Information Interchange):
   - Standard 7-bit Encoding: 2^7 = 128 unique character codes (0 to 127).
   - Printable Range: 32 (Space) to 126 (~).
   - Control Characters: 0 to 31 (e.g., 10 = Line Feed \n, 13 = Carriage Return \r, 9 = Tab \t).
   - Critical Memorization Anchors for CBSE Exams:
     * Digit '0' = ASCII 48 (binary 00110000) -> '9' = ASCII 57
     * Uppercase 'A' = ASCII 65 (binary 01000001) -> 'Z' = ASCII 90
     * Lowercase 'a' = ASCII 97 (binary 01100001) -> 'z' = ASCII 122
     * Space ' ' = ASCII 32
     * Case Conversion Rule: 'a' - 'A' = 32 (flipping the 6th bit, index 5).
   - Extended ASCII (8-bit): 2^8 = 256 characters (adds accented European letters).

B. ISCII (Indian Standard Code for Information Interchange):
   - 8-bit Character Encoding standardized by the Bureau of Indian Standards (BIS, 1991).
   - Retains standard ASCII in the lower half (0–127).
   - Uses the upper half (128–255) for Indian scripts (Devanagari, Bengali, Gurmukhi,
     Gujarati, Oriya, Tamil, Telugu, Kannada, Malayalam).
   - Unified character positions: The phonetic character 'Ka' has the exact same code
     point offset across all supported Indian scripts (Inscript Keyboard layout).

C. UNICODE (Universal Character Set):
   - Universal standard developed by Unicode Consortium to encode EVERY human writing
     system, mathematical symbol, ancient script, and modern emoji.
   - Notation: Represented as U+XXXX (where XXXX is a hexadecimal code point, e.g., U+0041 for 'A').
   - Transformation Formats (Encodings):
     1. UTF-8 (Variable-width, 1 to 4 bytes):
        * ASCII characters (0–127) take exactly 1 byte (100% backward-compatible).
        * Indic / Bengali / Arabic characters take 3 bytes.
        * Emojis take 4 bytes.
        * The default standard for modern web, Python 3, Linux, and databases.
     2. UTF-16 (Variable-width, 2 or 4 bytes):
        * Common characters take 2 bytes; supplementary symbols take 4 bytes.
        * Used internally by Java JVM and Windows API.
     3. UTF-32 (Fixed-width, 4 bytes / 32 bits):
        * Every single character occupies 4 bytes. Fast indexing but high memory consumption.

2. [ENRICHMENT / ADVANCED CONCEPT] SIGNED INTEGER REPRESENTATIONS
--------------------------------------------------------------------------------
In digital ALUs, negative numbers require specialized binary encoding schemes:

A. SIGN-MAGNITUDE:
   - MSB (Leftmost bit) = Sign Flag: 0 = Positive (+), 1 = Negative (-).
   - Remaining (n-1) bits = Absolute Magnitude in binary.
   - Example (8-bit): +25 = 00011001, -25 = 10011001.
   - Major Flaw: Two representations of zero (+0 = 00000000, -0 = 10000000) and
     requires separate, complex hardware for addition and subtraction.

B. 1's COMPLEMENT:
   - Positive numbers: Normal binary with MSB = 0.
   - Negative numbers: Invert every bit of the positive representation (0->1, 1->0).
   - Example (8-bit): +13 = 00001101 -> -13 = 11110010.
   - Flaw: Still suffers from two zeros (+0 = 00000000, -0 = 11111111).

C. 2's COMPLEMENT (UNIVERSAL INDUSTRY STANDARD):
   - 2's Complement = (1's Complement) + 1.
   - Fast Hardware Shortcut: Starting from the right (LSB), keep all trailing zeros
     and the very first '1' unchanged; invert all remaining bits to the left.
   - Example (8-bit):
     +13 = 00001101
     1's Complement = 11110010
     Add 1: 11110010 + 1 = 11110011 (This is -13 in 2's complement).
   - Key Advantages:
     1. Unique zero: 0 is uniquely represented as 00000000.
     2. Subtraction A - B is performed as A + (2's complement of B) using simple adders.
     3. Dynamic Range for n bits: -2^(n-1) to +2^(n-1) - 1 (e.g., 8-bit: -128 to +127).
