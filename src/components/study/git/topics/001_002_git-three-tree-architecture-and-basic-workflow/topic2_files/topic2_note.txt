1. TWO WAYS TO START A GIT REPOSITORY
--------------------------------------------------------------------------------
There are exactly two primary methods to initialize a local Git repository on
your computer:

A) Starting from Scratch: 'git init'
   - Used when starting a brand new project on your local machine, or turning an
     existing non-versioned folder into a Git repository.
   - Creates a hidden '.git' directory with skeleton files (HEAD, refs/, objects/, config).
   - Has 0 commits, 0 branches, and 0 remote tracking connections by default.

B) Cloning an Existing Project: 'git clone <url>'
   - Used when copying an existing repository from a remote hosting server
     (GitHub, GitLab, Bitbucket, corporate self-hosted Git server).
   - Downloads the 100% complete revision history, all commits, all branches,
     and all tags across the entire lifetime of the project.
   - Automatically sets up a remote named 'origin' pointing to the clone URL.
   - Checks out the default remote branch (usually 'main') into your working tree.


2. 'git init' SYNTAX & VARIATIONS
--------------------------------------------------------------------------------
1. Initialize in current working directory:
   $ git init

2. Initialize in a newly created named subfolder:
   $ git init my-awesome-project

3. Initialize with custom initial default branch name:
   $ git init --initial-branch=main   (or -b main)

4. Initialize a Bare Repository (server-side, without working tree):
   $ git init --bare


3. 'git clone' SYNTAX & ADVANCED OPTIONS
--------------------------------------------------------------------------------
1. Standard clone via HTTPS:
   $ git clone https://github.com/user/repo.git

2. Standard clone via SSH:
   $ git clone git@github.com:user/repo.git

3. Clone into a custom directory name:
   $ git clone https://github.com/user/repo.git custom-folder-name

4. Shallow Clone (fetch only latest N commits for faster CI/CD downloads):
   $ git clone --depth 1 https://github.com/user/repo.git

5. Single Branch Clone:
   $ git clone --single-branch --branch feature-ui https://github.com/user/repo.git


4. COMPARISON MATRIX: git init vs git clone
--------------------------------------------------------------------------------
+-----------------------+-------------------------+-------------------------+
| Feature               | git init                | git clone               |
+-----------------------+-------------------------+-------------------------+
| Starting State        | 0 commits, empty repo   | Full historical commits |
| Remote Link           | None (must add manual)  | 'origin' auto-configured|
| Initial Branch        | 'main' (or configured)  | Tracks remote default   |
| Network Requirement   | 100% Offline            | Requires network to URL |
| Use Case              | New original project    | Existing team codebase  |
+-----------------------+-------------------------+-------------------------+


5. TEACHER'S GOLDEN RULE
--------------------------------------------------------------------------------
"Never run 'git init' inside an existing Git repository or in your system's
User Home directory (~ or C:\Users\Username). Doing so creates nested repositories
that cause phantom submodule warnings and tracked file confusion!"
— Sukanta Hui, Coder & AccoTax
