1. MODULE 002_002 SUMMARY & KEY CONCEPTS:
   a) Fast-Forward (FF) Merges:
      - Occurs when target branch pointer is an ancestor of the incoming branch.
      - Simply advances pointer forward; creates 0 merge commits.
   b) Three-Way (3-Way) Merges:
      - Requires 3 commit snapshots: Common Ancestor (Merge Base), HEAD, and Incoming tip.
      - Calculated via `git merge-base branchA branchB`.
   c) Merge Commits:
      - Has 2 (or more) parent commit hashes recorded in its DAG header.
   d) Preserving Topologies (--no-ff):
      - Enforces creation of explicit merge commits to maintain feature boundaries in history.
   e) Merge Conflict Mechanics:
      - Triggered by concurrent changes to the same lines or modify/delete collisions.
      - Expressed via conflict markers (`<<<<<<< HEAD`, `=======`, `>>>>>>>`).
      - Enhanced via `merge.conflictStyle = zdiff3` to show ancestor base.
   f) The 5-Step Resolution Protocol:
      - Status -> Diff -> Edit & Test -> Stage (`git add`) -> Commit.
   g) Tooling & Rollback:
      - `git mergetool` for 3-way visual editing (VS Code, Meld, KDiff3).
      - `git merge --abort` for atomic zero-loss cancellation.
   h) Squash Merging:
      - `git merge --squash`: consolidates feature commits into 1 single-parent commit on target.
      - Feature branch must be deleted immediately after squash.
   i) Merge Engines:
      - Modern `ort` engine (Git 2.33+) vs legacy `recursive`.
      - Strategy options: `-X ours`, `-X theirs`, `-X ignore-all-space`.
