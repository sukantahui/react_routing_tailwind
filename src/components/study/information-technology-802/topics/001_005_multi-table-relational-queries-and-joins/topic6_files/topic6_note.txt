1. CORE CONCEPT & OVERVIEW
--------------------------------------------------------------------------------
Multi-table queries with ORDER BY: sorting joined result sets ascending/descending by primary and secondary keys.

In relational database systems (RDBMS), data is normalized into multiple specialized
tables (e.g., STUDENT, PARENTS, COACH, ACTIVITY) to eliminate redundancy, avoid 
anomalies, and maintain referential integrity. When information from multiple tables 
is needed simultaneously, Multi-Table Relational Queries and Table Joins are used.

2. CARTESIAN PRODUCT VS EQUI-JOIN
--------------------------------------------------------------------------------
- Cartesian Product (Cross Join):
  * Unfiltered combination of every row in Table 1 with every row in Table 2.
  * Cardinality (Row Count) = Cardinality(T1) * Cardinality(T2).
  * Degree (Column Count)   = Degree(T1) + Degree(T2).
  * Syntax: SELECT * FROM Table1, Table2;

- Equi-Join:
  * Filtered Cartesian product where a Primary Key in the parent table matches 
    a Foreign Key in the child table.
  * Eliminates mathematically invalid row pairings.
  * Implicit Syntax:
      SELECT S.Name, P.FatherName 
      FROM Student S, Parents P 
      WHERE S.ParentID = P.ParentID;
  * Explicit ANSI Syntax:
      SELECT S.Name, P.FatherName 
      FROM Student S 
      INNER JOIN Parents P ON S.ParentID = P.ParentID;

4. BOARD EXAMINATION PITFALLS & GOLDEN RULES
--------------------------------------------------------------------------------
[Rule 1] Table Aliasing:
Always qualify column names with table aliases (e.g. S.ParentID vs P.ParentID) to 
prevent 'ERROR 1052: Column in field list is ambiguous'.

[Rule 2] N-Table Joins:
To join N tables together without Cartesian explosion, you need at least (N - 1) 
join equality conditions in your WHERE or ON clause.

[Rule 3] WHERE Filtering with Joins:
Additional filter criteria (e.g. BirthYear < 2019, Class <> 'II') must be combined 
with the join predicate using the logical AND operator.

[Rule 4] ORDER BY Sorting:
ORDER BY executes as the final step. Multi-table queries can sort by attributes 
from either table (e.g. ORDER BY S.RollNo DESC, P.FatherName ASC).
