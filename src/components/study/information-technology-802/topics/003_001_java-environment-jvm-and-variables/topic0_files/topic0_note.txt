1. WHAT IS JAVA BYTECODE?
--------------------------------------------------------------------------------
- When a Java programmer writes source code in a file with `.java` extension, it cannot be directly executed by the underlying operating system or hardware CPU.
- The Java Compiler (`javac.exe`) translates human-readable Java source code into an intermediate, highly optimized, platform-independent machine language called "Bytecode".
- Bytecode is stored in binary files with the `.class` extension (e.g., `StudentDemo.java` compiles to `StudentDemo.class`).
- Bytecode is NOT machine code for Windows, Linux, or macOS. It is machine language for an abstract virtual computer called the "Java Virtual Machine" (JVM).

2. THE PURPOSE AND ROLE OF THE JVM
--------------------------------------------------------------------------------
- JVM stands for "Java Virtual Machine".
- It is an abstract computing machine that provides a runtime execution environment in which Java bytecode can be executed.
- The JVM is platform-DEPENDENT (there is a separate JVM specifically created for Windows, Linux, macOS, Solaris, Android, etc.), but it executes the same platform-INDEPENDENT bytecode.

3. CORE SUBSYSTEMS OF THE JVM:
--------------------------------------------------------------------------------
a) ClassLoader Subsystem:
   - Responsible for loading, linking, and initializing `.class` files into the JVM memory.
   - Verifies bytecode security (Bytecode Verifier checks for illegal memory access, stack overflow, type safety).

b) JVM Memory Areas (Runtime Data Area):
   - Method Area: Stores class-level structures, constant pool, method code.
   - Heap Area: Stores all created objects and instance variables (managed by Garbage Collector).
   - Java Stack Area: Stores stack frames containing local variables, intermediate calculations, and method call states.
   - Program Counter (PC) Register: Holds the memory address of the current JVM instruction being executed.
   - Native Method Stack: Handles native C/C++ library invocations.

c) Execution Engine:
   - Interpreter: Reads bytecode stream line-by-line, converts it into native CPU instructions, and executes them immediately.
   - Just-In-Time (JIT) Compiler: Identifies frequently executed bytecode ("hot spots"), compiles them directly into native machine code, and caches them in memory to dramatically boost performance.
   - Garbage Collector (GC): Automatically scans heap memory and reclaims unreferenced/orphan objects to prevent memory leaks.

4. STEP-BY-STEP JAVA EXECUTION WORKFLOW:
--------------------------------------------------------------------------------
1. Source Code Creation: Developer writes `Application.java`.
2. Compilation: `javac Application.java` -> creates platform-independent `Application.class` (Bytecode).
3. Class Loading: `java Application` launches the JVM. ClassLoader loads `Application.class`.
4. Bytecode Verification: Bytecode Verifier ensures the code conforms to JVM specifications and does not violate host security.
5. Execution: Execution Engine (Interpreter + JIT Compiler) translates bytecode into host CPU binary instructions (x86, ARM, x64).
6. Hardware Execution: Host operating system and processor run the instructions.

5. WHY JVM IS CRITICAL FOR CBSE IT-802 EXAMINATIONS:
--------------------------------------------------------------------------------
- Key Concept 1: Java is both a compiled AND interpreted language. (Compiled to Bytecode by `javac`, interpreted/JIT-compiled to machine code by `JVM`).
- Key Concept 2: Bytecode makes Java portable; JVM makes Bytecode executable.
- Key Concept 3: Source code (`.java`) is platform-independent. Bytecode (`.class`) is platform-independent. The JVM itself is platform-DEPENDENT.
