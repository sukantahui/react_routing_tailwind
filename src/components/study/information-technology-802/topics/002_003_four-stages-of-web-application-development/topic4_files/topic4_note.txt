1. WHAT IS THE TESTING & QUALITY ASSURANCE PHASE?
--------------------------------------------------------------------------------
Testing & Quality Assurance (Stage 4) is the verification and validation phase of the Web Application Development Lifecycle. In this phase, QA engineers execute the software with simulated and real data to uncover bugs, logic errors, security holes, and usability bottlenecks before deploying to live end-users.

Goal: Ensure the application is defect-free, reliable, secure, and complies 100% with the requirements documented in the Software Requirements Specification (SRS).

2. HIERARCHY OF TESTING LEVELS
--------------------------------------------------------------------------------
1. Unit Testing:
   - Scope: Individual functions, subroutines, methods, or classes tested in isolation.
   - Example: Testing a Java method `calculateElectricityBill(240)` with standard, zero, and boundary inputs.
   - Carried out by: Developers using frameworks like JUnit.

2. Integration Testing:
   - Scope: Verifies data flow and interface communication between combined modules.
   - Example: Verifying that the front-end billing form transmits JSON parameters to the middle-tier Java Servlet, which successfully persists the record to the MySQL database.

3. System Testing:
   - Scope: Comprehensive end-to-end testing of the entire integrated system against all functional and non-functional requirements.
   - Example: Simulating the complete user journey: Login -> Meter Lookup -> Bill Generation -> UPI Payment -> Invoice Download.

4. User Acceptance Testing (UAT):
   - Alpha Testing: Internal testing conducted in a simulated environment by internal QA and developers.
   - Beta Testing: Pre-release testing conducted by actual prospective clients/end-users in real-world environments.
   - Goal: Formal business sign-off before production release.

3. SPECIALIZED NON-FUNCTIONAL TESTING TYPES
--------------------------------------------------------------------------------
- Regression Testing: Re-executing previous test cases after fixing a bug or refactoring code to ensure existing features remain unaffected.
- Boundary Value Analysis (BVA): Testing extreme values at the edges of valid input partitions (e.g., test 0, 1, 9999, 10000 for a 1-10000 units range).
- Performance & Load Testing: Simulating thousands of concurrent user requests (using tools like Apache JMeter) to test server response times and peak traffic stability.
- Security & Penetration Testing: Auditing for vulnerabilities like SQL Injection, Cross-Site Scripting (XSS), insecure cookies, and session hijacking.
- Cross-Browser & Cross-Device Compatibility: Testing identical rendering across Google Chrome, Firefox, Safari, Edge, Android, and iOS.

4. THE BUG / DEFECT LIFECYCLE
--------------------------------------------------------------------------------
When a test fails, a defect is logged and managed through standard lifecycle stages:
  [NEW] -> [ASSIGNED to Developer] -> [OPEN / IN PROGRESS] -> [FIXED] -> [RETEST / VERIFIED by QA] -> [CLOSED]
  (If the bug persists upon retesting, it transitions from [RETEST] back to [REOPENED]).

Bug Severity Levels:
- Blocker / Critical: System crashes or core functionality (e.g. login/payment) completely unavailable.
- Major: Significant feature defect with no simple workaround.
- Minor: Functional defect with a feasible workaround.
- Trivial / Cosmetic: Misaligned text, typo, or color inconsistency.

5. DELIVERABLES OF STAGE 4 (TESTING PHASE)
--------------------------------------------------------------------------------
1. Comprehensive Test Plan Document
2. Detailed Test Cases (Test ID, Pre-conditions, Input Data, Expected Output, Actual Output, Pass/Fail Status)
3. Bug Tracking & Defect Summary Reports (JIRA / Bugzilla logs)
4. Cross-Browser & Security Audit Reports
5. Final User Acceptance Testing (UAT) Sign-off Certificate

6. KEY CBSE BOARD EXAM TAKEAWAYS
--------------------------------------------------------------------------------
- "Which phase is responsible for uncovering software defects and verifying SRS compliance?" -> Stage 4: Testing & Quality Assurance.
- "What is the difference between Unit Testing and Integration Testing?" -> Unit testing checks individual isolated methods, whereas integration testing checks the data exchange between combined modules.
- "What is Regression Testing?" -> Re-testing after code modifications to ensure no existing functionality is broken.
- "What is Beta Testing?" -> Pre-release testing conducted by real end-users in actual operating environments.
