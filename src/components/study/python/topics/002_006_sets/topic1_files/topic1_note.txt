1. TOPIC OVERVIEW & CREATION STRATEGIES
--------------------------------------------------------------------------------
Python provides two primary mechanisms for creating set objects:
  1. Set Literal Syntax: Using curly braces `{e1, e2, ...}`
  2. Set Constructor Syntax: Using the built-in function `set(iterable)`

Both create a mutable, unordered collection of unique elements, but each has
distinct syntactic behaviors, performance nuances, and use-case scenarios.

--------------------------------------------------------------------------------
2. SET LITERAL SYNTAX: {elem1, elem2, ...}
--------------------------------------------------------------------------------
  • Syntax: `my_set = {10, 20, 30, "Kolkata"}`
  • Performance: Faster than set() when populating known static constants because
    the Python compiler directly emits the `BUILD_SET` bytecode instruction.
  • Requirement: Cannot be empty! `{}` creates an empty dictionary, not a set.
  • Elements must be hashable/immutable.

--------------------------------------------------------------------------------
3. SET CONSTRUCTOR SYNTAX: set(iterable)
--------------------------------------------------------------------------------
  • Syntax: `my_set = set(iterable_object)`
  • Converts any valid Python iterable into a deduplicated set.
  • Examples:
      - Empty Set: `empty = set()` -> `<class 'set'>`
      - From String: `set("banana")` -> `{'b', 'a', 'n'}`
      - From List: `set([1, 2, 2, 3])` -> `{1, 2, 3}`
      - From Dict Keys: `set({"a": 1, "b": 2})` -> `{'a', 'b'}`
      - From Dict Values: `set(d.values())` -> `{1, 2}`
      - From Range: `set(range(5))` -> `{0, 1, 2, 3, 4}`
      - From Generator: `set(x*x for x in range(5))` -> `{0, 1, 4, 9, 16}`

--------------------------------------------------------------------------------
4. BYTECODE & PERFORMANCE ANALYSIS
--------------------------------------------------------------------------------
When using a set literal:
  `{1, 2, 3}` compiles to:
    LOAD_CONST (1)
    LOAD_CONST (2)
    LOAD_CONST (3)
    BUILD_SET 3

When using set():
  `set([1, 2, 3])` compiles to:
    LOAD_GLOBAL (set)
    LOAD_CONST (1, 2, 3)
    BUILD_LIST 3
    CALL_FUNCTION 1

Result: Set literals `{}` execute roughly 2x-3x faster for fixed constants!

--------------------------------------------------------------------------------
5. COMMON PITFALLS & GOTCHAS
--------------------------------------------------------------------------------
  [x] Gotcha 1: `s = {}` creates a DICTIONARY, not a set.
  [x] Gotcha 2: `{[1, 2]}` tries to put a list in a set literal -> TypeError.
  [x] Gotcha 3: `set(100)` raises TypeError: 'int' object is not iterable.
      (You must pass an iterable like `set([100])` or `{100}`).

--------------------------------------------------------------------------------
6. SUMMARY BLUEPRINT & MASTER ADVICE
--------------------------------------------------------------------------------
  • Use `{...}` when writing hardcoded literal constants in source code.
  • Use `set()` when creating an empty set or transforming dynamic iterables.
  • Never pass unhashable containers (lists, dicts) as direct set members.
