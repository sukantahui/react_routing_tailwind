1. CORE CONCEPT: WHY SETS ARE UNORDERED & UNINDEXED
--------------------------------------------------------------------------------
In Python, sets are explicitly designed as UNORDERED collections:
  • Elements have NO defined positional index (no index 0, 1, 2, ...).
  • Elements do NOT retain insertion sequence.
  • Slicing (`s[start:stop]`) and subscripting (`s[index]`) are disallowed and
    raise `TypeError: 'set' object is not subscriptable`.

Why is this by design?
  Because sets prioritize ultra-fast O(1) hash lookups over sequential memory
  layout. Elements are scattered across sparse hash buckets based solely on
  their computed `hash(x)` address.

--------------------------------------------------------------------------------
2. PYTHON HASH SEED RANDOMIZATION (SECURITY ARCHITECTURE)
--------------------------------------------------------------------------------
  • Since Python 3.3, string and byte hashes are randomized across interpreter
    processes using an internal seed (`PYTHONHASHSEED`).
  • This prevents Algorithmic Complexity Denial of Service (DoS) attacks on web
    servers.
  • Consequence: The iteration order of strings in a set can change completely
    between different Python script runs!

--------------------------------------------------------------------------------
3. WORKAROUNDS: ACCESSING ELEMENTS WITHOUT INDICES
--------------------------------------------------------------------------------
  A. If you need a sorted list from a set:
     `sorted_list = sorted(my_set)`  # Returns a new, sequentially indexed list

  B. If you need any arbitrary single element:
     `one_item = next(iter(my_set))` # Retrieves the first element yielded

  C. If you need Deduplication + Order Preservation:
     `ordered_unique = list(dict.fromkeys(raw_list))` # O(N) Order-Preserved Set

--------------------------------------------------------------------------------
4. LISTS VS SETS MEMORY LAYOUT
--------------------------------------------------------------------------------
  • List: Contiguous, indexed memory array (`[item0, item1, item2, ...]`).
          Supports `list[0]`, slicing `list[1:3]`, maintains strict order.
  • Set:  Sparse hash table with open-addressing buckets.
          No indices, non-contiguous, O(1) instant jump via hash code.

--------------------------------------------------------------------------------
5. COMMON PITFALLS & GOTCHAS
--------------------------------------------------------------------------------
  [x] Writing `s[0]` or `s[-1]` expecting first/last item -> TypeError.
  [x] Relying on print(s) order in automated unit tests (tests will randomly fail).
  [x] Mistaking small integer hash patterns (1, 2, 3) for guaranteed sorting.
