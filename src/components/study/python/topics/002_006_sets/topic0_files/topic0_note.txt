1. EXECUTIVE SUMMARY & CORE DEFINITION
--------------------------------------------------------------------------------
A Set in Python is an unordered, unindexed, and mutable collection of unique,
immutable (hashable) elements. Sets directly model the mathematical concept of
a finite set and are implemented internally using hash tables (hash sets).

Key Characteristics:
  • Uniqueness: Duplicates are strictly disallowed and automatically pruned.
  • Unordered: Elements do not have a defined index, position, or insertion order.
  • Hashable Elements Only: Every element inside a set must be immutable (integers,
    floats, strings, tuples, frozensets, booleans). Mutable types (lists, dicts,
    sets) cannot be elements of a set.
  • High Performance: Membership testing ('in' / 'not in') executes in O(1) 
    average time complexity, compared to O(N) linear scans in lists and tuples.

--------------------------------------------------------------------------------
2. SYNTAX & CREATION MECHANISMS
--------------------------------------------------------------------------------
  A. Set Literal Syntax:
     student_ids = {101, 102, 103, 104}

  B. Set Constructor:
     unique_chars = set("Barrackpore")     # {'B', 'a', 'r', 'c', 'k', 'p', 'o', 'e'}
     unique_nums  = set([10, 20, 10, 30])  # {10, 20, 30}

  C. CRITICAL GOTCHA: Empty Set Creation:
     empty_dict = {}     # TYPE: <class 'dict'>  <-- DANGER: Creates empty dictionary!
     empty_set  = set()  # TYPE: <class 'set'>   <-- CORRECT: Creates empty set

--------------------------------------------------------------------------------
3. INTERNAL ARCHITECTURE (HOW SETS WORK UNDER THE HOOD)
--------------------------------------------------------------------------------
Python sets are implemented as open-addressing hash tables:
  1. When an element is added, Python computes its hash value: hash(element).
  2. The hash value determines the array bucket index where the element is stored.
  3. If a duplicate element is added, its hash matches an existing bucket and the
     equality check (a == b) confirms duplication; the new entry is discarded.
  4. Lookup time is O(1) because Python calculates the hash and jumps directly
     to the bucket without scanning the entire sequence.

--------------------------------------------------------------------------------
5. COMMON PITFALLS & MISTAKES TO AVOID
--------------------------------------------------------------------------------
  [x] Mistake 1: Attempting index access: my_set[0] -> TypeError: 'set' object is not subscriptable.
  [x] Mistake 2: Creating empty set with {} instead of set().
  [x] Mistake 3: Putting a list inside a set: {[1, 2], [3, 4]} -> TypeError: unhashable type: 'list'.
  [x] Mistake 4: Relying on element printing order; set order is non-deterministic and can vary.

--------------------------------------------------------------------------------
6. TEACHER'S MASTER CHECKLIST
--------------------------------------------------------------------------------
  [v] Use sets when uniqueness and ultra-fast O(1) membership lookup matter.
  [v] Use lists when sequential order, index access, and duplicate elements matter.
  [v] Use dictionaries when key-value associative mappings are required.
  [v] Always use set() to instantiate an empty set.
