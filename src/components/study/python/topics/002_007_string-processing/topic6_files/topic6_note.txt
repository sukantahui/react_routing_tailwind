1. delimiter.join(iterable) SYNTAX & DESIGN RATIONALE
--------------------------------------------------------------------------------
  Syntax:
      "separator".join(iterable_of_strings)

  Why separator.join(list) and NOT list.join(separator)?
  • Polymorphism: join() works with ANY iterable (tuples, sets, dictionaries,
    generators, open file objects), not just lists.
  • Type Safety: The method belongs to str, guaranteeing that the separator
    is always a valid string object.
  • Consistency: Avoids duplicating the same join() logic across list, tuple,
    set, and dict classes.

--------------------------------------------------------------------------------
2. DELIMITER PLACEMENT INVARIANTS
--------------------------------------------------------------------------------
  • Delimiters are placed strictly BETWEEN items.
  • No leading or trailing delimiters are ever generated!
      Example:
        ", ".join([])          -> ""             (Empty string)
        ", ".join(["Single"])  -> "Single"       (Zero comma)
        ", ".join(["A", "B"])  -> "A, B"         (Single comma between)

--------------------------------------------------------------------------------
3. DEFENSIVE TYPE CASTING PATTERNS
--------------------------------------------------------------------------------
  Rule: ALL items in the iterable MUST be strings, or Python raises TypeError!
    TypeError: sequence item 0: expected str instance, int found

  Solution Patterns:
  1. Generator Expression:
       ", ".join(str(x) for x in data)
  2. Functional map() in C:
       ", ".join(map(str, data))
  3. Formatted List Comprehension:
       ", ".join(f"INR {x:,.2f}" for x in amounts)

--------------------------------------------------------------------------------
4. DICTIONARY JOINING PATTERNS
--------------------------------------------------------------------------------
  Given d = {"name": "Susmita", "city": "Barrackpore"}:
  • ", ".join(d)                       -> "name, city" (Keys by default)
  • ", ".join(d.values())              -> "Susmita, Barrackpore" (Values)
  • "&".join(f"{k}={v}" for k,v in d.items()) -> "name=Susmita&city=Barrackpore"

--------------------------------------------------------------------------------
5. CPYTHON MEMORY ARCHITECTURE: O(N) VS O(N^2)
--------------------------------------------------------------------------------
  Why is join() 40x-100x faster than += in loops?

  A. Two-Pass join() [O(N) Complexity]:
     • Pass 1: Sums total byte length of all strings + (N-1) * len(separator).
     • Heap Allocation: Allocates EXACTLY ONE contiguous memory buffer.
     • Pass 2: Copies each string and delimiter directly via native C memcpy().

  B. '+=' Loop Concatenation [O(N^2) Complexity]:
     • On each step, Python must allocate a new string, copy all previous
       characters, copy the new word, and discard the old object.
     • For 20,000 strings, this causes catastrophic quadratic slowdown.

--------------------------------------------------------------------------------
6. COMMON MISTAKES TO AVOID
--------------------------------------------------------------------------------
  ❌ Mistake: Calling list.join(", ") -> Raises AttributeError!
              Fix: Call ", ".join(list).
  ❌ Mistake: Joining numbers directly without str() -> Raises TypeError!
              Fix: ", ".join(map(str, numbers)).
  ❌ Mistake: Using a '+' concatenation loop to build long strings or CSVs.
              Fix: Collect rows into a list and call "\n".join(rows).
