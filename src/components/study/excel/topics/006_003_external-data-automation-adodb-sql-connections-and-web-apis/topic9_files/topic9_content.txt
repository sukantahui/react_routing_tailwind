================================================================================

1. EXECUTIVE OVERVIEW
Managing database transactions in VBA (`BeginTrans`, `CommitTrans`, `RollbackTrans`) is an essential discipline in enterprise database engineering, cloud systems integration, and full-stack financial automation.
It provides the core protocols required to connect Excel directly to enterprise relational databases, query closed workbooks via SQL, and consume cloud REST APIs.

2. SYNTAX & TOKEN STRUCTURE
Operational Architecture: Database Transactions: conn.BeginTrans | On Error GoTo TransError | conn.Execute sql1 | conn.Execute sql2 | conn.CommitTrans | TransError: conn.RollbackTrans

3. CORE TECHNICAL MECHANICS
1. The ACID Principle in Spreadsheets:
   Atomicity (All operations succeed or none do); Consistency (Database remains in a valid state); Isolation (Concurrent operations don't interfere); Durability (Committed data survives crashes).

2. The `conn.BeginTrans` Lock:
   Marks the beginning of an atomic transaction. All subsequent INSERT/UPDATE statements are held in temporary staging by the database engine.

3. The `conn.RollbackTrans` Safeguard:
   If any error occurs during a 10-step billing update, `RollbackTrans` completely undoes all previous steps, leaving the database 100% pristine and uncorrupted.

5. TROUBLESHOOTING & COMMON ERRORS
• Omitting RollbackTrans on Error (Database Lockup):
  Root Cause: Error occurs inside a transaction without calling `RollbackTrans`, leaving table rows locked on the database server.
  Diagnostic Fix: Always place `conn.RollbackTrans` inside the structured error handler block.
• Long-Running Transactions Holding Locks:
  Root Cause: Pausing a transaction with a `MsgBox` while holding active database table locks blocks other corporate users.
  Diagnostic Fix: Perform all user confirmations BEFORE calling `conn.BeginTrans`; execute SQL in milliseconds and commit immediately.
• Calling CommitTrans When BeginTrans Failed:
  Root Cause: Calling `CommitTrans` on an uninitialized transaction throws runtime error.
  Diagnostic Fix: Track transaction state with a Boolean flag (`inTransaction = True`).

6. PRO TIPS & SHORTCUTS
• Transaction Pattern (conn.BeginTrans → SQLs → conn.CommitTrans (ErrorHandler: conn.RollbackTrans)): The universal ACID transaction template.
• No UI Inside Transactions (Never put MsgBox inside BeginTrans...CommitTrans): Keeps transaction duration under 50 milliseconds to prevent lock contention.
• Atomicity Guarantee (All succeed or all fail together): Eliminates half-completed corrupted database records.
