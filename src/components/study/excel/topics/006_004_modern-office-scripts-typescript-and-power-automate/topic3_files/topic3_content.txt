3. CORE TECHNICAL MECHANICS
1. Strict Type Safety in Spreadsheets:
   Types (`number`, `string`, `boolean`, `Date`, `object`) prevent accidental type errors before code ever runs on corporate financial sheets.

2. The 2D Array Grid Representation (`(string|number)[][]`):
   Excel cell ranges are represented as 2D arrays in TypeScript: an array of rows, where each row is an array of cell values (`[["ID", "Amount"], [101, 5000]]`).

5. TROUBLESHOOTING & COMMON ERRORS
• Confusing 1D Arrays with 2D Range Arrays:
  Root Cause: Passing a 1D array `[1, 2, 3]` to `range.setValues()` throws runtime error 'Values must be a 2D array'.
  Diagnostic Fix: Always wrap values in 2D array format: `[[1, 2, 3]]` (single row) or `[[1], [2], [3]]` (single column).
• Using 'any' Everywhere (Losing Type Safety):
  Root Cause: Typing all variables as `any` defeats TypeScript's error-prevention benefits.
  Diagnostic Fix: Declare strict types: `let revenue: number`, `let customer: string`.
• Using 'var' Instead of 'const' / 'let':
  Root Cause: Using legacy `var` introduces variable hoisting bugs.
  Diagnostic Fix: Always use `const` for immutable variables and `let` for reassignable variables.

6. PRO TIPS & SHORTCUTS
• 2D Array Syntax (const data: (string|number)[][] = [["A", 10], ["B", 20]];): The standard format for all Excel range reads and writes.
• Use const by Default (const ws = workbook.getActiveWorksheet();): Best practice in modern TypeScript development.
• Array.filter() (const filtered = rows.filter(r => r[1] > 100);): Fast, readable array filtering.
