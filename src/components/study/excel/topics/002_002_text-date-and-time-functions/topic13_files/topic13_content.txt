5. TROUBLESHOOTING & COMMON ERRORS
• Hardcoding Variable Values:
  Root Cause: Hardcoding dates, rates, or character counts directly into formulas breaks model scalability.
  Diagnostic Fix: Always reference structured lookup cells, parameter blocks, or dynamic locator functions.
• Ignoring Regional Date Standards:
  Root Cause: Building formulas that assume US date formats without handling international client settings.
  Diagnostic Fix: Use DATE(yyyy, mm, dd) and unambiguous dd-mmm-yyyy visual formats.
• Failing to Handle Boundary Values:
  Root Cause: Testing formulas only with happy-path data while failing on blank, zero, or error inputs.
  Diagnostic Fix: Test formulas thoroughly against empty strings, leap days, and midnight crossovers.

6. PRO TIPS & SHORTCUTS
• Defensive Formula Design (Wrap with IFERROR()): Protect client dashboards against ugly #VALUE! and #N/A errors.
• Audit Intermediate Steps (Evaluate Formula (Alt + M + V)): Step through complex nested formulas to pinpoint calculation bugs.
• Named Ranges for Tables (Ctrl + F3): Use descriptive named ranges like HolidaysRange for readable formulas.
