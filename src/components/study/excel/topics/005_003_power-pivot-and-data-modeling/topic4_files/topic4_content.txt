1. EXECUTIVE OVERVIEW
Cross-filter direction: Single vs Both directions and avoiding ambiguous relationship paths is an essential discipline in enterprise data architecture, business intelligence, and large-scale analytical modeling.
It provides the core protocols required to shatter Excel's 1-million row limit, establish clean relational schemas, and build high-performance data models.

2. SYNTAX & TOKEN STRUCTURE
Operational Architecture: Cross-Filter Direction: Single Direction (Dim -> Fact) | Both Directions (Bi-Directional Filtering) | Manage Relationships

3. CORE TECHNICAL MECHANICS
1. Natural Single-Direction Flow (Dim -> Fact):
   By default, filters placed on a Dimension table flow DOWN to the Fact table. Filters placed on a Fact table do NOT flow back up to dimensions.

2. The Danger of Bi-Directional Filtering ('Both'):
   Enabling Bi-directional filtering allows filters to travel in both directions, but introduces ambiguous cyclic calculation loops and severe performance degradation.

3. Dynamic DAX Directional Control:
   Instead of permanent model-level Bi-directional relationships, use targeted DAX functions (`CROSSFILTER()`) inside explicit measures.

5. TROUBLESHOOTING & COMMON ERRORS
• Defaulting to Bi-Directional Filtering Everywhere:
  Root Cause: Setting all relationships to 'Both' cross-filter direction creates unpredictable results and massive CPU slowdowns.
  Diagnostic Fix: Keep relationships as Single direction; use DAX `CROSSFILTER(..., BOTH)` only when explicitly needed.
• Ambiguous Relationship Paths Error:
  Root Cause: Creating multiple active relationship paths between the same two tables causes Power Pivot to disable one path.
  Diagnostic Fix: Use Inactive relationships and activate them dynamically in DAX with `USERELATIONSHIP()`.
• Expecting Fact Filters to Filter Dimension Slicers:
  Root Cause: Wondering why filtering Fact_Sales doesn't reduce items in a Dim_Product slicer under Single Direction.
  Diagnostic Fix: Use measure-based visual filtering or explicit DAX filtering expressions.

6. PRO TIPS & SHORTCUTS
• Single Direction Default (Always use Single Direction by default): Guarantees clean, predictable, high-speed filter propagation.
• CROSSFILTER Function (=CALCULATE([Measure], CROSSFILTER(Dim[Key], Fact[Key], BOTH))): Enables bi-directional filtering temporarily for a single calculation.
• Inspect Filter Arrows (Look at arrow direction in Diagram View): Shows exactly how filter selections flow across tables.
