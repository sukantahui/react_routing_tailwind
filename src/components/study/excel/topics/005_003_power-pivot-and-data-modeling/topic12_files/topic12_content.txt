3. CORE TECHNICAL MECHANICS
1. Column Cardinality (The #1 Memory Driver):
   Cardinality (number of unique values in a column) dictates dictionary size and run-length compression efficiency. Low cardinality = Tiny RAM; High cardinality = Huge RAM.

2. Memory Breakdown Architecture:
   Total Data Model Memory = Data Hierarchy Columns + Column Dictionaries + Relationship Indexes + User Hierarchies.

3. Eliminating Timestamp Precision Bloat:
   Splitting a DateTime column (`12/04/2026 14:32:15.892`) into separate Date and Hour columns can reduce column RAM footprint by 95%.

5. TROUBLESHOOTING & COMMON ERRORS
• Leaving High-Precision Floats Unrounded:
  Root Cause: Storing numbers with 10 decimal places (`₹45.129847192`) creates millions of unique values, destroying VertiPaq dictionary compression.
  Diagnostic Fix: Round decimal currencies to 2 decimal places in Power Query.
• Keeping Auto Date/Time Hidden Tables Enabled:
  Root Cause: Excel creating hidden date hierarchy tables for every single date column in the model, wasting megabytes of RAM.
  Diagnostic Fix: Disable Auto Date/Time in Power Pivot options; use a dedicated Date Dimension table.
• Unused Technical Columns Left in Fact Table:
  Root Cause: Leaving 30 database audit columns (`CreatedBy`, `ModifiedDate`, `RowID`) in a 5-million row model.
  Diagnostic Fix: Remove all columns not strictly required for reporting in Power Query before loading.

6. PRO TIPS & SHORTCUTS
• Cardinality Rule (Low Unique Count = Maximum Speed): The foundational principle of tabular data modeling.
• Split Date & Time (Transform > Date & Time into 2 columns): Slashes timestamp memory footprint by up to 95%.
• Remove Unused Columns (Power Query > Choose Columns): The fastest way to optimize any Power Pivot workbook.
