1. EXECUTIVE OVERVIEW & PHASE 4 OBJECTIVES
--------------------------------------------------------------------------------
Initial system exploits (Phase 3) are temporary: if the victim workstation reboots, the user 
logs off, or the vulnerable service restarts, the attacker's interactive shell session dies.

Phase 4 (Maintaining Access) is the discipline of establishing durable, long-term persistence 
and stealthy Command and Control (C2) communication channels that survive system restarts, 
firewall changes, and defensive investigations.

3. ROOTKIT CLASSIFICATION & EXECUTION RINGS
--------------------------------------------------------------------------------

[1. USER-MODE ROOTKITS (RING 3)]
  * Operates in user space; hooks Win32 APIs (e.g., `EnumProcesses`, `FindFirstFile`).
  * Function: Hides malware files and processes from Task Manager and Windows Explorer.

[2. KERNEL-MODE ROOTKITS (RING 0)]
  * Operates in kernel space as a signed/vulnerable device driver (`.sys` / `.ko`).
  * Direct Kernel Object Manipulation (DKOM): Unlinks malware processes from the kernel 
    `ActiveProcessLinks` list, making the process 100% invisible to the OS kernel itself.

[3. UEFI / FIRMWARE BOOTKITS]
  * Resides in the motherboard's SPI Flash ROM (e.g., BlackLotus, CosmicStrand).
  * Executes before the OS kernel loads, surviving full hard drive wipes and OS reinstalls.

4. COMMAND & CONTROL (C2) BEACONING & JITTER MECHANICS
--------------------------------------------------------------------------------

* Traditional Beacon: Heartbeats sent at exact 60-second intervals (60s, 60s, 60s) -> Flagged by SIEM.
* Jittered Beacon: Adds randomized percentage variation to sleep time (e.g. 60s sleep with 30% jitter):
  - Beacon 1 : 48.2s
  - Beacon 2 : 71.5s
  - Beacon 3 : 54.1s
  - Beacon 4 : 63.8s
  * Impact: Randomizes network timing, blending with authentic human web browsing traffic.

* DNS Tunneling (`dnscat2` / `iodine`):
  - Encodes C2 commands inside recursive DNS query subdomains (Port 53), bypassing egress web proxies.

--------------------------------------------------------------------------------
5. BLUE TEAM DETECTION & EDR MEMORY SCANNERS
--------------------------------------------------------------------------------

1. Unbacked Executable Memory Scanners:
   - Flags memory regions allocated with `PAGE_EXECUTE_READWRITE` (RWX) that lack disk backing.

2. Process Injection Monitoring:
   - Sysmon Event ID 8 (`CreateRemoteThread`) flags when a process injects shellcode into `explorer.exe`.

3. UEFI Secure Boot & Driver Signature Enforcement (DSE):
   - Cryptographically verifies bootloaders and kernel drivers, blocking Ring 0 rootkits from loading.

7. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL PERSISTENCE HABITS:
  1. Set Auto-Kill Deadman Switches: Ensure test C2 beacons self-destruct after assessment completion.
  2. Maintain a Dropped Artifact Log: Record every registry key, scheduled task, and account created.
  3. Use Jittered Outbound HTTPS: Randomize heartbeat intervals to test EDR behavioral heuristics.

* COMMON BEGINNER PERSISTENCE MISTAKES:
  - Leaving active backdoor shells on client servers after the penetration test concludes.
  - Creating noisy scheduled tasks with obvious names (e.g. `hack.exe` in `C:\`) that trigger alerts.
  - Forgetting that Section 43(c) and 66 of the IT Act 2000 punish introducing computer contaminants.
  - Hardcoding static 10-second beacon sleeps that immediately trigger SIEM periodicity alarms.
