1. EXECUTIVE OVERVIEW & THE CONTINUOUS IMPROVEMENT PARADIGM
--------------------------------------------------------------------------------
Cybersecurity is not a static one-time project—it is a living, continuous management discipline. 
The Plan-Do-Check-Act (PDCA) Deming cycle provides the iterative working procedure that drives 
ISO/IEC 27001 Information Security Management Systems:

  * THE REALITY   : A static security system rapidly decays due to emerging cyber exploits, 
                    architectural drift, shadow IT, and personnel turnover.
  * THE PARADIGM  : Continuous iteration through Plan ➔ Do ➔ Check ➔ Act ensures defenses 
                    adapt proactively to new threats, business changes, and legal regulations.

--------------------------------------------------------------------------------

3. THE 5-WHYS ROOT CAUSE ANALYSIS (RCA) METHODOLOGY
--------------------------------------------------------------------------------

In the ACT phase, an organization must uncover the systemic root cause behind audit findings:
  * Finding : Production customer database snapshot was found publicly accessible on AWS S3.
  * Why 1?  : Bucket permissions were set to 'Public'.
  * Why 2?  : DevOps engineer shared data with offshore testing contractor.
  * Why 3?  : Enterprise lacked a secure B2B API gateway for third-party testing.
  * Why 4?  : Third-party data access policy was not defined in the ISMS.
  * Why 5?  : (ROOT CAUSE) Vendor Risk Management procedure (A.5.19) was missing operational rules!

  * CAPA RESOLUTION :
    - Corrective Action : Immediately set S3 bucket to private and enabled KMS encryption.
    - Preventive Action : Deployed AWS SCP policy blocking public buckets + updated Vendor Policy!

--------------------------------------------------------------------------------
4. AUDIT FINDINGS CLASSIFICATION (STAGE 2 AUDITS)
--------------------------------------------------------------------------------

  * MAJOR NON-CONFORMITY (Major NC) : Total absence or breakdown of a mandatory ISO 27001 clause 
    (e.g. no risk assessment conducted, no internal audits performed). BLOCKS CERTIFICATION!
  * MINOR NON-CONFORMITY (Minor NC) : Isolated, non-systemic lapse (e.g. 1 server had clock drift, 
    1 training record missing). CERTIFICATION GRANTED subject to an approved 90-day CAPA plan.

7. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL PDCA HABITS:
  1. Complete the Full Loop: Never stop after Plan and Do; Check and Act are where resilience is forged.
  2. Apply the 5-Whys for Every Finding: Identify systemic architectural causes rather than blaming users.
  3. Convene Annual Management Reviews: Present objective audit KPIs to the Board of Directors (Cl 9.3).
  4. Mitigate Architectural Drift: Use automated Infrastructure as Code (IaC) drift detection tools.

* COMMON BEGINNER PDCA PITFALLS:
  - "Plan-Do-Stop" Syndrome (Planning and deploying tools, but never conducting internal audits).
  - Fixing only the immediate symptom (Closing audit findings without implementing preventive controls).
  - Auditing your own code (Violating internal auditor independence under Clause 9.2).
  - Neglecting to update the Risk Register when external laws or technologies change.
