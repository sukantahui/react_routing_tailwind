1. VIRTUAL PRIVATE CLOUD (VPC) & HYPERSCALER NETWORK ARCHITECTURE
--------------------------------------------------------------------------------
• Virtual Private Cloud (VPC):
  A logically isolated Software-Defined Network (SDN) dedicated to a tenant account.
  - Public Subnet: Attached to an Internet Gateway (IGW) for public web/ALB ingress.
  - Private Subnet: Routes outbound traffic through a managed NAT Gateway; zero direct public ingress.
• Security Groups vs Network ACLs (NACLs):
  - Security Groups: Stateful firewalls applied at the virtual NIC (instance) level (allow rules only).
  - Network ACLs: Stateless packet filters applied at the subnet boundary (numbered allow/deny rules).

--------------------------------------------------------------------------------
2. CLOUD OVERLAY NETWORKS & HYBRID CONNECTIVITY
--------------------------------------------------------------------------------
• VXLAN (Virtual Extensible LAN - RFC 7348) & GENEVE (RFC 8926):
  Encapsulates Layer 2 Ethernet frames inside Layer 4 UDP packets (UDP Port 4789 / 6081)
  using 24-bit VNIs to support 16 million isolated virtual tenant networks across Layer 3 underlays.
• Dedicated Cloud Interconnect (AWS Direct Connect / Azure ExpressRoute):
  Private, dedicated 1G/10G/100G optical fiber circuits connecting on-premises data centers
  directly to cloud regions with deterministic sub-4ms latency (bypassing the public Internet).
• Cloud Transit Gateway (TGW):
  Centralized hub-and-spoke routing fabric connecting hundreds of VPCs, VPNs, and on-premises links.
• PrivateLink & VPC Endpoints:
  Private Elastic Network Interfaces (ENIs) connecting internal VMs to cloud PaaS/SaaS services.

--------------------------------------------------------------------------------
3. CONTAINER NETWORKING & KUBERNETES EBPF INGRESS
--------------------------------------------------------------------------------
• eBPF & Cilium CNI:
  Executes high-performance sandboxed bytecode inside the Linux kernel networking layer,
  replacing slow iptables rules with identity-aware Layer-3/4/7 routing, encryption, and telemetry.
• Service Mesh (Istio / Linkerd):
  Sidecar Envoy proxies enforcing automatic Mutual TLS (mTLS) between all microservice containers.

5. COMMON PITFALLS & PRACTICAL ADVICE
--------------------------------------------------------------------------------
- Never configure `0.0.0.0/0` inbound access on administrative SSH, RDP, or database ports.
- Avoid complex N*(N-1)/2 VPC peering meshes; deploy centralized Cloud Transit Gateways.
- Utilize VPC Gateway Endpoints for S3/DynamoDB to eliminate unnecessary NAT data egress costs.
- Formulate all hybrid cloud Direct Connect, Transit Gateway, and NAT budgets in Indian Rupees (₹).
