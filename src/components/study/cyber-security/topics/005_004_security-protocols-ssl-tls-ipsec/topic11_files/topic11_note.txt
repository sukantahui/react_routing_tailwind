1. PROTOCOL DOWNGRADE ATTACKS: THREAT ANATOMY
----------------------------------------------------------------------------------------------------
Downgrade (or Version Rollback) attacks occur when an active Man-in-the-Middle (MitM) adversary 
intercepts the cryptographic handshake and alters the parameters (ClientHello / ServerHello) to force 
the client and server to negotiate obsolete protocols or weak export-grade ciphers that the attacker 
can break in real time.

Historic Downgrade Attacks & Vulnerabilities:
1. SSL Strip (Moxie Marlinspike, 2009):
   - Intercepts 302/301 HTTP-to-HTTPS redirects. Proxies HTTPS to backend server while serving plain HTTP 
     to the victim browser, intercepting session cookies and credentials in cleartext.
2. POODLE (Padding Oracle On Downgraded Legacy Encryption - CVE-2014-3566):
   - Forces fallback from TLS 1.2 to SSL 3.0 CBC mode, exploiting unverified padding to decrypt cookies.
3. FREAK (Factoring Attack on Export RSA Keys - CVE-2015-0204):
   - Forces servers to use legacy 512-bit export RSA keys, factorable via cloud compute in hours.
4. Logjam (CVE-2015-4000):
   - Downgrades Diffie-Hellman to 512-bit export groups (DHE_EXPORT), allowing precomputation attacks.
5. DROWN (Decrypting RSA with Obsolete and Weakened eNcryption - CVE-2016-0800):
   - Exploits cross-protocol key reuse on servers supporting SSLv2 to decrypt modern TLS sessions.


2. MODERN HARDENING STANDARDS & DEFENSE MECHANISMS
----------------------------------------------------------------------------------------------------
A. HTTP Strict Transport Security (HSTS - RFC 6797):
   - HTTP response header instructing browsers to communicate ONLY over HTTPS for a defined duration.
   - Header Syntax: `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
   - HSTS Preload List: Hardcoded in Chrome, Firefox, and Safari. Browsers initiate HTTPS connections 
     directly (Internal 307 Redirect) without ever sending a single unencrypted HTTP packet on the wire!

B. TLS Fallback Signaling Cipher Suite Value (TLS_FALLBACK_SCSV - RFC 7507):
   - Embedded by clients during retry handshakes. If a server supports a higher protocol version than 
     indicated in the fallback ClientHello, the server immediately aborts the connection with `inappropriate_fallback`.

C. Certificate Authority Authorization (CAA - RFC 8659):
   - DNS TXT record restricting which Certificate Authorities are authorized to issue certificates for the domain.
   - Example: `barrackpore.gov.in. IN CAA 0 issue "letsencrypt.org"`

D. Certificate Transparency (CT - RFC 9162 / RFC 6962):
   - Public append-only cryptographically audited Merkle Tree logs recording all issued SSL/TLS certificates.
   - Browsers enforce Signed Certificate Timestamps (SCTs) to reject secretly issued certificates.

E. Encrypted Client Hello (ECH):
   - Encrypts the Server Name Indication (SNI) and ClientHello metadata using the server's public key published in DNS (HTTPS/SVCB records), concealing the visited domain from network sniffers.
