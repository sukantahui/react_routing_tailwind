1. THE EMAIL SECURITY PROBLEM: HOP-BY-HOP VS END-TO-END
----------------------------------------------------------------------------------------------------
Standard email transmission operates via SMTP (Simple Mail Transfer Protocol) using a "store-and-forward" 
architecture. Even when STARTTLS (Hop-by-Hop Transport Encryption) is enabled, messages are decrypted 
to plaintext in memory and on disk at every intermediate Mail Transfer Agent (MTA) relay server.

Security Architecture Comparison:

| Feature                            | S/MIME (RFC 8551)        | OpenPGP / GPG (RFC 4880) |

2. DUAL CRYPTOGRAPHIC PIPELINE: SIGNING + ENCRYPTION
----------------------------------------------------------------------------------------------------
A. Digital Signing Pipeline (Sender: Susmita):
   1. Compute SHA-256 hash of email body.
   2. Encrypt hash with Sender's Private Key ➔ Creates Digital Signature.
   3. Guarantees: Data Origin Authentication, Integrity, and Legal Non-Repudiation.

B. Asymmetric Hybrid Encryption Pipeline (Sender: Susmita ➔ Receiver: Debangshu):
   1. Generate a random 256-bit symmetric session key ($K_{session}$) (e.g., AES-256-GCM).
   2. Encrypt the email message and signature using $K_{session}$.
   3. Encrypt $K_{session}$ with Receiver's (Debangshu's) Public Key.
   4. Transmit encrypted session key + encrypted message envelope.
   5. Guarantees: 100% End-to-End Confidentiality (Only Debangshu's Private Key can decrypt $K_{session}$).


3. THE EMAIL AUTHENTICATION TRIAD: SPF, DKIM, AND DMARC
----------------------------------------------------------------------------------------------------
1. Sender Policy Framework (SPF - RFC 7208):
   - DNS TXT record specifying authorized outbound mail server IP addresses for the domain.
   - Example: `v=spf1 ip4:203.0.113.10 include:_spf.google.com ~all`
2. DomainKeys Identified Mail (DKIM - RFC 6376):
   - MTA signs email headers and body with an asymmetric private key. Receiver validates the signature 
     against the sender domain's public key published in DNS (`selector._domainkey.domain.com`).
3. Domain-based Message Authentication, Reporting & Conformance (DMARC - RFC 7489):
   - Enforces policy action (`p=none`, `p=quarantine`, `p=reject`) if SPF or DKIM fails alignment, 
     and sends forensic XML reports to domain administrators.
