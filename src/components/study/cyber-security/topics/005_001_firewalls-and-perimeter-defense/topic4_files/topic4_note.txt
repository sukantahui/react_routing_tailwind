1. DEFINITION & HISTORICAL TAXONOMY
----------------------------------------------------------------------------------------------------
Stateful Packet Inspection (SPI), patented by Check Point Software Technologies (Gil Shwed) in 1993, 
represents the third generation of firewall architecture. An SPI firewall tracks the state of active network 
connections across Layers 3 and 4 of the OSI model by maintaining a dynamic in-memory State Table 
(known in Linux Netfilter as the `conntrack` table).

Unlike stateless filters that evaluate packets in isolation, an SPI firewall inspects the full lifecycle 
of every communication session, ensuring that incoming packets are accepted ONLY if they correspond to an 
actively established session initiated by an authorized internal host or a legitimate public service handshake.


2. THE LINUX NETFILTER CONNECTION TRACKING (`conntrack`) ARCHITECTURE
----------------------------------------------------------------------------------------------------
Each entry in the kernel connection tracking table consists of two directional 5-tuple structures:

  [ORIGINAL DIRECTION (Client → Server)]
    - Source IP, Source Port, Destination IP, Destination Port, Protocol (e.g., 10.10.1.50:51200 → 203.0.113.88:443 [TCP])
  [REPLY DIRECTION (Server → Client)]
    - Expected Source IP, Expected Source Port, Expected Dest IP, Expected Dest Port (203.0.113.88:443 → 10.10.1.50:51200 [TCP])

Connection States in Netfilter / iptables:
  1. `NEW`         : The initial packet of a connection (e.g. TCP SYN without ACK) attempting to initiate a session.
  2. `ESTABLISHED` : Packets in both directions have been observed (e.g. 3-way handshake completed).
  3. `RELATED`     : A new connection created by an existing established connection (e.g. FTP data channel, ICMP error).
  4. `INVALID`     : Packets that do not follow proper protocol state transitions (e.g. unsolicited ACK, corrupt checksum).
  5. `UNTRACKED`   : Packets explicitly bypassed from conntrack using `-j NOTRACK` in the `raw` table.


3. TCP FINITE STATE MACHINE (FSM) & SEQUENCE NUMBER WINDOW TRACKING
----------------------------------------------------------------------------------------------------
Modern SPI firewalls monitor TCP sequence and acknowledgment numbers to prevent blind TCP injection attacks:

  [CLIENT]                                                      [SERVER]
     │                                                             │
     │ ──── 1. SYN (seq=X) [State: SYN_SENT] ───────────────────>  │
     │                                                             │
     │ <─── 2. SYN+ACK (seq=Y, ack=X+1) [State: SYN_RECV] ─────── │
     │                                                             │
     │ ──── 3. ACK (seq=X+1, ack=Y+1) [State: ESTABLISHED] ─────>  │
     │                                                             │

Window Validation:
  The firewall enforces: `RCV.NXT <= Packet.Seq <= RCV.NXT + RCV.WND`.
  If an external attacker injects a spoofed TCP packet with an out-of-window sequence number, the SPI 
  engine flags it as `INVALID` and drops it immediately.


4. SECURING DYNAMIC PROTOCOLS (APPLICATION LAYER GATEWAY - ALG HELPERS)
----------------------------------------------------------------------------------------------------
Dynamic protocols negotiate secondary ephemeral data ports inside control payloads:

  - Active FTP (Port 21 Control → Ephemeral Data Port):
    Client sends `PORT 10,10,1,50,200,10` (Port 51210).
    The kernel FTP ALG helper (`nf_conntrack_ftp`) inspects payload, parses the negotiated port, and 
    dynamically inserts a temporary, time-limited `RELATED` pinhole allowing the FTP server to connect 
    back to port 51210 without leaving all high ports wide open!

  - SIP / H.323 (VoIP):
    SIP control on UDP port 5060 negotiates RTP audio streams on UDP ports 16384-32767. SIP ALGs 
    dynamically track and permit only the active audio streams.


5. DENIAL-OF-SERVICE ON SPI: CONTRACK EXHAUSTION & SYN COOKIE DEFENSE
----------------------------------------------------------------------------------------------------
Vulnerability:
  Because an SPI firewall allocates ~320 bytes of kernel RAM per session, an attacker launching a distributed 
  SYN flood can fill the conntrack table (`net.netfilter.nf_conntrack_max`), causing the kernel error:
  `nf_conntrack: table full, dropping packet`, which denies service to all legitimate traffic.

Defense (SYN Cookies - RFC 4987):
  When the conntrack table fills beyond a threshold, the firewall ceases allocating state for SYN packets. 
  Instead, it encodes connection parameters (MSS, timestamp, cryptographic secret) into the 32-bit initial 
  TCP sequence number ($Y = \text{HMAC}(Src, Dst, Port, Secret) + Timestamp$).
  Only when the client returns a valid ACK ($Y+1$) does the firewall allocate state in memory!
