1. DEFINITION & HISTORICAL TAXONOMY
----------------------------------------------------------------------------------------------------
First-generation firewalls, developed in the late 1980s, operate as Stateless Packet Filters. 
A Stateless Packet Filtering Firewall inspects incoming and outgoing network packets at Layer 3 (Network) 
and Layer 4 (Transport) of the OSI model in isolation, evaluating each packet independently against a static 
rule base without remembering previous packets or tracking connection state.

Because stateless filters do not maintain a connection tracking table (`conntrack`), they make forwarding 
decisions in microseconds with minimal CPU and memory overhead, making them ideal for high-throughput 
edge screening routers and basic ACL filtering.


2. THE 5-TUPLE INSPECTION MATRIX
----------------------------------------------------------------------------------------------------
A stateless packet filter evaluates each packet against the classic 5-Tuple plus TCP flag bits:

  1. SOURCE IP ADDRESS        : Network layer origin (e.g. 198.51.100.25)
  2. DESTINATION IP ADDRESS   : Network layer destination (e.g. 172.16.1.10)
  3. TRANSPORT PROTOCOL       : TCP (6), UDP (17), ICMP (1), GRE (47)
  4. SOURCE PORT              : Ephemeral port (e.g. 52410) or service port
  5. DESTINATION PORT         : Target service port (e.g. 80, 443, 53, 22)
  +  TCP CONTROL FLAGS        : SYN, ACK, FIN, RST, PSH, URG


3. INHERENT VULNERABILITIES & LIMITATIONS OF STATELESS FILTERING
----------------------------------------------------------------------------------------------------
While fast, stateless filtering suffers from major structural vulnerabilities:

  1. THE TCP ACK SPOOFING / ESTABLISHED BYPASS:
     - To permit inbound reply traffic for web browsing, stateless firewalls use rules like:
       `PERMIT TCP ANY:ANY -> LAN:ANY IF TCP.FLAGS contains ACK`
     - Attack Vector: An external attacker crafts an unsolicited packet with the ACK flag bit set (`0x10`). 
       The stateless filter assumes it is a reply to an internal session and permits it through!

  2. BLIND TO APPLICATION LAYER (LAYER 7) PAYLOADS:
     - Stateless filters cannot inspect HTTP URIs, SQL queries, or malware signatures. A packet to port 443 
       containing a malicious SQL injection payload is forwarded without restriction.

  3. INABILITY TO SECURE DYNAMIC PORTS (FTP / RPC / SIP):
     - Protocols like Active FTP use port 21 for commands but dynamically negotiate random high ports 
       (1024-65535) for data transfer. Stateless filters must leave huge port ranges wide open.

  4. FRAGMENTATION ATTACKS (TINY FRAGMENT EXPLOITS):
     - Attackers split a TCP packet across IP fragments such that the TCP flags and destination port reside 
       in Fragment 2. Naive stateless filters inspecting Fragment 1 cannot evaluate the port and allow it.


4. CISCO EXTENDED ACL & LINUX STATELESS IPTABLES SYNTAX
----------------------------------------------------------------------------------------------------
[1. Cisco IOS Extended Stateless ACL:]
  access-list 101 permit tcp any host 172.16.1.10 eq 443
  access-list 101 permit tcp any host 172.16.1.10 eq 80
  access-list 101 permit tcp any 10.10.1.0 0.0.0.255 established  ! Matches ACK or RST flag
  access-list 101 deny ip any any

[2. Linux iptables Stateless Rules (RAW Table / No Conntrack):]
  # Stateless rule permitting incoming established TCP via ACK flag
  iptables -A INPUT -p tcp --tcp-flags ACK ACK -j ACCEPT
  iptables -A INPUT -p tcp --dport 443 -j ACCEPT
  iptables -A INPUT -j DROP


5. MATHEMATICAL FORMULATION: FILTERING LATENCY & PACKET PROCESSING OVERHEAD
----------------------------------------------------------------------------------------------------
For a stateless filter with 'N' sequential rules, average lookup time per packet is O(N):

  T_lookup = Sum(T_rule_eval_i) for i = 1 to M (where M is matched rule index)

Because no state table lookup or hash table collision resolution is needed:
  - Stateless Packet Filter Latency: ~0.5 to 2 nanoseconds per packet.
  - Stateful / DPI Inspection Latency: ~50 to 500 nanoseconds per packet (250x higher!).

This explains why border routers process line-rate 100 Gbps traffic using stateless hardware ACLs (TCAM) 
before forwarding to stateful NGFWs.

7. STATUTORY COMPLIANCE & EXAM CHECKLIST
----------------------------------------------------------------------------------------------------
[ ] Stateless firewalls inspect Layer 3 and Layer 4 headers in isolation (5-Tuple).
[ ] 5-Tuple: Source IP, Destination IP, Protocol, Source Port, Destination Port + TCP Flags.
[ ] Stateless filters do NOT maintain state tables (`conntrack`), providing line-rate speed (O(1)/O(N)).
[ ] Major weakness: Susceptible to TCP ACK spoofing, fragmentation attacks, and dynamic port bypasses.
[ ] Cisco `established` keyword checks for ACK or RST flag bits (`0x10` or `0x04`).
[ ] Hardware TCAM (Ternary Content-Addressable Memory) evaluates stateless ACLs in parallel in 1 clock cycle.
[ ] Best practice: Combine stateless edge ACLs for high-speed volumetric dropping with stateful NGFW for depth.
