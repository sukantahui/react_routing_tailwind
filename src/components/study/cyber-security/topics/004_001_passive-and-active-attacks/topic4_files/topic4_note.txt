1. EXECUTIVE OVERVIEW & ACTIVE DATA INTEGRITY THREATS
--------------------------------------------------------------------------------
An Active Message Modification Attack involves the unauthorized interception, alteration, 
substitution, reordering, or injection of data in transit or at rest. This directly violates 
the INTEGRITY and AUTHENTICITY pillars of the CIA Triad:

  * THE CORRUPTION OF STATE :
    - Unlike passive attacks (ΔS = ∅), active message tampering creates state corruption:
        D' ≠ D  (Data payloads altered)
        C' ≠ C  (System configurations manipulated)

  * THE MALLEABILITY TRAP :
    - Encryption alone does NOT protect integrity! In stream ciphers (AES-CTR) and CBC mode:
        C' = C ⊕ Δ  ===>  P' = P ⊕ Δ
      An attacker can predictably flip bits in ciphertext to alter plaintext values 
      (e.g. changing ₹500 to ₹50,000) without triggering key decryption errors!

2. CRYPTOGRAPHIC INTEGRITY & AUTHENTICATION MECHANISMS
--------------------------------------------------------------------------------

A. MESSAGE AUTHENTICATION CODES (HMAC-SHA256) :
   - Uses a dual-nested hash construction to prevent length-extension attacks:
       HMAC(K, m) = H( (K ⊕ opad) || H( (K ⊕ ipad) || m ) )
   - Guarantees message integrity and proof of shared secret key ownership.

B. AUTHENTICATED ENCRYPTION WITH ASSOCIATED DATA (AEAD - AES-256-GCM) :
   - Computes GHASH polynomial field authentication over Galois Field GF(2^128):
       Tag = GHASH_H( AAD, Ciphertext ) ⊕ AES_K(IV)
   - Any single-bit modification causes tag verification to fail; decryption is instantly aborted.

C. ASYMMETRIC DIGITAL SIGNATURES (Ed25519 / ECDSA) :
   - Sender signs message hash with private key: S = Sign_Priv( H(m) ).
   - Receiver verifies using public key: Verify_Pub( H(m), S ).
   - Guarantees Data Integrity + Non-Repudiation (Sender cannot deny authoring message).
