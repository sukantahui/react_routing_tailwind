1. EXECUTIVE OVERVIEW & IN-BAND EXTRACTION TAXONOMY
--------------------------------------------------------------------------------
In-Band SQL Injection occurs when the attacker sends the exploit and receives exfiltrated database 
records directly within the application's HTTP response channel:

  * THE TWO CORE IN-BAND TECHNIQUES :
    1. UNION-BASED SQLi : Appends a custom `SELECT` query to the original query results using `UNION`.
    2. ERROR-BASED SQLi : Triggers deliberate runtime database errors containing query data inside error text.

--------------------------------------------------------------------------------
2. UNION-BASED SQLi EXPLOITATION PIPELINE
--------------------------------------------------------------------------------

  * STEP 1: Determine Column Count via `ORDER BY`:
    - Inject `ORDER BY 1--`, `ORDER BY 2--`, `ORDER BY 3--` until an error occurs ($K = 3$).

  * STEP 2: Identify String-Compatible Columns:
    - Inject `UNION SELECT 'test', NULL, NULL--` until query executes without type errors.

  * STEP 3: Suppress Original Query Results:
    - Set original parameter to false (`id = -1`) so the UI renders the injected UNION data.

  * STEP 4: Harvest Database Schema & Dump Tables:
    - Query `information_schema.tables` and `information_schema.columns` to map tables.
    - Use `GROUP_CONCAT()` or `string_agg()` to exfiltrate entire tables in a single HTTP response!

--------------------------------------------------------------------------------

5. STUDENT MINI CHECKLIST (EXAM & CAREER ESSENTIALS)
================================================================================
  [✔] UNION SQLi requires identical column counts ($K$) and compatible data types.
  [✔] `ORDER BY 1, 2, 3...` determines the exact column count of the original query.
  [✔] Prepending `id = -1` suppresses legitimate records so the UI renders injected UNION data.
  [✔] Error-Based SQLi exploits `CAST()` or `ExtractValue()` to reflect data inside error messages.
  [✔] Disabling verbose database error messages in production completely neutralizes Error-Based SQLi.
  [✔] Parameterized Prepared Statements provide 100% mathematical immunity against In-Band SQLi.
