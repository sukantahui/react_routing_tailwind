1. EXECUTIVE OVERVIEW & RDBMS QUERY COMPILATION
--------------------------------------------------------------------------------
SQL Injection occurs when untrusted user input is directly concatenated into an SQL statement, 
altering the database parser's Abstract Syntax Tree (AST) before execution:

  * THE 4 SQL INJECTION CONTEXTS :
    1. STRING LITERAL CONTEXT : `WHERE user = 'USER'` ➔ Requires single quote `'` breakout.
    2. NUMERIC CONTEXT        : `WHERE id = USER`     ➔ No quotes needed; executes SQL commands directly!
    3. IDENTIFIER CONTEXT     : `ORDER BY USER`       ➔ Cannot use `?` placeholders; requires whitelisting!
    4. DML UPDATE / INSERT    : `UPDATE ... SET bio = USER` ➔ Overwrites other users' roles/passwords.

5. STUDENT MINI CHECKLIST (EXAM & CAREER ESSENTIALS)
================================================================================
  [✔] String concatenation mutates the query AST, while Prepared Statements keep the AST fixed.
  [✔] Numeric context SQLi requires no quotes, executing operators (`UNION`, `OR`) directly.
  [✔] Tautology `' OR 1=1--` bypasses login because `False OR True === True` for all database rows.
  [✔] `ORDER BY` injection cannot use `?` placeholders and must be protected via strict whitelists.
  [✔] MySQL comments require a trailing space (`-- `) or hash (`#`), while Postgres uses `--`.
  [✔] Section 66F of the IT Act penalizes SQL injection cyber terrorism with Life Imprisonment.
