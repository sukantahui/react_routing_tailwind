1. EXECUTIVE OVERVIEW & FORMAL 5-TUPLE MATHEMATICAL DEFINITION
--------------------------------------------------------------------------------
In modern formal mathematical cryptography, a cryptosystem is rigorously defined 
as a 5-tuple:

                    S = ( P, C, K, E, D )

  * P (Plaintext Space)   : The set of all possible unencrypted messages.
  * C (Ciphertext Space)  : The set of all possible encrypted ciphertext outputs.
  * K (Key Space)         : The finite set of all possible secret cryptographic keys.
  * E (Encryption Family) : A set of functions { e_k : P → C } indexed by key k in K.
  * D (Decryption Family) : A set of functions { d_k : C → P } indexed by key k in K.

* FUNDAMENTAL DECRYPTION INVARIANCE CONDITION:
  For every plaintext message x in P and every key k in K:
                    d_k( e_k( x ) ) = x

2. CORE CRYPTOGRAPHIC PRIMITIVES & TERMINOLOGY
--------------------------------------------------------------------------------

+--------------------+-------------------------+------------------------------------------------+
| PRIMITIVE          | MATHEMATICAL ROLE       | PRACTICAL SECURITY FUNCTION                    |
+--------------------+-------------------------+------------------------------------------------+
| 1. Plaintext (P)   | Raw original data       | Human-readable or binary unencrypted cleartext |
+--------------------+-------------------------+------------------------------------------------+
| 2. Ciphertext (C)  | Scrambled encrypted data| High-entropy pseudo-random output              |
+--------------------+-------------------------+------------------------------------------------+
| 3. Key (K)         | Cipher parameter        | Governs transformation; 256 bits = 2^256 keys  |
+--------------------+-------------------------+------------------------------------------------+
| 4. Nonce / IV      | Randomizing token       | Ensures identical plaintexts produce unique C  |
+--------------------+-------------------------+------------------------------------------------+
| 5. Salt            | Random string for hashes| Appended to passwords to defeat Rainbow Tables |
+--------------------+-------------------------+------------------------------------------------+

3. BLOCK CIPHER MODES OF OPERATION COMPARISON
--------------------------------------------------------------------------------

[1. ELECTRONIC CODEBOOK (ECB) - INSECURE & FORBIDDEN]
  * Mechanism: Encrypts each 16-byte block independently: C_i = E_k(P_i).
  * Flaw: Identical plaintext blocks produce identical ciphertext blocks!
  * Visual Leak: Encrypting bitmap images preserves outlines (The ECB Penguin Leak).

[2. CIPHER BLOCK CHAINING (CBC) - SEQUENTIAL WITH IV]
  * Mechanism: XORs each block with preceding ciphertext: C_i = E_k(P_i ^ C_{i-1}).
  * Flaw: Malleable; vulnerable to Padding Oracle attacks if unauthenticated.

[3. COUNTER MODE (CTR) - HIGH-SPEED STREAM ADAPTER]
  * Mechanism: Encrypts successive counter values: C_i = P_i ^ E_k(Nonce || Counter_i).
  * Advantage: 100% parallelizable on multi-core CPUs; requires zero padding.

[4. GALOIS/COUNTER MODE (GCM) - AUTHENTICATED ENCRYPTION (AEAD)]
  * Mechanism: Combines CTR encryption with Galois field authentication (GMAC).
  * Advantage: Provides Confidentiality + Integrity Tag (T) in a single hardware pass.

--------------------------------------------------------------------------------
4. KEY ENTROPY: TRNG VS CSPRNG
--------------------------------------------------------------------------------

1. True Random Number Generators (TRNG):
   - Measures non-deterministic physical phenomena (thermal noise, quantum fluctuations in hardware).

2. Cryptographically Secure Pseudo-Random Number Generators (CSPRNG):
   - Algorithmic bit generators (e.g. `/dev/urandom`, `BCryptGenRandom`) seeded by physical TRNGs, 
     passing all NIST SP 800-22 statistical randomness tests.

5. INDIAN STATUTORY COMPLIANCE & LEGAL LIABILITY
--------------------------------------------------------------------------------

* IT ACT 2000 SECTION 43A (Reasonable Security Practices):
  - Requires body corporates handling Sensitive Personal Data or Information (SPDI) to enforce 
    documented encryption standards (ISO/IEC 27001).

* DIGITAL PERSONAL DATA PROTECTION (DPDP) ACT 2023:
  - Imposes penalties extending up to ₹250 Crores for failure to implement reasonable security 
    safeguards (like AES-256 authenticated encryption) leading to personal data breaches.

7. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL CRYPTOGRAPHIC PRIMITIVE HABITS:
  1. Never Use ECB Mode: Always use AEAD modes (AES-GCM or ChaCha20-Poly1305).
  2. Enforce 96-bit Unique Nonces: Never encrypt two messages with the same (Key, Nonce) pair.
  3. Generate Keys from CSPRNGs: Never use `rand()` or `time()` to generate cryptographic keys.

* COMMON BEGINNER CRYPTOGRAPHY MISTAKES:
  - Confusing a Salt (Password Hashing) with an IV (Block Cipher Chaining).
  - Reusing nonces in AES-GCM (Allows attackers to forge authentication tags).
  - Assuming AES-CBC provides integrity (Vulnerable to padding oracle bit-flipping).
  - Storing plaintext customer financial data in violation of IT Act Section 43A.
