1. EXECUTIVE OVERVIEW & MATHEMATICAL DEFINITION
--------------------------------------------------------------------------------
A Cryptographic Hash Function is a deterministic, one-way mathematical algorithm that 
compresses an arbitrary-length binary input string into a fixed-length output digest:

                    H : {0, 1}*  ->  {0, 1}^n

* CORE CHARACTERISTICS:
  - Deterministic Output : The exact same input message always produces the identical hash digest.
  - Fixed-Length Digest  : Output length is constant (MD5: 128 bits, SHA-1: 160 bits, SHA-256: 256 bits).
  - Avalanche Effect     : Flipping a single bit in the input flips ~50% of the output bits randomly.

--------------------------------------------------------------------------------
2. THE 3 FUNDAMENTAL SECURITY PROPERTIES
--------------------------------------------------------------------------------

  1. PREIMAGE RESISTANCE (One-Way Property):
     - Given hash digest h, it is computationally infeasible to find any message m such that H(m) = h.
     - Work Factor: O( 2^n ).

  2. SECOND PREIMAGE RESISTANCE (Weak Collision Resistance):
     - Given a specific message m_1, it is computationally infeasible to find another message m_2 != m_1 
       such that H(m_1) = H(m_2).
     - Work Factor: O( 2^n ).

  3. COLLISION RESISTANCE (Strong Collision Resistance):
     - It is computationally infeasible to find ANY arbitrary pair of distinct messages (m_1, m_2) 
       such that H(m_1) = H(m_2).
     - Work Factor: O( 2^(n/2) ) due to the Birthday Paradox!

4. THE MERKLE-DAMGÅRD CONSTRUCTION & LENGTH EXTENSION
--------------------------------------------------------------------------------

* MERKLE-DAMGÅRD PIPELINE (MD5, SHA-1, SHA-2):
  - Pads message to a multiple of 512 bits (appending `100...` and 64-bit message length).
  - Iteratively feeds 512-bit blocks through compression function: H_i = f( H_{i-1}, M_i ).

* LENGTH EXTENSION ATTACK FLAW:
  - Because the output hash is the exact internal state of the final compression block, naive 
    keyed hashing `Hash(Key || Message)` is broken: attackers can append data `M'` and compute 
    `Hash(Key || Message || M')` without knowing `Key`!
  - Permanent Remedy: Use HMAC-SHA256: Hash( (K ^ opad) || Hash( (K ^ ipad) || M ) ).

--------------------------------------------------------------------------------
5. PASSWORD HASHING: WHY SHA-256 IS INSECURE FOR PASSWORDS
--------------------------------------------------------------------------------

* THE FAST HASH PROBLEM:
  - Fast cryptographic hashes (SHA-256) are designed for speed: modern GPUs test >100 Billion 
    SHA-256 hashes per second, cracking 8-character passwords in minutes.

* MEMORY-HARD PASSWORD HASHING (ARGON2id / BCRYPT):
  - Password hashing requires intentionally slow, memory-hard algorithms.
  - Argon2id allocates hundreds of megabytes of RAM per hash evaluation, throttling GPU cracking 
    speeds to just ~50 guesses/sec, defeating dictionary and brute-force attacks.

6. INDIAN STATUTORY COMPLIANCE & LEGAL ADMISSIBILITY
--------------------------------------------------------------------------------

* SECTION 65B OF INDIAN EVIDENCE ACT 1872 / BSA 2023:
  - Mandatory SHA-256 hashing of electronic evidence (hard drives, server logs, CCTV footage) at the 
    moment of forensic seizure to establish an immutable mathematical Chain of Custody in court.

* DIGITAL PERSONAL DATA PROTECTION (DPDP) ACT 2023:
  - Pseudonymization: Replacing raw customer identifiers (Aadhaar numbers) with HMAC-SHA256 tokens 
    keyed by a secret HSM master key, enabling secure big data analytics with zero data leak liability.

8. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL HASHING HABITS:
  1. Default to SHA-256 or SHA-3: Standardize on FIPS 180-4 / FIPS 202 for all data integrity checks.
  2. Use HMAC-SHA256 for Message Authentication: Prevents length extension attacks.
  3. Use Argon2id with Unique Salts for Passwords: Slow memory-hard hashing prevents GPU cracking.

* COMMON BEGINNER HASHING PITFALLS:
  - Using MD5 or SHA-1 for digital signatures (Vulnerable to collision attacks).
  - Storing passwords using unsalted SHA-256 (Vulnerable to rainbow tables and fast GPU cracking).
  - Using naive `Hash(Key || Message)` for authentication (Vulnerable to length extension).
  - Neglecting Section 65B forensic hash certificates during digital evidence seizure.
