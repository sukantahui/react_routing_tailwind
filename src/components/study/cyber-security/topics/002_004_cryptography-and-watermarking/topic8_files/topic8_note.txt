1. EXECUTIVE OVERVIEW & THE TRIAD OF AUTHENTICITY
--------------------------------------------------------------------------------
A Digital Signature is a mathematical mechanism that binds an author's cryptographic 
identity to a specific digital document by signing the document's cryptographic hash 
with the author's secret Private Key:

         S = Sign_{K_priv}( Hash( M ) )    |    Verify_{K_pub}( Hash( M ), S ) → { True, False }

* THE 3 PILLARS OF MESSAGE AUTHENTICITY:
  1. MESSAGE INTEGRITY   : Recipient verifies that not a single bit was modified in transit.
  2. AUTHENTICATION      : Proves that the message was generated by the authentic private key holder.
  3. NON-REPUDIATION     : Prevents the author from denying creating the document in a court of law.

3. DIGITAL SIGNATURE ALGORITHMS EVOLUTION
--------------------------------------------------------------------------------

  * RSA-PKCS#1 v1.5 vs RSA-PSS (FIPS 186-5):
    - Legacy PKCS#1 v1.5 padding was deterministic and vulnerable to Bleichenbacher forgery attacks.
    - Modern RSA-PSS (Probabilistic Signature Scheme) adds randomized salt and MGF1 masking, 
      providing provable cryptographic reduction to the RSA integer factorization problem.

  * THE SONY PLAYSTATION 3 (PS3) ECDSA DISASTER (2010):
    - Sony's engineers hardcoded a static constant for the random nonce k in ECDSA signing.
    - Signing two games with the same k allowed hackers to deduce Sony's root private key d:
           k = (z1 - z2) / (s1 - s2) mod n  ==>  d = (s1 * k - z1) / r mod n
    - Root private key extracted in milliseconds → Console hypervisor permanently cracked!

  * Ed25519 (RFC 8032 - DETERMINISTIC EDWARDS CURVE SIGNATURES):
    - Derives nonce deterministically from hash of private key and message: r = SHA-512( K_priv || M ).
    - 100% immune to random number generator bias and nonce reuse; executes in strict constant-time.

4. PUBLIC KEY INFRASTRUCTURE (PKI) & REVOCATION
--------------------------------------------------------------------------------

* X.509 CERTIFICATE HIERARCHY:
  - Root CA (Self-signed master) → Intermediate CAs → End-Entity Certificates.

* REVOCATION MECHANISMS:
  1. CRL (Certificate Revocation List) : Bulky, high-latency lists of revoked serial numbers.
  2. OCSP (Online Certificate Status)  : Real-time queries to CA (Leaked user privacy to CA).
  3. OCSP STAPLING (RFC 6066)          : Web server caches CA-signed OCSP response and sends it 
     directly during TLS handshake (Zero latency, 100% user privacy).

* CERTIFICATE TRANSPARENCY (CT / RFC 6962):
  - Public, append-only Merkle tree logs. Browsers reject SSL certificates lacking Signed Certificate 
    Timestamps (SCTs), preventing rogue CAs from issuing secret unauthorized certificates.

5. POST-QUANTUM DIGITAL SIGNATURE STANDARDS (NIST 2024)
--------------------------------------------------------------------------------

* FIPS 204 (ML-DSA / CRYSTALS-Dilithium) :
  - Lattice-based digital signature based on Module Learning with Errors (MLWE).
  - 100% immune to Shor's quantum algorithm; replaces RSA-PSS and ECDSA globally.

* FIPS 205 (SLH-DSA / SPHINCS+) :
  - Stateless hash-based digital signature backup; built strictly on cryptographic hash security.

6. INDIAN STATUTORY COMPLIANCE & LEGAL WEIGHT
--------------------------------------------------------------------------------

* IT ACT 2000 SECTION 3 & 5 (Legal Admissibility):
  - Section 5 gives asymmetric digital signatures identical legal validity and evidentiary non-repudiation 
    to physical handwritten ink signatures in all Indian courts of law.

* CONTROLLER OF CERTIFYING AUTHORITIES (CCA INDIA) CLASS-3 DSC:
  - Licensed CAs (eMudhra, Capricorn, (n)Code) issue Class-3 Digital Signature Certificates (DSCs) 
    anchored to 2048-bit RSA/ECC keys stored inside FIPS 140-2 Level 2 cryptographic USB tokens.

* DIGITAL PERSONAL DATA PROTECTION (DPDP) ACT 2023:
  - Data Principal Consent Artifacts must be cryptographically signed, creating tamper-evident 
    audit trails for the Data Protection Board of India.

8. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL DIGITAL SIGNATURE HABITS:
  1. Default to Ed25519 or RSA-PSS: Eliminates deterministic padding and RNG failure vulnerabilities.
  2. Always Sign the Hash (Hash-then-Sign): Never pass raw unhashed files into asymmetric signing APIs.
  3. Store Root Signing Keys in FIPS 140-3 HSMs: Never store private keys on plain hard drives or in source code.
  4. Enforce OCSP Stapling: Validate certificate revocation in real time with zero network latency.

* COMMON BEGINNER SIGNATURE PITFALLS:
  - Believing symmetric HMAC provides legal non-repudiation (Both parties hold the key; it is repudiable).
  - Reusing random nonces in ECDSA (Leaks the private key in milliseconds, as Sony PS3 proved).
  - Using legacy RSA PKCS#1 v1.5 padding (Vulnerable to Bleichenbacher forgery attacks).
  - Failing to check certificate expiration and revocation status (Accepting revoked certificates).
