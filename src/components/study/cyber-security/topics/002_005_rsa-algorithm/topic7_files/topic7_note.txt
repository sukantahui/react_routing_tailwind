1. EXECUTIVE OVERVIEW & SECURITY VS PERFORMANCE TRADE-OFF
--------------------------------------------------------------------------------
Selecting the appropriate RSA key length requires balancing cryptographic security margins 
against computational throughput, latency, and energy consumption. As modulus bit length b 
increases, modular exponentiation complexity scales cubically O(b^3):

  * SECURITY BOUNDARY     : General Number Field Sieve (GNFS) sub-exponential scaling L_N[1/3, c].
  * PERFORMANCE BOTTLENECK: Doubling key size (2048 -> 4096) slows private signing by ~7.7x.

3. ASYMMETRIC VS SYMMETRIC VS ECC SECURITY EQUIVALENCE
--------------------------------------------------------------------------------

Under NIST SP 800-57 Part 1 Rev 5:
  * 80-bit Security  : RSA-1024  ==  ECC-160   ==  2-Key Triple DES (DEPRECATED)
  * 112-bit Security : RSA-2048  ==  ECC-224   ==  3-Key Triple DES (Standard)
  * 128-bit Security : RSA-3072  ==  ECC-256   ==  AES-128 (High Security)
  * 192-bit Security : RSA-7680  ==  ECC-384   ==  AES-192 (Top Secret)
  * 256-bit Security : RSA-15360 ==  ECC-521   ==  AES-256 (Quantum Era Goal)

* WHY RSA KEYS GROW EXPONENTIALLY FASTER THAN ECC:
  - RSA factoring (GNFS) has sub-exponential complexity L_N[1/3, c].
  - ECC discrete log attacks (Pollard's Rho) are fully exponential O(sqrt(p)).
  - Therefore, a tiny 256-bit ECC key matches a massive 3072-bit RSA key!

4. NETWORK & HARDWARE CONSTRAINTS
--------------------------------------------------------------------------------

  * TLS CERTIFICATE CHAIN FRAGMENTATION:
    - Standard Ethernet TCP Maximum Segment Size (MSS) is 1460 bytes.
    - RSA-2048 Certificate Chain: ~1.8 KB (Requires 2 TCP packets).
    - RSA-4096 Certificate Chain: ~3.6 KB (Requires 3-4 TCP packets, causing packet-loss latency).
    - Ed25519 Certificate Chain:  ~0.6 KB (Fits in a single sub-millisecond IP packet!).

  * IOT BATTERY CONSUMPTION:
    - On an ARM Cortex-M4 @ 80 MHz, RSA-4096 takes 1.25 seconds and consumes 165 mJ per signature, 
      reducing battery lifespan from 5 years to 6 months.

5. INDIAN STATUTORY COMPLIANCE & CCA GUIDELINES
--------------------------------------------------------------------------------

* CCA INDIA CLASS 3 DSC GUIDELINES (IT ACT 2000 SECTION 35):
  - All Digital Signature Certificates used in Indian e-tendering, MCA21 corporate filings, and 
    tax portals must use at least RSA-2048 with SHA-256. RSA-1024 is strictly illegal.

* DIGITAL PERSONAL DATA PROTECTION (DPDP) ACT 2023:
  - Fiduciaries must decommission deprecated key lengths; retaining RSA-1024 exposes organizations 
    to statutory penalties up to ₹250 Crores under Section 33.

7. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL KEY MANAGEMENT HABITS:
  1. Enforce RSA-2048 as Universal Minimum: Strictly reject any client or certificate using RSA-1024.
  2. Reserve RSA-4096 for Root CAs: Use 4096-bit keys for offline root vaults with 20-30 year lifespans.
  3. Pre-Calculate TLS Handshake Budgets: Factor in TCP MSS packet fragmentation for high-traffic servers.
  4. Prepare for Post-Quantum Migration: Do not inflate RSA to 8192 bits; deploy FIPS 203 ML-KEM instead.

* COMMON BEGINNER KEY MANAGEMENT PITFALLS:
  - Assuming RSA-2048 provides 2048 bits of security (It provides only 112 bits of symmetric security!).
  - Using RSA-4096 on battery-powered IoT microcontrollers (Drains battery in months).
  - Deploying RSA-1024 in production (Vulnerable to $1M ASIC factoring clusters).
  - Believing RSA-8192 provides quantum resistance (Broken by Shor's algorithm in polynomial time).
