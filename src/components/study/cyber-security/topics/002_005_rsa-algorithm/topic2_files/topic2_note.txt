1. EXECUTIVE OVERVIEW & MODULAR ARITHMETIC IN ASYMMETRIC CRYPTOGRAPHY
--------------------------------------------------------------------------------
Modular arithmetic is the mathematical engine of public-key cryptography. Unlike standard 
infinite fields, modular arithmetic operates over finite cyclic rings (Z / N Z) where numbers 
"wrap around" a fixed modulus N:

  * MODULAR CONGRUENCE : a ≡ b (mod N)  <==>  N divides (a - b).
  * MULTIPLICATIVE INVERSE: An integer d such that:  e * d ≡ 1 (mod phi(N)).
  * COMPUTATION METHOD : Computed in logarithmic time via the Extended Euclidean Algorithm (EEA).

--------------------------------------------------------------------------------
2. BEZOUT'S IDENTITY & THE EXTENDED EUCLIDEAN ALGORITHM (EEA)
--------------------------------------------------------------------------------

  1. BEZOUT'S IDENTITY:
     - For any integers a and b, there exist integers x and y such that:
                   a * x + b * y = gcd(a, b)

  2. APPLICATION TO RSA KEY GENERATION:
     - Public exponent e is chosen such that gcd(e, phi(N)) = 1.
     - The Extended Euclidean Algorithm finds integers d and k satisfying:
                   e * d + phi(N) * k = 1
     - Taking this equation modulo phi(N):
                   e * d ≡ 1 (mod phi(N))
     - The integer d is the secret private decryption exponent!

  3. HANDLING NEGATIVE INVERSES:
     - If EEA returns a negative coefficient x < 0, the canonical positive inverse is:
                   d = x + phi(N)

4. SIDE-CHANNEL ATTACKS & HARDENING IN MODULAR ARITHMETIC
--------------------------------------------------------------------------------

  * SIMPLE POWER ANALYSIS (SPA) & TIMING ATTACKS:
    - Naive Square-and-Multiply executes multiplication ONLY when key bit is 1.
    - Oscilloscopes and timers can read private exponent d directly from CPU traces.
    - Defense: Montgomery Ladder (Executes uniform multiply & square on EVERY bit).

  * CRYPTOGRAPHIC BLINDING:
    - Multiplying ciphertext by random r^e mod N before modular exponentiation:
             C_blind = (C * r^e) mod N  ==>  M_blind = (C_blind)^d = M * r mod N
    - Unblind: M = M_blind * r^(-1) mod N.
    - Completely eliminates timing and cache side-channel correlation!

  * BELLCORE FAULT ATTACK ON RSA-CRT:
    - If hardware fault corrupts m1 mod p while m2 mod q is correct:
             gcd( S'^e - M, N ) = q  (Factors 2048-bit N in 1 millisecond!)
    - Defense: Always verify signature ((S')^e mod N == M) BEFORE transmitting to client.

7. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL MODULAR ARITHMETIC HABITS:
  1. Enforce Constant-Time Montgomery Exponentiation: Prevents SPA and timing side channels.
  2. Implement Cryptographic Blinding: Decouples physical execution time from secret message bits.
  3. Deploy RSA-CRT with Signature Verification: Delivers 4x speedup while neutralizing Bellcore faults.
  4. Always Check gcd(e, phi(N)) == 1: Ensures unique modular inverse d exists before key generation.

* COMMON BEGINNER MODULAR MATH MISTAKES:
  - Forgetting to handle negative Bezout coefficients (Returning negative private key d).
  - Using naive modular exponentiation (M^e) without Square-and-Multiply (CPU timeout).
  - Failing to verify CRT signatures before sending (Vulnerable to Bellcore single-glitch factoring).
  - Using memory array lookups during exponentiation (Vulnerable to Flush+Reload cache attacks).
