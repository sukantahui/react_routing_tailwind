1. EXECUTIVE OVERVIEW & THE 5-STEP KEYGEN LIFECYCLE
--------------------------------------------------------------------------------
RSA key generation is the foundational lifecycle procedure that transforms raw physical entropy 
into mathematically linked asymmetric public and private key pairs:

  * PUBLIC KEY  (e, N) : Freely distributed in X.509 certificates to encrypt data and verify signatures.
  * PRIVATE KEY (d, N) : Kept strictly isolated in FIPS 140-3 HSMs to decrypt data and sign documents.

--------------------------------------------------------------------------------
2. THE 5 SEQUENTIAL MATHEMATICAL KEYGEN STEPS
--------------------------------------------------------------------------------

  STEP 1 : PRIME GENERATION (p, q)
    - Generate two massive, distinct 1024-bit primes p and q using a hardware CSPRNG.
    - Validate primality using 64 rounds of the Miller-Rabin test (Error probability < 2^-128).
    - Enforce strong prime properties: |p - q| > 2^900 (Defeats Fermat difference of squares).

  STEP 2 : MODULUS MULTIPLICATION (N)
    - Compute public modulus: N = p * q (2048 bits / 617 decimal digits).
    - Modulus N is published as part of both the Public and Private keys.

  STEP 3 : TOTIENT GROUP ORDER CALCULATION (phi(N) / lambda(N))
    - Calculate Euler's Totient: phi(N) = (p - 1) * (q - 1).
    - Or Carmichael's Totient:   lambda(N) = lcm(p - 1, q - 1) (PKCS#1 v2.2 standard).

  STEP 4 : PUBLIC EXPONENT SELECTION (e)
    - Select integer e such that 1 < e < phi(N) and gcd(e, phi(N)) = 1.
    - Universal Global Standard: e = 65537 = 2^16 + 1 (Fermat prime F4).

  STEP 5 : PRIVATE EXPONENT DERIVATION (d) & CRT PRE-COMPUTATION
    - Calculate modular multiplicative inverse via Extended Euclidean Algorithm:
                    e * d ≡ 1 (mod phi(N))  ==>  d = e^(-1) mod phi(N)
    - Pre-compute Chinese Remainder Theorem (CRT) parameters for 4x faster private operations:
                    d_p = d mod (p - 1),  d_q = d mod (q - 1),  q_inv = q^(-1) mod p
    - Securely wipe primes p, q, and phi(N) from volatile RAM immediately!

4. CRITICAL KEYGEN FLAWS IN HISTORY & REMEDIATION
--------------------------------------------------------------------------------

  * ROCA VULNERABILITY (CVE-2017-15361):
    - Flaw: Infineon crypto chips generated primes with structured form p = k*M + (65537^a mod M).
    - Impact: 2048-bit RSA keys factored for $76 on AWS in 17 days using Coppersmith's attack.
    - Remedy: Enforce full-entropy standard Miller-Rabin primality testing.

  * DEBIAN OPENSSL WEAK PRNG BUG (CVE-2008-0166):
    - Flaw: Maintainer removed uninitialized entropy bytes, leaving only PID (1..32767) as seed.
    - Impact: Pre-computed dictionary of 32,768 keys allowed root login on all Debian servers.
    - Remedy: Seed PRNG exclusively from hardware TRNGs (/dev/urandom).

  * BATCH GCD COMPROMISE (Heninger et al., 2012):
    - Flaw: Embedded IoT routers generated keys during boot before entropy pool was filled.
    - Impact: Multiple routers shared a single prime factor p; gcd(N1, N2) factored 64,000+ keys!
    - Remedy: Block key generation until the operating system entropy pool is 100% full.

7. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL RSA KEYGEN HABITS:
  1. Always Use Modern OpenSSL genpkey: Generates PKCS#8 encrypted keys with PBKDF2/AES-256.
  2. Implement Secure RAM Zeroization: Erase primes p, q, and totient phi(N) immediately after keygen.
  3. Pre-Compute CRT Parameters: Include d_p, d_q, and q_inv for 4x faster private operations.
  4. Block Keygen on Low Entropy: Never generate keys until the CSPRNG entropy pool is 100% seeded.

* COMMON BEGINNER KEYGEN MISTAKES:
  - Using Math.random() or rand() to pick primes (Trivially predictable PRNG).
  - Storing private keys on unencrypted disk partitions without PKCS#8 password protection.
  - Generating keys immediately on device boot without checking system entropy (Batch GCD vulnerability).
  - Using proprietary "fast prime" generation shortcuts (Vulnerable to ROCA-style attacks).
