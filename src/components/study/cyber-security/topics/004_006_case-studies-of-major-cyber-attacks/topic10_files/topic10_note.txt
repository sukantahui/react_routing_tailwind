1. EXECUTIVE OVERVIEW: THE INCIDENT RESPONSE LIFECYCLE (NIST SP 800-61 REV 2)
----------------------------------------------------------------------------------------------------
Incident Response (IR) is the structured, systematic methodology an organization executes to prepare for, 
detect, contain, eradicate, recover from, and analyze cyber security breaches.

According to NIST Special Publication 800-61 Rev 2 and SANS, the incident response lifecycle comprises 
six continuous, interconnected phases:

  +-------------------+---------------------------------------------------------------------------+
  | PHASE             | CORE OPERATIONAL OBJECTIVES                                               |
  +-------------------+---------------------------------------------------------------------------+
  | 1. PREPARATION    | Tooling deployment (EDR, SIEM), incident playbooks, out-of-band war rooms,|
  |                   | call trees, forensic acquisition kits, tabletop training simulations.     |
  +-------------------+---------------------------------------------------------------------------+
  | 2. IDENTIFICATION | Threat detection, alert triage, scope definition, Indicator of Compromise |
  |                   | (IOC) enrichment, severity classification (P1-Critical to P4-Low).        |
  +-------------------+---------------------------------------------------------------------------+
  | 3. CONTAINMENT    | Short-Term: Host network isolation, disabling compromised accounts.       |
  |                   | Long-Term: Sandboxing, forensic disk/RAM capture, C2 traffic redirection. |
  +-------------------+---------------------------------------------------------------------------+
  | 4. ERADICATION    | Purging malware binaries, terminating rootkits, deleting JSP web shells,  |
  |                   | revoking forged Kerberos/SAML tokens, rotating KRBTGT passwords twice.    |
  +-------------------+---------------------------------------------------------------------------+
  | 5. RECOVERY       | Phased restoration from clean offline backups in isolated staging VLANs,  |
  |                   | applying patches, rotating credentials, 24/7 heightened SOC surveillance. |
  +-------------------+---------------------------------------------------------------------------+
  | 6. LESSONS LEARNED| 5 Whys Root Cause Analysis, Fishbone diagrams, blameless post-mortem,     |
  |                   | updating defensive controls, Jira tracking for architectural remediation. |
  +-------------------+---------------------------------------------------------------------------+


2. DIGITAL FORENSICS & SUPER-TIMELINE RECONSTRUCTION
----------------------------------------------------------------------------------------------------
During forensic investigation, analysts reconstruct the adversary's actions with millisecond accuracy:

  A. FORENSIC SUPER-TIMELINES (PLASO / LOG2TIMELINE):
     - Aggregates file system MACB timestamps ($MFT), Windows Event Logs, web access logs, browser history, 
       prefetch execution artifacts, and network NetFlows into a unified chronological stream.

  B. MACB TIMESTAMPS & TIMESTOMPING DETECTION:
     - Modified (M), Accessed (A), Changed ($MFT record - C), Born / Creation (B).
     - Timestomping Detection: Malware authors modify `$STANDARD_INFORMATION` attributes to forge old dates. 
       Forensic analysts compare this against kernel-protected `$FILE_NAME` timestamps in the NTFS $MFT 
       to expose forged creation dates.

  C. VOLATILE MEMORY FORENSICS (RFC 3227):
     - Order of Volatility: Capture volatile CPU registers and RAM before pulling power cables.
     - Tools: WinPmem / LiME for acquisition; Volatility 3 (`windows.netscan`, `windows.malfind`) to locate 
       injected shellcode, unmapped DLLs, and decrypted cryptographic keys in memory.


3. ROOT CAUSE ANALYSIS (RCA) & BLAMELESS POST-MORTEM
----------------------------------------------------------------------------------------------------
A. THE "5 WHYS" METHODOLOGY:
   - Iteratively drilling down past superficial symptoms to uncover foundational governance and architectural failures.
   - Example: 1. Server breached -> 2. Unpatched Struts -> 3. Notice not received -> 4. No centralized SBOM -> 5. ROOT CAUSE: Lack of executive DevSecOps governance and funding.

B. ISHIKAWA (FISHBONE) DIAGRAM MAPPING:
   - Categorizes causes across: People (training, sharing), Process (patch SLAs, change control), Technology 
     (expired SSL certs, flat VLANs), and Management (understaffed SOC, lack of CISO Board visibility).

C. BLAMELESS POST-MORTEM CULTURE:
   - Assumes employees acted in good faith with available information.
   - Eliminates blame and fear, encouraging rapid incident reporting while focusing on engineering guardrails.

6. STRATEGIC TAKEAWAYS FOR CSIRT LEADERSHIP
----------------------------------------------------------------------------------------------------
1. SPEED IS SURVIVAL:
   Compress Mean Time to Detect (MTTD) to < 1 hour and Mean Time to Contain (MTTR) to < 2 hours.

2. NEVER POWER OFF BEFORE RAM CAPTURE:
   Volatile memory holds encryption keys and in-memory shellcode that disappears upon reboot.

3. POST-MORTEM MUST DRIVE PERMANENT ARCHITECTURAL CHANGE:
   Convert post-mortem action items into tracked engineering deliverables with strict SLAs.
