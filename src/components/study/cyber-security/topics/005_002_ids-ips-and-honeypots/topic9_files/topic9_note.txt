1. DEFINITION & THE LEVEL OF INTERACTION TAXONOMY
----------------------------------------------------------------------------------------------------
Honeypots are classified according to the depth of interaction and operational freedom granted to the adversary. 
The level of interaction dictates the fidelity of threat intelligence gathered, the complexity of deployment, 
and the operational security risk of attacker pivoting.


2. THE 3 TIERS OF HONEYPOT INTERACTION
----------------------------------------------------------------------------------------------------
1. LOW-INTERACTION HONEYPOTS (LIH):
   - Definition: Software emulators that simulate specific network services and fixed protocol banners. 
     There is NO real underlying operating system, kernel, or real execution environment.
   - Prominent Tools:
     - Cowrie: Emulates SSH & Telnet services with a fake virtual file system.
     - Dionaea: Emulates SMB, MSSQL, FTP, HTTP to capture automated malware payloads and worms.
     - Conpot: Emulates industrial control systems (ICS/SCADA) Modbus, DNP3, and S7comm protocols.
     - Honeyd: Simulates entire network topologies with synthetic TCP/IP stack personality fingerprints.
   - Strengths: Extremely low CPU/RAM footprint (1 server can host 5,000 decoys); 0% risk of host compromise.
   - Limitations: Easily fingerprinted by experienced human hackers; cannot capture novel zero-day kernel exploits.

2. MEDIUM-INTERACTION HONEYPOTS (MIH):
   - Definition: Emulates complex application-level logic (e.g. web forms, databases) without real backend execution.
   - Prominent Tools:
     - Glastopf / Snare & Tanner: Emulates vulnerable web applications, capturing SQL injection and local file inclusion (LFI).
   - Strengths: Higher realism for automated web scrapers and scanner bots; safe containment.

3. HIGH-INTERACTION HONEYPOTS (HIH):
   - Definition: Real, fully functional, un-emulated operating systems (Windows Server, Linux) running real applications. 
     Attackers gain genuine administrator or root shell access.
   - Prominent Tools: Real KVM / VMware virtual machines instrumented with eBPF, Sysmon, and Honeynet Honeywalls.
   - Strengths: Maximum forensic realism; impossible to fingerprint; captures novel zero-day kernel rootkits and live human TTPs.
   - Limitations: Highest operational risk. Mandates strict egress data containment and automated VM snapshot rollback.

4. KERNEL TELEMETRY & DATA CONTROL FOR HIGH-INTERACTION HONEYPOTS
----------------------------------------------------------------------------------------------------
To safely run High-Interaction Honeypots without attacker evasion or lateral pivoting:
  1. Out-of-Band Kernel Tracing: Deploy eBPF (Extended Berkeley Packet Filter) or hypervisor introspection 
     to capture keystrokes, process execution (`execve`), and memory injections without installing observable in-guest agents.
  2. Data Control (Honeywall Egress Containment):
     - Rate-limiting outbound connections to a strict maximum (e.g., 5 packets/second).
     - Dropping all outbound packets destined for internal RFC 1918 private subnets.
     - Dynamic connection termination if the honeypot attempts to initiate an external port scan.
  3. Ephemeral Virtual Disks: Revert the VM to a clean base snapshot every 24 hours or immediately following 
     confirmed rootkit extraction.
