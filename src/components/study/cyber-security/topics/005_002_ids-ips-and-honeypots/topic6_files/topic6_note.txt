1. THE 2x2 CONFUSION MATRIX IN CYBERSECURITY MONITORING
----------------------------------------------------------------------------------------------------
Every alert generated by an Intrusion Detection System (IDS) or Intrusion Prevention System (IPS) maps 
into a 2x2 binary classification confusion matrix:

+-----------------------------+------------------------------------+------------------------------------+
|                             | ACTUAL GROUND TRUTH: REAL ATTACK   | ACTUAL GROUND TRUTH: BENIGN TRAFFIC|
+-----------------------------+------------------------------------+------------------------------------+
| SENSOR DECISION: ALERT/DROP | TRUE POSITIVE (TP) [SUCCESS]       | FALSE POSITIVE (FP) [TYPE I ERROR] |
|                             | Exploit caught; SOC notified.      | False alarm; causes alert fatigue. |
+-----------------------------+------------------------------------+------------------------------------+
| SENSOR DECISION: PASS/IGNORE| FALSE NEGATIVE (FN) [CATASTROPHIC] | TRUE NEGATIVE (TN) [NORMAL]        |
|                             | Undetected breach; data stolen!    | Normal traffic flows cleanly.      |
+-----------------------------+------------------------------------+------------------------------------+


2. MATHEMATICAL METRICS FOR IDS EVALUATION
----------------------------------------------------------------------------------------------------
1. PRECISION (Positive Predictive Value - PPV):
   - Proportion of generated alerts that represent genuine attacks:
     $$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}$$
   - High precision means analysts can trust alerts without wasting hours on false alarms.

2. RECALL / SENSITIVITY (True Positive Rate - TPR):
   - Proportion of total actual attacks that the sensor successfully caught:
     $$\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}}$$
   - High recall ensures zero attacks slip through undetected.

3. F1-SCORE (Harmonic Mean):
   - Balances precision and recall into a single unified performance score:
     $$\text{F1} = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$$

4. FALSE POSITIVE RATE (FPR):
   - Proportion of clean traffic incorrectly flagged: $\text{FPR} = \frac{\text{FP}}{\text{FP} + \text{TN}}$.


3. THE BASE RATE FALLACY IN INTRUSION DETECTION (BAYES' THEOREM)
----------------------------------------------------------------------------------------------------
Why does a sensor with "99% Accuracy" still flood the SOC with 90%+ false alarms?

Mathematical Proof using Bayes' Theorem:
  - Total Daily Events = $1,000,000$ packets
  - Attack Base Rate = $0.01\%$ ($100$ real attacks) | Clean Traffic = $99.99\%$ ($999,900$ clean packets)
  - Sensor Accuracy = $99\%$ True Positive Rate ($\text{TP} = 99$), $1\%$ False Positive Rate ($\text{FPR} = 0.01$)
  - False Positives Generated = $999,900 \times 0.01 = 9,999\text{ False Alarms}$
  - Probability that an alert is a real attack:
    $$P(\text{Attack} \mid \text{Alert}) = \frac{\text{TP}}{\text{TP} + \text{FP}} = \frac{99}{99 + 9,999} = \frac{99}{10,098} \approx 0.98\%$$
  - Real-World Consequence: Over $99\%$ of generated alerts are false alarms! Even a $1\%$ error rate on 
    massive traffic streams overwhelms SOC operations.


4. OPERATIONAL STRATEGIES FOR FALSE POSITIVE REDUCTION
----------------------------------------------------------------------------------------------------
1. RULE TUNING & REGEX REFINEMENT:
   - Eliminate greedy regex wildcards (`.*`). Enforce strict token boundaries (e.g., match exact SQL grammar).
2. THRESHOLDING & EVENT SUPPRESSION:
   - Configure Snort `event_filter` to alert only once per source IP per 60-second window during floods.
3. AUTHORIZED SCANNER WHITELISTING:
   - Suppress alerts triggered by scheduled internal vulnerability scanners (Nessus / Qualys IPs).
4. CONTEXTUAL THREAT INTELLIGENCE:
   - Correlate anomaly alerts with external reputation feeds (AbuseIPDB, AlienVault OTX) before alerting SOC.
