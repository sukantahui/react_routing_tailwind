1. DEFINITION & THE GENESIS OF INTRUSION DETECTION
----------------------------------------------------------------------------------------------------
An Intrusion Detection System (IDS) is a hardware appliance or software application that passively monitors 
network traffic or system host events for malicious activity, policy violations, or unauthorized access, 
producing alerts for a centralized Security Operations Center (SOC) or SIEM repository.

Historical Foundations:
  - James P. Anderson (1980): Published "Computer Security Threat Monitoring and Surveillance", introducing 
    the concept that user behavior deviates from normal baselines during an attack and classifying threats 
    into External Penetrations, Internal Misuse, and Clandestine Users.
  - Dr. Dorothy Denning (1987): Published the seminal paper "An Intrusion-Detection Model", establishing 
    the mathematical foundation for state transition engines, statistical profiles, and rule-based anomaly 
    detection still used by modern IDS platforms.


2. THE 3 FOUNDATIONAL SUBSYSTEMS OF AN IDS
----------------------------------------------------------------------------------------------------
  1. SENSORS / PROBES (Data Capture Subsystem):
     - Placed at strategic network tap points (SPAN ports, optical splitters) or installed as host agents.
     - Operates network interfaces in Promiscuous Mode using raw packet capture drivers (libpcap, AF_PACKET, 
       DPDK, PF_RING) to ingest all frames traversing the wire regardless of destination MAC address.

  2. ANALYSIS ENGINE (Detection & Processing Engine):
     - The "brain" of the IDS. Compares incoming packet headers and payload byte streams against known attack 
       signatures (Signature-based) or baseline behavioral models (Anomaly-based).

  3. ALERTING & MANAGEMENT CONSOLE (Reporting Subsystem):
     - Formats detected indicators of compromise (IoCs) into structured alerts (IDMEF RFC 4765, CEF, JSON), 
       pushing telemetry over TLS to SIEM platforms and triggering SOC analyst workflows.


3. THE CLASSIC ANALOGY: FIREWALL VS INTRUSION DETECTION SYSTEM
----------------------------------------------------------------------------------------------------
+--------------------+------------------------------------+-----------------------------------------+
| CHARACTERISTIC     | FIREWALL (THE SECURITY GATE / DOOR)| INTRUSION DETECTION SYSTEM (THE ALARM)  |
+--------------------+------------------------------------+-----------------------------------------+
| Primary Analogy    | Locked Door / Security Guard       | CCTV Camera / Burglar Alarm / Motion Sens|
| Operational Action | Active (Permits or Drops packets)  | Passive (Monitors and Alerts on threats)|
| Network Placement  | In-line (All traffic must cross it)| Out-of-Band (Receives mirrored traffic) |
| Latency Overhead   | Introduces microsecond delay       | Zero packet forwarding delay on wire    |
| Failure Impact     | Fail-Closed halts network traffic  | Appliance failure leaves traffic intact |
| Inspection Focus   | Layer 3/4 5-Tuples & App-ID        | Deep Payload Byte Matching & Heuristics |
+--------------------+------------------------------------+-----------------------------------------+


4. PROMISCUOUS MODE & PACKET CAPTURE MECHANICS
----------------------------------------------------------------------------------------------------
In standard network interface operation, the Network Interface Card (NIC) hardware filter discards any 
Ethernet frame whose Destination MAC address does not match the local host MAC or the broadcast address.

In Promiscuous Mode:
  - The NIC hardware filter is disabled.
  - The NIC passes 100% of all frames traversing the physical Ethernet segment directly to the operating 
    system kernel network stack (via libpcap/AF_PACKET), allowing the IDS to inspect all conversations 
    occurring across the broadcast domain or mirrored SPAN port.
