1. MATHEMATICAL FOUNDATIONS OF LATTICE-BASED CRYPTOGRAPHY
----------------------------------------------------------------------------------------------------
A lattice $\Lambda \subset \mathbb{R}^n$ is a discrete periodic grid of points formed by integer linear 
combinations of basis vectors $\mathbf{b}_1, \dots, \mathbf{b}_n$:
$$\Lambda = \left\{ \sum_{i=1}^{n} z_i \mathbf{b}_i \;\middle|\; z_i \in \mathbb{Z} \right\}$$

1. Core NP-Hard Computational Problems in High Dimensions ($n \ge 512$):
   - Shortest Vector Problem (SVP): Find the non-zero lattice vector $\mathbf{v} \in \Lambda$ with minimal Euclidean norm $\|\mathbf{v}\|$.
   - Closest Vector Problem (CVP): Given an arbitrary point $\mathbf{t} \in \mathbb{R}^n$, find the lattice point closest to $\mathbf{t}$.
   - Shortest Independent Vectors Problem (SIVP).

2. Learning With Errors (LWE - Oded Regev 2005):
   - Given public random matrix $\mathbf{A} \in \mathbb{Z}_q^{m \times n}$ and noisy vector $\mathbf{b} = \mathbf{A}\mathbf{s} + \mathbf{e} \pmod q$, 
     it is computationally impossible (both classically and quantumly) to recover secret vector $\mathbf{s}$.
   - Module-LWE (M-LWE) & Ring-LWE (R-LWE): Uses polynomial quotient rings $\mathbb{Z}_q[X]/(X^n + 1)$ to compress key sizes and accelerate 
     multiplication via the Number Theoretic Transform (NTT).


2. HASH-BASED CRYPTOGRAPHY: LAMPORT OTS & SPHINCS+ (SLH-DSA)
----------------------------------------------------------------------------------------------------
Hash-based cryptography relies solely on the collision resistance and preimage resistance of secure cryptographic 
hash functions (SHA-256 / SHAKE-256), requiring NO unproven algebraic mathematical assumptions:

1. Lamport One-Time Signature (OTS):
   - Private key: 256 pairs of random 256-bit strings $(sk_{0,i}, sk_{1,i})$.
   - Public key: Hashes of all 512 strings $(H(sk_{0,i}), H(sk_{1,i}))$.
   - Signing: Reveal $sk_{0,i}$ if $m_i = 0$, or $sk_{1,i}$ if $m_i = 1$.
   - Critical Rule: A Lamport private key can be used EXACTLY ONCE; signing a second message leaks the remaining private strings!

2. Merkle Signature Scheme (MSS) & XMSS (RFC 8391):
   - Combines $2^H$ Lamport OTS keys into the leaves of a binary Merkle Tree.
   - The root of the tree is a compact 32-byte public key capable of signing $2^H$ messages.
   - Limitation: Stateful (must track signature index counter to prevent key reuse).

3. SPHINCS+ / SLH-DSA (NIST FIPS 205):
   - Stateless Hash-based Signature: Uses a hyper-tree of Few-Time Signatures (FORS - Forest of Random Subsets), eliminating state tracking.
