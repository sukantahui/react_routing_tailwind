1. DEFINITION & THE CORE VPN CONCEPT
----------------------------------------------------------------------------------------------------
A Virtual Private Network (VPN) is a cryptographic technology that creates a secure, encrypted logical 
communication channel ("tunnel") over an insecure, untrusted physical public network (such as the Internet). 

Key Terms:
- Virtual: No dedicated physical leased fiber line is used; the private link is created logically over public routing.
- Private: All data crossing the tunnel is encrypted and authenticated, ensuring only authorized endpoints can read it.
- Network: Connects individual endpoints (Remote Access) or entire enterprise LAN subnets (Site-to-Site).


2. THE 3 FOUNDATIONAL CRYPTOGRAPHIC PILLARS OF A VPN
----------------------------------------------------------------------------------------------------
1. CONFIDENTIALITY:
   - Data payloads are encrypted using symmetric ciphers (AES-256-GCM, ChaCha20-Poly1305). Eavesdroppers on public 
     Wi-Fi or ISPs see only unintelligible ciphertext.
2. INTEGRITY:
   - Cryptographic hashes (HMAC-SHA-256) and authenticated encryption (AEAD) ensure that in-transit data cannot be 
     tampered with or modified by Man-in-the-Middle (MitM) adversaries.
3. AUTHENTICATION & NON-REPUDIATION:
   - Both VPN endpoints verify identities prior to tunnel establishment using X.509 Digital Certificates (PKI), 
     Pre-Shared Keys (PSK), or Multi-Factor Authentication (MFA).


3. HOW VPN TUNNELING WORKS: ENCAPSULATION & PACKET ANATOMY
----------------------------------------------------------------------------------------------------
Tunneling wraps an original private network packet inside a new public transport packet:
  [ New Public IP Header (Routable) ] + [ VPN Security Header (ESP/TLS) ] + [ Encrypted Original IP Packet ]

Steps:
  1. The client creates a private IP packet (e.g. Src: 10.10.1.5, Dst: 10.20.1.50).
  2. The VPN client encrypts the entire original IP packet.
  3. A new public IP header is appended (Src: Client Public IP, Dst: Corporate VPN Gateway IP).
  4. The packet traverses the public internet as generic UDP/TCP traffic.
  5. The VPN gateway receives the packet, strips the public header, decrypts the payload, and forwards the 
     original packet to the internal corporate LAN.


4. VPN TAXONOMY: REMOTE ACCESS VS SITE-TO-SITE
----------------------------------------------------------------------------------------------------
+----------------------+------------------------------------+------------------------------------+
| FEATURE              | REMOTE ACCESS VPN                  | SITE-TO-SITE (ROUTER-TO-ROUTER)    |
+----------------------+------------------------------------+------------------------------------+
| Endpoints            | Individual User Laptop to Gateway  | Branch Office Router to HQ Router  |
| Software Needed      | VPN Client Software (AnyConnect)   | Built into Network Gateway Routers |
| Use Case             | Remote Workers, Traveling Execs    | Connecting Barrackpore to Kolkata HQ|
| Protocol Example     | SSL/TLS (OpenVPN), IKEv2, WireGuard| IPsec Tunnel Mode                  |
| User Action          | User logs in with MFA credentials  | Always-on automatic hardware link  |
+----------------------+------------------------------------+------------------------------------+

    Abhronila (WireGuard Architect), Susmita (Compliance & CERT-In Auditor), Debangshu (Cryptographic Engineer).

Scenario:
The Barrackpore municipal e-governance staff required secure access to the central Salt Lake Sector V datacenter:
- Deployment Architecture:
  - Mamata and Debangshu deployed an AES-256-GCM encrypted VPN gateway at the Salt Lake core datacenter.
  - Mahima configured endpoint client profiles enforcing MFA and continuous device health checks.
  - Susmita ensured that all VPN session logs and authentication timestamps were archived for 180 days in compliance with CERT-In directives.
- Threat Neutralization:
  - An attacker on an untrusted public Wi-Fi hotspot in Barrackpore attempted an ARP spoofing and packet sniffing attack against a municipal employee's laptop.
  - Because all traffic was encapsulated inside an authenticated WireGuard tunnel, the attacker captured only encrypted ciphertext; zero credentials or citizen records were exposed.
  - Outcome: 100% data confidentiality achieved; verified compliance with CERT-In and the DPDP Act 2023.


6. STUDENT MINI CHECKLIST (EXAM & CAREER ESSENTIALS)
----------------------------------------------------------------------------------------------------
[ ] A VPN provides Confidentiality, Integrity, and Authentication over untrusted public networks.
[ ] Encapsulation wraps private IP packets inside routable public IP headers.
[ ] Remote Access VPN connects individual users to a gateway; Site-to-Site VPN connects entire branch subnets.
[ ] Modern VPN ciphers include AES-256-GCM, AES-256-CBC with HMAC-SHA-256, and ChaCha20-Poly1305.
[ ] VPNs introduce packet overhead (20 to 80 bytes per packet), requiring MSS/MTU clamping to prevent fragmentation.
[ ] CERT-In mandates 180-day retention of all VPN authentication logs, connection timestamps, and assigned IPs.
