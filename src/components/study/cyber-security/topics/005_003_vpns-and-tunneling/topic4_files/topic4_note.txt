1. THE THREE-TIER TUNNELING MODEL (PASSENGER, ENCAPSULATING & CARRIER)
----------------------------------------------------------------------------------------------------
Tunneling allows a network protocol to be transported across an incompatible or untrusted intermediate network 
by wrapping it in specialized cryptographic layers.
The architecture comprises three distinct protocol roles:
  1. Passenger Protocol: The original data payload and private network header being transported 
     (e.g., Private IPv4 `10.10.1.5`, IPv6, or raw Layer-2 Ethernet MAC frames).
  2. Encapsulating / Tunneling Protocol: The cryptographic security envelope that wraps and encrypts the passenger 
     (e.g., IPsec ESP, WireGuard Noise, OpenVPN TLS, GRE).
  3. Carrier / Transport Protocol: The routable public network protocol used to deliver the packet across the 
     public Internet (e.g., Public IPv4/IPv6 carrying UDP Port 4500, UDP Port 51820, or TCP Port 443).


2. CARRIER PROTOCOL DYNAMICS: WHY UDP IS MANDATORY & TCP MELTDOWN
----------------------------------------------------------------------------------------------------
- The UDP Advantage:
  - Tunneling protocols (IPsec, WireGuard, OpenVPN UDP) utilize UDP as their outer carrier because UDP provides 
    connectionless, low-overhead transport without its own retransmission timers.
  - This allows the inner passenger application's TCP stack to manage end-to-end flow control cleanly.
- The "TCP-over-TCP Meltdown" Disaster:
  - If a VPN uses TCP as its outer carrier protocol (e.g., OpenVPN over TCP port 443 across public Wi-Fi), a 
    single dropped packet triggers retransmissions in BOTH the inner application TCP stack AND the outer VPN TCP stack.
  - Both timers back off exponentially, creating bufferbloat, severe latency spikes (from 20ms to 10,000ms), and 
    eventual tunnel collapse.


3. PACKET OVERHEAD, MTU & TCP MSS CLAMPING
----------------------------------------------------------------------------------------------------
- The Maximum Transmission Unit (MTU) of standard Ethernet is 1500 bytes.
- When VPN encapsulation adds 50 to 80 bytes of extra headers (Outer IP, UDP, ESP Header, IV, Auth Tag), 
  a 1500-byte passenger packet expands to 1580 bytes, exceeding the link MTU.
- If the `Don't Fragment` (DF) bit is set, intermediate routers drop the packet silently ("PMTU Blackhole").
- The Solution: TCP MSS Clamping:
  - Edge routers rewrite the Maximum Segment Size (MSS) option in TCP SYN packets:
    $$\text{MSS} = \text{MTU (1500)} - \text{IP/TCP Headers (40B)} - \text{VPN Overhead (80B)} = 1380\text{ Bytes}$$
  - This forces endpoints to construct smaller segments, eliminating packet fragmentation completely.
