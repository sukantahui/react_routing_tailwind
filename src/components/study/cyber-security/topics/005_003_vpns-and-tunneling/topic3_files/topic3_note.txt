1. THE CRYPTOGRAPHIC TRIAD IN VPN TUNNELING
----------------------------------------------------------------------------------------------------
A Virtual Private Network is defined by its ability to deliver three mandatory security guarantees 
over untrusted public infrastructure:
  1. Confidentiality (Data Privacy via Symmetric Encryption)
  2. Data Integrity (Anti-Tampering via Cryptographic Hashes / AEAD)
  3. Peer & User Authentication (Identity Verification via PKI / MFA)
Plus two crucial operational security extensions:
  4. Anti-Replay Protection (Monotonic Sequence Sliding Windows)
  5. Perfect Forward Secrecy - PFS (Ephemeral Key Exchange)


2. CONFIDENTIALITY: SYMMETRIC CIPHER ARCHITECTURE
----------------------------------------------------------------------------------------------------
- Principle: Both VPN endpoints share a temporary symmetric encryption key negotiated during the handshake.
- Ciphers Compared:
  1. AES-256-GCM (Galois/Counter Mode): Modern gold standard. An Authenticated Encryption with Associated 
     Data (AEAD) cipher providing confidentiality and integrity in a single hardware-accelerated pass.
  2. AES-256-CBC: Legacy block cipher requiring explicit initialization vectors (IVs) and separate HMAC 
     integrity hashing; susceptible to padding-oracle exploits if misconfigured.
  3. ChaCha20-Poly1305: High-speed stream cipher used in WireGuard; delivers ultra-fast software encryption 
     on mobile and embedded CPUs lacking hardware AES-NI instructions.


3. DATA INTEGRITY & ANTI-TAMPERING
----------------------------------------------------------------------------------------------------
- Principle: Verifies that not a single bit of the packet has been modified, corrupted, or injected by an adversary.
- Mechanisms:
  1. Keyed-Hash Message Authentication Code (HMAC-SHA-256 / HMAC-SHA-384): Computes a cryptographic hash 
     over the ciphertext using the shared secret key.
  2. Authenticated Encryption (AEAD Auth Tag): In GCM mode, the GMAC hardware unit generates a 128-bit 
     authentication tag simultaneously with encryption.


4. AUTHENTICATION & PERFECT FORWARD SECRECY (PFS)
----------------------------------------------------------------------------------------------------
- Authentication Methods:
  1. Pre-Shared Key (PSK): Static passphrase; simple but unmanageable at enterprise scale.
  2. X.509 PKI Certificates (RSA-3072 / ECDSA P-384 / Ed25519): Industry standard for mutual device authentication.
  3. Multi-Factor Authentication (EAP-TLS / SAML 2.0): Enforces biometric or FIDO2 hardware verification for users.
- Perfect Forward Secrecy (PFS):
  - Uses Ephemeral Diffie-Hellman (ECDHE / Curve25519) to generate independent, temporary session keys for 
    every connection. If the server's long-term master private key is compromised in the future, past recorded 
    VPN sessions CANNOT be retroactively decrypted.

Scenario:
The Barrackpore drinking water treatment grid SCADA system transmitting critical valve automation packets to Salt Lake HQ:
- Implementation:
  - Mamata and Debangshu enforced AES-256-GCM encryption with 256-bit keys and Curve25519 ECDHE Perfect Forward Secrecy.
  - Mahima enabled hardware AES-NI acceleration and configured an anti-replay sliding window of 1024 packets.
- Tactical Defense:
  - An adversary intercepted SCADA flow packets and attempted a packet injection and replay attack to trigger unauthorized valve shutdowns.
  - The IPsec gateway's GCM authentication tag verification failed on the injected packets, and duplicate sequence numbers were instantly discarded.
  - Outcome: 100% water grid uptime; zero unauthorized commands executed; verified compliance with CERT-In 180-day logging mandates.
