1. EXECUTIVE OVERVIEW & PURPOSE OF CLASSIFICATION
--------------------------------------------------------------------------------
Information Classification is the foundational process of categorizing enterprise data into defined 
sensitivity tiers based on the business, financial, and legal impact of unauthorized disclosure or loss:

  * THE REALITY   : Treating all data identically is financially and operationally impossible. 
                    Applying FIPS HSM encryption to public marketing brochures wastes budget; 
                    leaving customer Aadhaar/PAN records unencrypted causes ₹250 Crore DPDP penalties.
  * THE PARADIGM  : Establishing clear handling, encryption, access, and disposal baselines for each tier.

--------------------------------------------------------------------------------

3. GOVERNMENT & MILITARY CLASSIFICATION (OFFICIAL SECRETS ACT 1923)
--------------------------------------------------------------------------------

  * TOP SECRET   : Unauthorized disclosure causes EXCEPTIONALLY GRAVE DAMAGE to national defense.
  * SECRET       : Causes SERIOUS DAMAGE to national security and critical infrastructure.
  * CONFIDENTIAL : Causes PREJUDICE to state interests, diplomatic cables, or law enforcement.
  * UNCLASSIFIED : Standard public governmental gazettes and administrative records.

--------------------------------------------------------------------------------
4. MULTI-LEVEL SECURITY: THE BELL-LAPADULA (BLP) MODEL
--------------------------------------------------------------------------------

  * SIMPLE SECURITY PROPERTY ("NO READ UP"):
    A user with 'Confidential' clearance can read 'Public' and 'Confidential' data, but is 
    strictly blocked from reading 'Restricted' data.

  * * (STAR) PROPERTY ("NO WRITE DOWN"):
    A user with 'Restricted' clearance cannot write or copy data into a 'Public' or 'Internal' 
    document, mathematically preventing unauthorized data leakage or accidental de-classification.

--------------------------------------------------------------------------------
5. DATA LOSS PREVENTION (DLP) ENFORCEMENT
--------------------------------------------------------------------------------

  * ENDPOINT DLP : Blocks copying 'RESTRICTED' files to USB drives, clipboard, or local printers.
  * NETWORK DLP  : Inspects outbound SMTP emails and web traffic; blocks unencrypted Aadhaar/PAN regex.
  * CLOUD DLP    : Scans AWS S3 buckets and databases; alerts on unclassified data containing PII.

--------------------------------------------------------------------------------
6. DATA SANITIZATION STANDARDS PER TIER (NIST SP 800-88)
--------------------------------------------------------------------------------

  * CLEAR   : Logical overwrite of storage sectors (Used for Internal / Confidential tiers).
  * PURGE   : Low-level ATA Secure Erase or Crypto-Erase (Used for Confidential / Restricted tiers).
  * DESTROY : Physical shredding to particles < 2mm or incineration (Mandatory for Restricted drives).
  * CRYPTO-SHREDDING : Destroying KMS Data Encryption Keys (DEKs) to sanitize cloud storage instantly.

--------------------------------------------------------------------------------
7. INDIAN STATUTORY & REGULATORY LANDSCAPE
--------------------------------------------------------------------------------

  * DIGITAL PERSONAL DATA PROTECTION (DPDP) ACT 2023:
    - All customer personal data must be classified as RESTRICTED.
    - Section 33 imposes fines up to ₹250 CRORES for failure to protect personal data assets.

  * INFORMATION TECHNOLOGY ACT 2000 (SPDI RULES 2011):
    - Rule 3 defines 6 categories of Sensitive Personal Data (Passwords, Financial, Medical, Biometric).
    - Section 43A makes organizations liable for damages if SPDI is not protected with ISO 27001 controls.

9. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL CLASSIFICATION HABITS:
  1. Automate DLP Metadata Tagging: Never rely solely on manual human classification marking.
  2. Implement Column-Level Data Masking: Mask sensitive PAN/Aadhaar numbers in database queries.
  3. Enforce Bell-LaPadula * Property: Block users from copying Restricted data into Public documents.
  4. Schedule Periodic Re-Classification: De-classify embargoed financial reports post-SEBI filing.

* COMMON BEGINNER CLASSIFICATION PITFALLS:
  - Over-Classification (Marking public flyers as Restricted, wasting budget and causing friction).
  - Under-Classification (Leaving customer PII as Internal, risking ₹250 Cr DPDP fines).
  - Failing to update metadata tags when documents are modified or combined.
  - Deleting cloud storage files without destroying encryption keys (Leaves data recoverable).
