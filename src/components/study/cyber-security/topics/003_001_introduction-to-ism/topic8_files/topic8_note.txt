1. EXECUTIVE OVERVIEW & LIFECYCLE SECURITY PARADIGM
--------------------------------------------------------------------------------
Information security is not a single static barrier; enterprise data continuously evolves across 
states and locations. Data Lifecycle Security Management applies tailored cryptographic and policy 
controls across all 6 stages of data existence:

  * THE REALITY   : Protecting a database at rest is useless if data is intercepted in transit across 
                    unencrypted APIs or recovered from discarded cloud disks post-decommissioning.
  * THE PARADIGM  : Maintaining an unbroken security chain from Creation to NIST SP 800-88 Destruction.

--------------------------------------------------------------------------------
2. THE THREE FUNDAMENTAL STATES OF DATA
--------------------------------------------------------------------------------

+--------------------+-------------------------+------------------------------------------------+
| DATA STATE         | DEFINITION & LOCATION   | MANDATORY SECURITY CONTROLS                    |
+--------------------+-------------------------+------------------------------------------------+
| 1. DATA AT REST    | Stored on SSDs, SANs,   | AES-256-GCM Full Disk Encryption, FIPS 140-3   |
|                    | S3 buckets, or databases| HSM Master Keys, Column-Level Data Masking     |
|                    |                         |                                                |
| 2. DATA IN MOTION  | Traversing public net-  | Mutual TLS (TLS 1.3), IPsec, Certificate       |
| (IN TRANSIT)       | works or internal subnets| Pinning, API Tokenization, Network DLP Filters |
|                    |                         |                                                |
| 3. DATA IN USE     | Active in CPU registers | Confidential Computing (Intel SGX / AMD SEV),  |
| (IN PROCESSING)    | and RAM during compute  | Hardware Memory Enclaves, Process Isolation    |
+--------------------+-------------------------+------------------------------------------------+

3. THE 6 UNIVERSAL DATA LIFECYCLE STAGES
--------------------------------------------------------------------------------

  [ 1. CREATE ]  ➔ Data Minimization & Classification Tagging (DPDP Act Section 8)
        |
  [ 2. STORE ]   ➔ AES-256-GCM Encryption at Rest + Multi-AZ Replication
        |
  [ 3. USE ]     ➔ Role-Based Access Control (RBAC) + Confidential Enclave Memory Protection
        |
  [ 4. SHARE ]   ➔ Mutual TLS (mTLS 1.3) + Data Loss Prevention (DLP) Boundary Inspection
        |
  [ 5. ARCHIVE ] ➔ Encrypted WORM (Write-Once-Read-Many) Storage (5-Year Statutory Retention)
        |
  [ 6. DESTROY ] ➔ NIST SP 800-88 Sanitization (Clear, Purge, Destroy, Crypto-Shredding)

--------------------------------------------------------------------------------
4. DATA SANITIZATION STANDARDS (NIST SP 800-88 REV 1)
--------------------------------------------------------------------------------

  * 1. CLEAR   : Logical overwrite of addressable sectors using standard read/write commands 
                 (e.g. single pass 0x00). Protects against simple logical recovery.
  * 2. PURGE   : Low-level ATA Secure Erase or NVMe Cryptographic Format. Protects against 
                 laboratory forensic reconstruction.
  * 3. DESTROY : Physical shredding of SSDs to particles < 2mm, degaussing, or incineration.
  * 4. CRYPTO-SHREDDING : Destroying the KMS Data Encryption Key (DEK) to instantly render cloud 
                 ciphertext mathematically unrecoverable ($2^{256}$ barrier).

--------------------------------------------------------------------------------
5. WRITE-ONCE-READ-MANY (WORM) ARCHIVAL STORAGE
--------------------------------------------------------------------------------

  * PURPOSE        : Guarantees that archived financial records and audit logs CANNOT be modified, 
                     overwritten, or deleted by anyone—not even root administrators or ransomware.
  * IMPLEMENTATION : AWS S3 Object Lock in Compliance Mode / Hardware WORM SAN Storage.
  * COMPLIANCE     : RBI Master Direction (5-7 years retention), CERT-In (180 days log retention).

--------------------------------------------------------------------------------
6. DIGITAL EVIDENCE & CHAIN OF CUSTODY (SECTION 65B)
--------------------------------------------------------------------------------

Under Section 65B of the Indian Evidence Act / Bharatiya Sakshya Adhiniyam:
  - Cryptographic SHA-256 hashes must be generated at the moment of record creation.
  - Logs must be stored in immutable WORM storage to preserve unbroken chain of custody.
  - Accompanied by a signed Section 65B Certificate proving computer operating integrity.

--------------------------------------------------------------------------------
7. INDIAN STATUTORY & REGULATORY LANDSCAPE
--------------------------------------------------------------------------------

  * DIGITAL PERSONAL DATA PROTECTION (DPDP) ACT 2023:
    - Section 6   : Consent lifecycle governance and automated withdrawal handling.
    - Section 8(7): Mandatory erasure of personal data once purpose is served (Storage Limitation).
    - Section 33  : Penalties up to ₹250 CRORES for lifecycle security failures!

  * INFORMATION TECHNOLOGY ACT 2000:
    - Section 43A : Reasonable security practices across all stages of data handling.
    - Section 70B : Mandatory 180-day rolling log retention synchronized with IST NTP servers.

9. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL LIFECYCLE HABITS:
  1. Practice Data Minimization: Collect only essential fields during the Creation stage.
  2. Deploy Crypto-Shredding in Cloud: Delete KMS encryption keys to sanitize cloud storage instantly.
  3. Enforce WORM Archival: Lock audit logs in compliance mode to prevent ransomware tampering.
  4. Generate SHA-256 Hashes at Ingestion: Preserve Section 65B court evidence admissibility.

* COMMON BEGINNER LIFECYCLE PITFALLS:
  - Relying on simple file deletion (Leaves data recoverable from raw flash blocks).
  - Hoarding customer records indefinitely (Direct violation of DPDP Section 8(7)).
  - Leaving data in use unencrypted in memory during processing (Vulnerable to RAM dumps).
  - Storing backup encryption keys on the same storage media being encrypted.
