1. EXECUTIVE OVERVIEW & THE SECURITY TRILEMMA
--------------------------------------------------------------------------------
In theoretical cybersecurity, Confidentiality, Integrity, and Availability (CIA) 
are presented as three equal pillars. However, in production systems, it is 
mathematically, physically, and economically impossible to maximize all three 
pillars to 100% simultaneously. 

Every security architecture represents an intentional engineering trade-off:
  * Prioritizing Confidentiality (e.g., 4096-bit RSA, air-gaps, biometrics) 
    increases computational latency and user friction, directly risking Availability.
  * Prioritizing Integrity (e.g., synchronous 2-Phase Commit, immutable consensus) 
    creates database lock contention, capping system throughput.
  * Prioritizing Availability (e.g., edge caching, fail-open bypasses, async BASE) 
    accepts temporary data inconsistency or uninspected traffic flow.

The mark of an expert security architect is knowing WHICH pillar to prioritize 
based on mission criticality, failure tolerance, and regulatory compliance.

3. DISTRIBUTED SYSTEMS THEOREMS : CAP & PACELC MAPPED TO CIA
--------------------------------------------------------------------------------

1. THE CAP THEOREM (Eric Brewer):
   In any distributed data store, you can choose at most TWO out of THREE:
     - C : Consistency (Integrity of read/write state)
     - A : Availability (Every non-failing node returns a response)
     - P : Partition Tolerance (Network drops/delays will happen in real life)
   Since physical network partitions (P) are unavoidable:
     * CP Systems (Banking): Preserves Integrity by rejecting writes during network splits.
     * AP Systems (Social Media/CDN): Preserves Availability by accepting writes that may diverge.

2. THE PACELC THEOREM (Daniel Abadi):
   Extends CAP to normal (non-partitioned) operations:
     "If Partition (P), choose Availability (A) or Consistency (C);
      Else (E), choose Latency (L) or Consistency (C)."
   Examples:
     * MongoDB   ==> PC/EC (Consistency in both partition & normal ops).
     * Cassandra ==> PA/EL (Availability in partition, Low Latency in normal ops).

4. FORMAL SECURITY POLICY MODELS COMPARISON
--------------------------------------------------------------------------------

1. BELL-LAPADULA MODEL (Confidentiality Focus):
   - Simple Security Property: Subject cannot READ higher classification (No Read Up).
   - *-Property (Star Property): Subject cannot WRITE lower classification (No Write Down).
   - Primary Goal: Prevent state secrets from leaking to lower clearance levels.

2. BIBA INTEGRITY MODEL (Integrity Focus):
   - Simple Integrity Property: Subject cannot READ lower integrity data (No Read Down).
   - *-Integrity Property: Subject cannot WRITE higher integrity data (No Write Up).
   - Primary Goal: Prevent corrupted or unverified data from contaminating critical systems.

3. CLARK-WILSON MODEL (Commercial Fraud Prevention):
   - Separation of Duties: Critical transactions require multiple independent actors.
   - Well-Formed Transactions: Data can only be modified through audited transformation procedures.

4. PARKERIAN HEXAD (Granular 6-Dimensional Evaluation):
   - Expands CIA to: Confidentiality, Possession, Integrity, Authenticity, Availability, Utility.
   - Example: Encrypted laptop stolen → Possession lost, Confidentiality preserved, Utility lost.

5. LOCALIZED ENGINEERING SCENARIOS (WEST BENGAL CASE STUDIES)
--------------------------------------------------------------------------------

SCENARIO 1 : CORE BANKING UPI MICROSERVICES (KOLKATA FINTECH HUB)
  * Lead Architect : Mamata | Budget : ₹8,50,000 | Location : Kolkata
  * Dilemma : 18,000 TPS flash sale spike. 4096-bit RSA asymmetric encryption caused 
    900ms processing queues and payment timeout crashes (Availability failure).
  * Evaluated Trade-Off : Never compromise financial Integrity. Replaced synchronous 
    RSA with PCIe HSM hardware-accelerated AES-256-GCM and stateless tokenization.
  * Result : Sub-30ms latency with 100% ACID compliance and zero double-spend anomalies.

SCENARIO 2 : EMERGENCY TRAUMA "BREAK-GLASS" SYSTEM (ICHAPUR GENERAL HOSPITAL)
  * Lead Security Officer : Mahima | Budget : ₹4,80,000 | Location : Ichapur
  * Dilemma : Enforcing 3-factor biometric login on defibrillators caused fatal delays 
    during cardiac arrest resuscitations (Availability failure).
  * Evaluated Trade-Off : Human life requires instantaneous Availability. Implemented 
    a "Break-Glass" emergency override that unlocks full medical access immediately, 
    while recording tamper-evident immutable audit logs to S3 WORM storage.
  * Result : 0ms lockout during resuscitations with 100% legal auditability.

SCENARIO 3 : 220KV PROTECTIVE RELAYS (BARRACKPORE SUBSTATION GRID)
  * Lead OT Engineer : Debangshu | Budget : ₹6,20,000 | Location : Barrackpore
  * Dilemma : Short-circuit faults require breaker trip commands within 16 milliseconds. 
    Heavy public-key signatures took 70ms, risking physical transformer explosion.
  * Evaluated Trade-Off : Replaced heavy RSA with lightweight HMAC-SHA256 nonces and 
    optical data diodes. 
  * Result : 0.4ms cryptographic authentication well inside the 16ms physics deadline.

SCENARIO 4 : HIGH-PERFORMANCE RESEARCH DATASET (JADAVPUR LABS)
  * Lead Researchers : Abhronila & Susmita | Budget : ₹3,90,000 | Location : Jadavpur
  * Dilemma : AI cancer research on 10 TB genomic datasets. Aggressive k-anonymity 
    stripped rare genetic markers, dropping AI model accuracy from 96% to 78%.
  * Evaluated Trade-Off : Deployed Differential Privacy with calibrated mathematical noise 
    (Epsilon = 1.2), balancing subject privacy with high statistical model integrity.
  * Result : 94.8% AI diagnostic fidelity with formal DPDP Act privacy compliance.

6. MATHEMATICAL ROI & ECONOMIC FORMULAS
--------------------------------------------------------------------------------

1. Cost-Benefit Rule of Security Controls:
   Net Risk Mitigation ROI (₹) = (ALE_Before - ALE_After) - Annual Cost of Control
   Where:
     ALE = Single Loss Expectancy (SLE) * Annualized Rate of Occurrence (ARO)
   Golden Rule: Never spend ₹1,00,000/year to protect an asset with an ALE of ₹20,000.

2. System Downtime Cost Equation:
   Downtime Cost (₹) = Outage Duration (Hours) * Hourly Lost Revenue Rate (₹/hr)

3. Data Loss Transaction Cost (RPO):
   Loss Cost (₹) = (Unsynced Minutes / 60) * (Hourly Transaction Volume * Avg Profit/Tx)

7. PROFESSIONAL TIPS & COMMON PITFALLS
--------------------------------------------------------------------------------

* PROFESSIONAL HABITS:
  1. Always Document the Trade-Off: Never choose a security control without recording 
     which pillar was compromised and why.
  2. Implement Break-Glass for Life Safety: In hospitals and physical manufacturing, 
     emergency human safety always trumps digital authorization barriers.
  3. Tailor Architecture to the Domain: Do not force banking ACID models onto video 
     streaming, nor BASE models onto core banking ledgers.

* COMMON BEGINNER MISTAKES:
  - Believing a system can be 100% secure in all dimensions at zero cost.
  - Choosing Fail-Closed for emergency exit doors or hospital equipment (trapping humans).
  - Ignoring network physics (trying to do synchronous cross-country replication in < 5ms).
  - Enforcing excessive password complexity that drives users directly into Shadow IT.
