1. THE 7 FOUNDATIONAL ASSUMPTIONS OF CPM & PERT
--------------------------------------------------------------------------------

ASSUMPTION 1: DIRECTED ACYCLIC GRAPH (DAG) TOPOLOGY
• A project is partitioned into distinct, non-overlapping activities.
• The network is strictly acyclic: NO loops, NO cycles, NO backward branches.
• The project has exactly ONE starting node and ONE terminal sink node.

ASSUMPTION 2: ACTIVITY INDEPENDENCE
• Individual activity durations are statistically independent of all other tasks:
      Cov(T_i, T_j) = 0   (for all i != j)
• Allows direct summation of means and variances along the critical path.

ASSUMPTION 3: DETERMINISTIC TIME & LINEAR CRASHING (CPM)
• Task durations in CPM are known with deterministic certainty.
• Crashing an activity from Normal Time (T_n) to Crash Time (T_c) causes a
  strictly linear increase in direct expense at constant marginal Cost Slope:
      Cost Slope = (Crash Cost - Normal Cost) / (Normal Time - Crash Time)

ASSUMPTION 4: BETA DISTRIBUTION FOR TASK DURATIONS (PERT)
• Individual task durations in PERT follow a continuous, unimodal Beta distribution
  parameterized by Optimistic (a), Most Likely (m), and Pessimistic (b) estimates:
      Expected Duration:   t_e = (a + 4m + b) / 6
      Duration Variance:   sigma^2 = ((b - a) / 6)^2

ASSUMPTION 5: CENTRAL LIMIT THEOREM (CLT) & NORMAL PATH CONVERGENCE
• By the Central Limit Theorem, the sum of independent random activity durations
  along the critical path converges to a Normal Distribution N(mu_cp, sigma_cp^2):
      mu_cp = Sum_{i in CP} t_e(i)
      sigma_cp^2 = Sum_{i in CP} sigma^2(i)
• Enables Z-score calculation: Z = (T_s - mu_cp) / sigma_cp.

ASSUMPTION 6: UNCONSTRAINED INITIAL RESOURCE CAPACITY
• Baseline forward and backward passes assume all necessary resources (labor, machines)
  are available on demand; resource limits are resolved in secondary leveling passes.

ASSUMPTION 7: SINGLE CRITICAL PATH DOMINANCE (NO MERGE BIAS)
• Classical PERT assumes project variance is determined solely by the single critical path,
  assuming non-critical paths have sufficient slack to absorb local delays.

--------------------------------------------------------------------------------
2. Z-SCORE PROBABILITY FORMULATION IN PERT
--------------------------------------------------------------------------------
To compute the probability P(T <= T_s) of completing a project within target date T_s:

    Z = (Target Date T_s - Expected Duration mu_cp) / sigma_cp

STANDARD NORMAL PROBABILITIES:
• Z = 0.00 ➔ P = 50.00% (Finishing on the expected mean date)
• Z = +1.00 ➔ P = 84.13%
• Z = +1.64 ➔ P = 95.00%
• Z = +2.00 ➔ P = 97.72%
• Z = +3.00 ➔ P = 99.87%

4. COMMON PITFALLS & PRACTICAL ADVICE
--------------------------------------------------------------------------------
- Never sum standard deviations directly (sigma_total != sigma_1 + sigma_2); ALWAYS sum variances (sigma^2) and take the square root!
- Remember that an expected completion date in PERT only has a 50% probability of on-time finish.
- Monitor Near-Critical Paths: if a near-critical path has high variance, it can easily become the true bottleneck during execution!
- Report all budgets, crashing costs, and investment figures in Indian Rupees (₹).
