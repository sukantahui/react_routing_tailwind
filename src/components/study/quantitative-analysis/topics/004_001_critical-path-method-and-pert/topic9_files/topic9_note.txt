1. DEFINITION OF THE CRITICAL PATH
--------------------------------------------------------------------------------
The CRITICAL PATH is the continuous, unbroken chain of sequential activities and
events extending from the initial start event (Node 1) to the final terminal sink
event (Node n) that requires the LONGEST TOTAL DURATION in the network.

THE CORE PARADOX:
• The LONGEST PATH dictates the MINIMUM PROJECT DURATION:
  Because every task in the project must be completed, the project cannot physically
  finish any sooner than the time required to complete the longest sequential chain.

--------------------------------------------------------------------------------
2. THE 5 CORE PROPERTIES OF THE CRITICAL PATH
--------------------------------------------------------------------------------

1. ZERO FLOAT CONTINUITY:
   • Every activity along the critical path has Total Float TF = 0, Free Float FF = 0,
     and Independent Float IF = 0.
   • Every node along the critical path has Event Slack S_i = L_i - E_i = 0.

2. SINGLE VS. MULTIPLE CRITICAL PATHS:
   • A project network can have multiple co-critical paths if two or more distinct
     routes from Node 1 to Node n share the identical maximum duration.
   • In multi-critical networks, shortening project duration requires crashing ALL
     parallel critical paths simultaneously!

3. DYNAMIC SHIFTING OF CRITICAL PATH:
   • As activities on the critical path are crashed, its duration shrinks.
   • When the critical path duration matches a subcritical path, the subcritical path
     becomes co-critical.
   • Conversely, severe delays on a non-critical path can consume all its float and
     shift the critical path to that branch.

4. SUBCRITICAL (NEAR-CRITICAL) PATHS:
   • Paths with very low total float (e.g. TF <= 2 days).
   • Require rigorous executive monitoring to prevent unmonitored path flips.

5. RESOURCE LEVELING & FINANCIAL CONTROL:
   • Non-critical paths can be shifted within their float windows to level manpower,
     reducing peak labor expenses and overtime direct costs in Indian Rupees (₹).

3. MULTI-PATH COMPARISON TABLE (EXAMPLE 7-NODE PROJECT)
--------------------------------------------------------------------------------
Path Name | Sequence of Nodes       | Sequence of Tasks | Duration | Float | Critical?
-------------------------------------------------------------------------------------
Path 1    | 1 ➔ 2 ➔ 4 ➔ 6 ➔ 7       | A ➔ C ➔ F ➔ H     | 24 Days  | 0 d   | YES (CRITICAL ⭐)
Path 2    | 1 ➔ 3 ➔ 4 ➔ 6 ➔ 7       | B ➔ D ➔ F ➔ H     | 24 Days  | 0 d   | YES (CRITICAL ⭐)
Path 3    | 1 ➔ 2 ➔ 5 ➔ 6 ➔ 7       | A ➔ E ➔ G ➔ H     | 17 Days  | 7 d   | Non-Critical
-------------------------------------------------------------------------------------
PROJECT DURATION = max(24, 24, 17) = 24 Days.
CO-CRITICAL PATHS: Path 1 and Path 2 are both critical!

5. COMMON PITFALLS & PRACTICAL ADVICE
--------------------------------------------------------------------------------
- Never assume there is only one critical path; always check for parallel paths with identical durations.
- In multi-critical networks, crashing only one critical path will NOT shorten project duration!
- Keep a close watch on subcritical paths with small float buffers.
- State all project investments, overtime budgets, and direct costs in Indian Rupees (₹).
