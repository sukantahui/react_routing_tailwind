1. THE FOUR RELATIONAL JOIN TYPES (pd.merge):
   --------------------------------------------------------------------------
   - `how='inner'` (Default):
     * Intersection: Keeps only rows where the merge key exists in BOTH DataFrames.
   - `how='left'`:
     * Retains ALL rows from left DataFrame; fills missing right table fields with NaN.
   - `how='right'`:
     * Retains ALL rows from right DataFrame; fills missing left table fields with NaN.
   - `how='outer'`:
     * Full outer union: Retains all records from both tables.
   - `how='cross'`:
     * Cartesian product (all combinations of rows).

2. KEY SPECIFICATION & COLUMN CONFLICTS:
   --------------------------------------------------------------------------
   - Same column name on both: `on='StudentID'`
   - Different column names: `left_on='user_id', right_on='student_code'`
   - Joining on Index: `left_index=True`, `right_index=True`
   - Overlapping non-key columns:
     `suffixes=('_left', '_right')` disambiguates columns sharing the same name.
   - Merge lineage tracing:
     `indicator=True` creates a `_merge` categorical column ('both', 'left_only', 'right_only').

3. CONCATENATION (pd.concat):
   --------------------------------------------------------------------------
   - Vertical Stacking (Appending rows):
     `pd.concat([df_jan, df_feb], axis=0, ignore_index=True)`
   - Horizontal Stacking (Binding columns):
     `pd.concat([df_features, df_labels], axis=1)`
   - `df.join()`: Convenience method designed specifically for index-based joins.

4. MACHINE LEARNING DATA ENGINEERING BEST PRACTICES:
   --------------------------------------------------------------------------
   - Validating merge cardinality: Use `validate='1:1'`, `validate='1:m'`, or `validate='m:1'` inside `pd.merge()` to ensure unexpected duplicates do not quietly multiply rows!
   - Always check `len(merged_df)` vs `len(original_df)` to catch row explosion or unintended dropped rows immediately.
