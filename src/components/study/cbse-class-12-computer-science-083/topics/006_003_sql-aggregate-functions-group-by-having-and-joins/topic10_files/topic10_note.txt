TOPIC 10: THE EQUI-JOIN: LINKING TABLES VIA COMMON ATTRIBUTES (WHERE TABLE1.ID = TABLE2.ID)

1. CORE CONCEPT SUMMARY:
An Equi-Join links records from two or more tables based on equality comparison between common attributes (typically Primary Key and Foreign Key).

2. KEY EXAMINATION POINTS:
  (1) An Equi-Join is effectively a Cartesian Product filtered by a join predicate: 'WHERE Table1.CommonCol = Table2.CommonCol'.
  (2) Number of Join Conditions Rule: To join N tables, at least (N - 1) join conditions are required in the WHERE clause to avoid Cartesian explosion.
  (3) Syntax: 'SELECT T1.Col1, T2.Col2 FROM Table1 T1, Table2 T2 WHERE T1.Key = T2.Key;'
  (4) Only records that have matching keys in both tables appear in the equi-join result set.

3. SYNTAX & CODE SNIPPET:
-- Two-table Equi-Join
SELECT S.RollNo, S.SName, C.CourseName, C.Fees 
FROM Student S, Course C 
WHERE S.CourseId = C.CourseId;

-- Three-table Equi-Join (Requires 3 - 1 = 2 Join conditions)
SELECT O.OrderId, C.CustName, I.ItemName, O.Qty 
FROM Orders O, Customer C, Item I 
WHERE O.CustId = C.CustId AND O.ItemId = I.ItemId;

4. CBSE COMMON PITFALLS:
Ensure correct placement of WHERE before GROUP BY and HAVING after GROUP BY.
