1. CORE CONCEPT SUMMARY:
Understanding the logical execution sequence of SQL clauses clarifies why column aliases cannot be used in WHERE or HAVING.

2. KEY EXAMINATION POINTS:
  (1) Stage 1: FROM (and JOINs) — Identify and load source relations into memory.
  (2) Stage 2: WHERE — Filter individual rows using relational and logical predicates.
  (3) Stage 3: GROUP BY — Aggregate remaining rows into partitioned buckets.
  (4) Stage 4: HAVING — Discard aggregate buckets that fail group conditions.
  (5) Stage 5: SELECT — Project specified columns, evaluate aliases and expressions.
  (6) Stage 6: ORDER BY — Sort final result set by requested sort keys.

3. SYNTAX & CODE SNIPPET:
-- Trace the execution flow:
SELECT Dept, AVG(Salary) AS MeanPay       -- Stage 5: SELECT & Alias
FROM Employee                            -- Stage 1: FROM
WHERE Status = 'Active'                  -- Stage 2: WHERE
GROUP BY Dept                            -- Stage 3: GROUP BY
HAVING COUNT(*) >= 3                     -- Stage 4: HAVING
ORDER BY MeanPay DESC;                   -- Stage 6: ORDER BY

4. CBSE COMMON PITFALLS:
Ensure correct placement of WHERE before GROUP BY and HAVING after GROUP BY.

5. REVISION CHECKLIST:
  [ ] Understand difference between COUNT(*) and COUNT(col).
  [ ] Master GROUP BY rules regarding non-aggregated columns.
  [ ] Remember WHERE cannot contain aggregate functions; use HAVING.
  [ ] Know Cartesian Product formulas: Cardinality = R1 * R2, Degree = C1 + C2.
  [ ] Always include (N - 1) join conditions when joining N tables.
