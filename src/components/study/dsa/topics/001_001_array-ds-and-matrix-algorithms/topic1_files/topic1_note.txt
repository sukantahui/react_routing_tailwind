1. DYNAMIC ARRAY STRUCT ENCAPSULATION
--------------------------------------------------------------------------------
In C, dynamic arrays are represented as a composite struct managing a heap buffer:

  typedef struct {
      int* data;          // Base address of dynamically allocated heap buffer
      size_t size;        // Number of elements currently in use
      size_t capacity;    // Total allocated slots in heap memory
  } DynamicArray;

2. THE GEOMETRIC DOUBLING STRATEGY & AMORTIZED O(1) PROOF
--------------------------------------------------------------------------------
Why double capacity (2x) instead of linear increment (+10)?

• Linear Growth (+C):
  - Inserting N elements triggers N/C reallocations.
  - Total copy operations: C + 2C + 3C + ... + N = O(N^2) total work.
  - Amortized cost per push: O(N^2) / N = O(N) (SLOW / Unacceptable).

• Geometric Doubling (2x):
  - Reallocations occur at capacities 1, 2, 4, 8, 16, ..., N.
  - Total copy operations: 1 + 2 + 4 + 8 + ... + N/2 = N - 1.
  - Total work across N pushes = N (insertions) + (N - 1) (copies) = 2N - 1.
  - Amortized cost per push: (2N - 1) / N ≈ O(1) CONSTANT TIME!

3. SAFE REALLOCATION VS THE DANGLING TRAP
--------------------------------------------------------------------------------
[X] DEADLY TRAP (Causes Memory Leak on Realloc Failure):
    vec->data = (int*)realloc(vec->data, new_capacity * sizeof(int));
    // If realloc() fails, it returns NULL, overwriting vec->data and 
    // permanently orphaning the existing buffer!

[✓] IDIOMATIC C SAFE PATTERN:
    int* temp = (int*)realloc(vec->data, new_capacity * sizeof(int));
    if (!temp) {
        perror("Memory allocation failed");
        // vec->data is still valid! Graceful error recovery possible.
        return;
    }
    vec->data = temp;
    vec->capacity = new_capacity;

4. HYSTERESIS SHRINKING (PREVENTING BUFFER THRASHING)
--------------------------------------------------------------------------------
• Never shrink capacity immediately when size drops below 1/2 capacity.
• If an app alternates between pushing and popping at the boundary:
  Push -> Double (realloc) -> Pop -> Halve (realloc) -> Push -> Double...
• Thrashing cost: O(N) work on EVERY operation!
• Solution: Shrink capacity to half ONLY when size drops to 1/4 of capacity (25%).

5. MEMORY TEARDOWN CHECKLIST (ZERO LEAKS)
--------------------------------------------------------------------------------
1. Free internal buffer: `free(vec->data);`
2. Neutralize pointer:   `vec->data = NULL;`
3. Free wrapper struct:  `free(vec);`
