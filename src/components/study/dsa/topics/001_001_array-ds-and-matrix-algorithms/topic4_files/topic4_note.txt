1. THE 4 CRITICAL HEAP MEMORY HAZARDS IN C
--------------------------------------------------------------------------------
Hazard                  Formal Definition & Physical Cause
--------------------------------------------------------------------------------
1. Memory Leak          Heap memory allocated via malloc()/calloc()/realloc() 
                        whose pointer reference is lost or overwritten before 
                        calling free(). That RAM remains locked and unavailable
                        to the operating system until the process terminates.

2. Dangling Pointer     A pointer variable that continues to hold the memory 
                        address of a heap block or stack frame that has ALREADY
                        been deallocated via free().

3. Use-After-Free       Dereferencing (reading/writing through) a dangling pointer.
   (CWE-416)            Can lead to silent data corruption, security exploits,
                        or arbitrary code execution.

4. Double-Free          Calling free(ptr) twice on the exact same allocated pointer.
   (CWE-415)            Corrupts the heap allocator's internal free-list bin 
                        metadata and is a major security vulnerability.


2. THE REALLOC() OVERWRITE TRAP (THE MOST COMMON NOVICE BUG)
--------------------------------------------------------------------------------
🚫 FATAL PATTERN:
    int *arr = (int*)malloc(100 * sizeof(int));
    // ...
    arr = (int*)realloc(arr, 1000000000 * sizeof(int)); // FATAL TRAP!

Why is this a fatal trap?
If realloc() fails (e.g. system is out of memory), it returns NULL.
Because `arr` is directly overwritten with NULL, the address of the ORIGINAL 
100-integer buffer is permanently erased! The original 400 bytes can NEVER be 
freed, causing an immediate, unrecoverable MEMORY LEAK.

✅ THE SAFE 3-STEP REALLOCATION PATTERN:
    // Step 1: Allocate into a temporary pointer
    int *temp = (int*)realloc(arr, new_capacity * sizeof(int));

    // Step 2: Validate temp before touching original pointer
    if (temp == NULL) {
        // Handle allocation failure gracefully
        fprintf(stderr, "Reallocation failed! Original buffer is safe.\n");
        // arr still points to original valid buffer!
    } else {
        // Step 3: Success! Update original pointer to point to new buffer
        arr = temp;
        capacity = new_capacity;
    }


3. POINTER NEUTRALIZATION DISCIPLINE (DEFENSIVE PROGRAMMING)
--------------------------------------------------------------------------------
Calling `free(ptr)` only marks the underlying heap chunk as free in glibc 
ptmalloc metadata. It DOES NOT modify the `ptr` variable in CPU registers/stack!
`ptr` still holds the old address (it becomes a Dangling Pointer).

The Golden Rule:
    free(ptr);
    ptr = NULL; // Neutralize immediately!

Why does this guarantee safety?
1. In C, `free(NULL)` is explicitly guaranteed by the C99/C11 standard to be 
   a safe NO-OP (no action taken, no crash).
2. If you accidentally dereference a NULL pointer (`*ptr = 10;`), the CPU 
   hardware Memory Management Unit (MMU) triggers an instant, deterministic 
   SIGSEGV segmentation fault at address 0x0 instead of silently corrupting 
   re-allocated heap memory!


4. INDUSTRIAL MEMORY DIAGNOSTICS & SANITIZERS
--------------------------------------------------------------------------------
Tool                    How to Use & Purpose
--------------------------------------------------------------------------------
1. AddressSanitizer     Compile with: `gcc -fsanitize=address -g program.c`
   (ASan)               Instruments binary at compile time. Catches Out-of-Bounds,
                        Use-After-Free, and Double-Free with 0% false positives.

2. Valgrind Memcheck    Run with: `valgrind --leak-check=full ./program`
                        Simulates virtual CPU to track every single byte of heap 
                        memory and reports exact line numbers of memory leaks.

3. Static Analyzers     `scan-build gcc -c program.c` or Clang-Tidy.


5. DYNAMIC ARRAY LIFECYCLE INVARIANT CHECKLIST
--------------------------------------------------------------------------------
[ ] 1. Every malloc()/calloc() has exactly one corresponding free().
[ ] 2. realloc() is always captured in a temporary pointer first (`temp`).
[ ] 3. After calling free(p), immediately assign `p = NULL;`.
[ ] 4. Check for NULL return values after every dynamic allocation.
[ ] 5. Encapsulate dynamic arrays in a struct tracking `{ data, size, capacity }`.
