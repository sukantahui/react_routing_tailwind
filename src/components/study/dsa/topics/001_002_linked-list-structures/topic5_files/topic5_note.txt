1. WHY LINKED LISTS BEAT ARRAYS FOR SPARSE POLYNOMIALS
--------------------------------------------------------------------------------
Consider P(x) = 5x^1000 + 3x^2 + 1:
  • Array approach: Needs an array of size 1001, where 998 entries are 0!
  • Linked List approach: Stores ONLY the 3 non-zero terms:
      [5 | 1000] -> [3 | 2] -> [1 | 0] -> NULL

Node Definition:
  struct Term {
      int coeff;          // Non-zero coefficient
      int exp;            // Exponent (kept sorted descending)
      struct Term *next;
  };

2. POLYNOMIAL ADDITION — TWO-POINTER MERGE IN O(N + M)
--------------------------------------------------------------------------------
Compare `p1->exp` and `p2->exp`:
  • Case 1 (`p1->exp > p2->exp`): Copy `p1` term to result, advance `p1`.
  • Case 2 (`p1->exp < p2->exp`): Copy `p2` term to result, advance `p2`.
  • Case 3 (`p1->exp == p2->exp`): Compute `sum = p1->coeff + p2->coeff`.
      - If `sum != 0`, append `(sum, exp)` to result.
      - If `sum == 0`, SKIP (terms cancelled out)!
      - Advance BOTH `p1` and `p2`.

3. SPARSE POLYNOMIAL MULTIPLICATION
--------------------------------------------------------------------------------
For every term `a` in P1 and every term `b` in P2:
  • Product term = `(a->coeff * b->coeff) * x^(a->exp + b->exp)`.
  • Insert into sorted result list, combining coefficients if exponent matches
    and deleting the node if the combined coefficient becomes 0!
  • Time Complexity:
      - Using sorted insertion: O(N * M * (N + M)) or O(N^2 * M^2) worst case
        (can be improved to O(N*M log(N*M)) using Merge Sort on product terms).
