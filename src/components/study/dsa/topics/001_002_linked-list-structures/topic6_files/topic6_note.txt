1. WHAT IS A DANGLING POINTER?
--------------------------------------------------------------------------------
When you call `free(ptr)` in C:
  • The OS/glibc heap allocator marks that memory block as reusable.
  • C does NOT automatically set `ptr` to `NULL`!
  • `ptr` STILL holds the old hex address (e.g., `0x55a030`), even though you
    no longer own that memory. That leftover pointer is a DANGLING POINTER.

2. THREE DANGEROUS BUGS CAUSED BY DANGLING POINTERS
--------------------------------------------------------------------------------
  1. Use-After-Free (UAF): Reading/writing `ptr->data` or `ptr->next` after
     `free(ptr)`. May appear to "work" briefly, then silently corrupt data!
  2. Double-Free: Calling `free(ptr)` a second time on the same address,
     corrupting the glibc free-list and crashing with `SIGABRT`.
  3. Orphaned `head` / `tail`: Freeing the whole list without setting
     `*headRef = NULL` leaves `head` pointing to dead heap memory.

3. THE GOLDEN CLEANUP PROTOCOL
--------------------------------------------------------------------------------
  void freeList(Node **headRef) {
      Node *curr = *headRef;
      while (curr != NULL) {
          Node *temp = curr->next; // 1. Save next BEFORE freeing
          free(curr);              // 2. Release heap block
          curr = temp;             // 3. Advance safely
      }
      *headRef = NULL;             // 4. Neutralize caller's head pointer!
  }

For single-node removal:
  free(target);
  target = NULL;  // Note: free(NULL) is guaranteed a safe no-op in C!
