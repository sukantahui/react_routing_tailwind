1. EXECUTIVE OVERVIEW & HARDWARE FOUNDATION
--------------------------------------------------------------------------------
In digital hardware architectures, memory cells and processor registers store only
homogeneous electrical voltages representing binary bits (0s and 1s). The physical
silicon does NOT inherently know whether a bit pattern represents a positive
integer, a negative integer, an ASCII character, a floating-point number, or a
memory address pointer.

The interpretation of raw bits is governed entirely by the instruction opcode and
the declared data type:
- UNSIGNED REPRESENTATION: All n bits represent pure positive magnitude. Every bit
  contributes a positive positional weight (+2^i).
- SIGNED REPRESENTATION: The Most Significant Bit (MSB, bit n-1) is reserved as the
  Sign Bit (0 = Positive / Zero, 1 = Negative). The remaining bits determine magnitude
  according to the encoding convention (Sign-Magnitude, 1's Complement, or 2's Complement).

2. MATHEMATICAL FORMULAS & NUMERICAL RANGES
--------------------------------------------------------------------------------
For an n-bit binary register:

A. UNSIGNED RANGE:
   Range: [0 to 2^n - 1]
   Total distinct values = 2^n
   Formula: V_unsigned = Sum_{i=0}^{n-1} (b_i * 2^i)

B. SIGNED 2'S COMPLEMENT RANGE (Standard in Modern CPUs):
   Range: [-2^(n-1) to +2^(n-1) - 1]
   Total distinct values = 2^n (Asymmetric: exactly one extra negative number)
   Formula: V_signed2s = (-b_{n-1} * 2^(n-1)) + Sum_{i=0}^{n-2} (b_i * 2^i)

C. SIGNED MAGNITUDE & 1'S COMPLEMENT RANGE:
   Range: [-(2^(n-1) - 1) to +(2^(n-1) - 1)]
   Total distinct non-zero values = 2^n - 1 (Symmetric, but suffers from Dual Zeros: +0 and -0)

COMPARISON TABLE BY REGISTER BIT-WIDTH:
--------------------------------------------------------------------------------
Width | Unsigned Range         | Signed (2's Comp) Range
--------------------------------------------------------------------------------
8-bit | 0 to 255               | -128 to +127
16-bit| 0 to 65,535            | -32,768 to +32,767
32-bit| 0 to 4,294,967,295     | -2,147,483,648 to +2,147,483,647
64-bit| 0 to ~18.44 Quintillion| -9.22 Quintillion to +9.22 Quintillion

3. THE "DUAL INTERPRETATION" OF THE EXACT SAME BIT PATTERN
--------------------------------------------------------------------------------
Consider the 8-bit bit pattern: 1111 1111 (0xFF)

- Unsigned Interpretation:
  128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = +255

- Signed 2's Complement Interpretation:
  -128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = -1

- Signed Magnitude Interpretation:
  Sign bit = 1 (negative), Magnitude = 111 1111 (127) → -127

- 1's Complement Interpretation:
  Inverting bits gives 0000 0000 → -0 (Negative Zero)

KEY TAKEAWAY: The CPU ALU executes different assembly instructions (e.g., `ADD` vs `ADDU`,
`CMP` vs `CMPU`, `JGE` vs `JAE`) depending on whether the software compiler treats the
variables as signed or unsigned.

5. COMMON PITFALLS & SENIOR BEST PRACTICES
--------------------------------------------------------------------------------
- PITFALL: Mixing signed and unsigned variables in C/C++ expressions. In `int x = -5; unsigned int y = 10; if (x < y)`, C promotes `x` to unsigned, transforming -5 into +4,294,967,291, making the condition FALSE!
- PITFALL: Assuming unsigned arithmetic never overflows. Unsigned integers silently
  wrap around (255 + 1 = 0 in 8-bit).
- BEST PRACTICE: Use fixed-width types from `<stdint.h>` (`uint8_t`, `int8_t`, `uint32_t`, `int32_t`) instead of vague platform-dependent types like `int` or `long`.
- BEST PRACTICE: Use unsigned types exclusively for bitmasks, memory addresses, array indices, and cryptographic hashes. Use signed types for mathematical quantities.
