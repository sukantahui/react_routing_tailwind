PROBLEM 1: Multi-Base Conversion Pipeline
Convert Decimal 379.375 into:
  (a) Binary Fixed-Point
  (b) Hexadecimal
  (c) Octal

Solution Step-by-Step:
1. Integer Part (379):
   - 379 / 2 = 189 rem 1 (LSB)
   - 189 / 2 = 94  rem 1
   - 94  / 2 = 47  rem 0
   - 47  / 2 = 23  rem 1
   - 23  / 2 = 11  rem 1
   - 11  / 2 = 5   rem 1
   - 5   / 2 = 2   rem 1
   - 2   / 2 = 1   rem 0
   - 1   / 2 = 0   rem 1 (MSB)
   Integer Binary = 101111011_2 (379_10)

2. Fractional Part (0.375):
   - 0.375 * 2 = 0.750 -> Integer 0
   - 0.750 * 2 = 1.500 -> Integer 1
   - 0.500 * 2 = 1.000 -> Integer 1 (Terminates)
   Fractional Binary = .011_2

(a) Binary Result: 101111011.011_2
(b) Hexadecimal: Pad into 4-bit nibbles:
    0001 0111 1011 . 0110_2 = 1 7 B . 6_16 -> 0x17B.6
(c) Octal: Pad into 3-bit groups:
    101 111 011 . 011_2 = 5 7 3 . 3_8 -> (573.3)_8

PROBLEM 2: Signed Arithmetic & Overflow Analysis
Given an 8-bit 2's complement ALU, evaluate the following operations:
  (A) (+95) + (+45)
  (B) (-70) + (-65)
  (C) (+80) - (-55)

Evaluation:
(A) (+95) + (+45):
    +95:  0 1 0 1 1 1 1 1
  + +45:  0 0 1 0 1 1 0 1
  ------------------------
    Sum:  1 0 0 0 1 1 0 0  (0x8C = -116 in signed 2's comp)
    Flags: Z=0, N=1, C=0, V=1.
    Diagnosis: Signed Overflow occurred! True mathematical sum is +140, which
    exceeds INT8_MAX (+127). The sign bit incorrectly flipped to 1 (negative).

(B) (-70) + (-65):
    -70 (256 - 70 = 186): 1 0 1 1 1 0 1 0
  + -65 (256 - 65 = 191): 1 0 1 1 1 1 1 1
  ----------------------------------------
    Sum:               (1) 0 1 1 1 1 0 0 1  (0x79 = +121)
    Flags: Z=0, N=0, C=1, V=1.
    Diagnosis: Signed Underflow occurred! True sum is -135, which falls below
    INT8_MIN (-128). Adding two negative numbers produced a positive sign bit.

(C) (+80) - (-55):
    Computed as (+80) + (+55).
    +80:  0 1 0 1 0 0 0 0
  + +55:  0 0 1 1 0 1 1 1
  ------------------------
    Sum:  1 0 0 0 0 1 1 1  (0x87 = -121)
    Flags: Z=0, N=1, C=0, V=1 (Overflow! +135 > +127).

PROBLEM 3: UTF-8 Variable-Length Byte Assembly
Encode the Unicode character for the Bengali letter 'ম' (Code Point U+09AE).

Solution:
1. Code point U+09AE falls into the 3-byte range (U+0800 to U+FFFF).
2. 3-byte UTF-8 template: 1110xxxx 10xxxxxx 10xxxxxx
3. 0x09AE in 16-bit binary: 0000 1001 1010 1110
4. Distribute payload bits:
   - Upper 4 bits (0000) -> 1110 0000 (0xE0)
   - Middle 6 bits (100110) -> 10 100110 (0xA6)
   - Lower 6 bits (101110) -> 10 101110 (0xAE)
Final UTF-8 Encoded Sequence: 0xE0 0xA6 0xAE (3 Bytes). Verified!
