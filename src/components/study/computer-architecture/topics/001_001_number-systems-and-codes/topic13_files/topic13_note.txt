1. EXECUTIVE SUMMARY & SILICON PARADIGM SHIFT
--------------------------------------------------------------------------------
In the early decades of computing (1940s–1960s), computer designers experimented
with multiple ways to represent negative integers on binary hardware:
  1. Sign-Magnitude Representation (IBM 7090, early mainframes)
  2. 1’s Complement Representation (CDC 6600, UNIVAC 1100 series)
  3. Excess-K (Biased) Representation (used today primarily for floating-point exponents)
  4. 2’s Complement Representation (IBM System/360, PDP-11, x86, ARM, RISC-V)

By the 1970s, 2’s Complement completely won the architectural battle and became
the universal standard for all general-purpose microprocessors. 

Why did 2's complement win?
- Hardware Simplicity: Subtraction is performed using identical adder hardware (A - B = A + ~B + 1).
- Single Zero: Only one bit-pattern for zero (00000000), eliminating dual-zero logic traps.
- Discarded Carry: Carry-out from MSB is safely ignored under modulo 2^n arithmetic,
  completely eliminating the slow, pipelined-disrupting "End-Around Carry" of 1's complement.
- Continuous Signed Range: An n-bit register represents [-2^(n-1) to +2^(n-1) - 1] (256 distinct
  numbers in 8 bits: -128 to +127), gaining 1 additional negative value over 1's complement.
- Trivial Flag Generation: Zero (Z), Negative (N), Carry (C), and Overflow (V = C_n ^ C_(n-1))
  are computed using immediate single-gate tapping from the adder datapath.

3. THE MATHEMATICAL FOUNDATIONS: RADIX COMPLEMENT MODULO 2^n
--------------------------------------------------------------------------------
In an n-bit binary system, arithmetic registers operate naturally on the finite
ring of integers modulo 2^n (Z / 2^n Z).

For an 8-bit register, the modulus is 2^8 = 256.
Any number X and its negative -X must satisfy:
  [X + (-X)] ≡ 0 (mod 256)

Therefore:
  -X ≡ (256 - X) (mod 256)

Notice that:
  256 - X = (255 - X) + 1
Where:
  255 in binary is 11111111_2.
  Subtracting X from 11111111 is identical to inverting every bit of X (bitwise NOT, ~X, or 1's complement).

Hence:
  -X = ~X + 1

Example for X = 25 (00011001_2):
  1. Invert bits (~X): 11100110
  2. Add 1 (~X + 1):  11100111 = 231 (in unsigned) = -25 (in signed 2's complement)

Addition verification (45 - 25 = 20):
    +45:  0 0 1 0 1 1 0 1
  + -25:  1 1 1 0 0 1 1 1
  ------------------------
    Sum: (1) 0 0 0 1 0 1 0 0  (Discard MSB Carry 1)
  Result: 00010100_2 = +20_10. Exact!

4. UNIFIED ADDER / SUBTRACTOR HARDWARE DATAPATH
--------------------------------------------------------------------------------
To compute (A + B) when SUB = 0:
  - B passes through XOR gates with 0: B ^ 0 = B.
  - Carry-In C0 = 0.
  - Output = A + B + 0 = A + B.

To compute (A - B) when SUB = 1:
  - B passes through XOR gates with 1: B ^ 1 = ~B (1's complement).
  - Carry-In C0 = 1 (adds 1 to LSB).
  - Output = A + ~B + 1 = A + (-B) = A - B.

Silicon Impact:
A single n-bit Full Adder plus n simple 2-input XOR gates handles all addition,
subtraction, signed comparison, and negative negation with zero redundant silicon.

5. REAL-WORLD CASE STUDIES (WEST BENGAL ENGINEERING CONTEXT)
--------------------------------------------------------------------------------
Case Study 1: Barrackpore High-Speed Audio DSP Engine
At a digital signal processing research unit in Barrackpore, Mamata and Mahima
benchmarked audio FIR filters. Using 2's complement ensured that audio sample
accumulation (summing millivolt signals) had zero DC offset drift, because +0 and
-0 do not exist, and truncation quantization is symmetric around true zero.

Case Study 2: Jadavpur University Custom RISC-V Core
At the Jadavpur VLSI laboratory, Debangshu and Susmita synthesized an 8-bit RISC-V
ALU on a Xilinx Artix-7 FPGA. By adopting 2's complement unified adder logic, they
reduced the ALU slice utilization from 148 LUTs down to 64 LUTs and increased maximum
clock frequency from 115 MHz to 195 MHz compared to a dual-zero 1's complement design.

6. ARCHITECTURAL PITFALLS & SENIOR BEST PRACTICES
--------------------------------------------------------------------------------
Pitfall 1: Asymmetry of INT_MIN (-2^(n-1))
  In 8-bit 2's complement, -128 is valid (10000000), but +128 cannot be represented.
  Evaluating abs(-128) or -(-128) results in -128 (integer overflow).
  Always check for INT_MIN before negation in security-critical firmware.

Pitfall 2: Forgetting Sign Extension When Widening
  Casting an 8-bit signed integer (e.g. -16 = 0xF0) to a 16-bit integer requires
  replicating the MSB sign bit (0xFFF0), not zero-padding (0x00F0 = +240).

Best Practice 1: One-Gate Overflow Flag
  Always wire the CPU Overflow (V) flag as: V = Carry_In(MSB) ^ Carry_Out(MSB).

Best Practice 2: Unified ADD/SUB Opcodes
  Expose single unified ADD and SUB instructions in CPU ISAs, using status flags
  (C for unsigned, V for signed) to handle conditional jumps.
