1. EXECUTIVE OVERVIEW & HARDWARE DEFINITION
--------------------------------------------------------------------------------
In digital hardware architectures, Arithmetic Overflow occurs when the mathematical
result of an arithmetic calculation exceeds the representable dynamic range of the
fixed-width destination register.

CRITICAL DISTINCTION:
- UNSIGNED OVERFLOW is detected by the CARRY FLAG (CF = Carry out of MSB = 1).
- SIGNED OVERFLOW is detected by the OVERFLOW FLAG (OF or V), indicating that the
  sign bit has been corrupted by magnitude bits spilling over.

--------------------------------------------------------------------------------
2. THE TWO UNIVERSAL RULES FOR SIGNED OVERFLOW DETECTION
--------------------------------------------------------------------------------

RULE 1: THE ALGEBRAIC SIGN RULE
Signed overflow occurs if and only if:
1. Adding two POSITIVE numbers produces a NEGATIVE result (+A + +B = -Result).
2. Adding two NEGATIVE numbers produces a POSITIVE result (-A + -B = +Result).
3. Adding numbers of OPPOSITE SIGNS (+A + -B) can NEVER produce an overflow!

Boolean Logic Formula:
  V = (A_{n-1} * B_{n-1} * NOT(S_{n-1})) + (NOT(A_{n-1}) * NOT(B_{n-1}) * S_{n-1})

RULE 2: THE HARDWARE CARRY-XOR RULE (SINGLE-GATE SYNTHESIS)
In processor ALU silicon, checking sign bits with wide AND-OR gates is unnecessary.
Instead, the Overflow Flag is generated using a SINGLE 2-input XOR gate comparing
the Carry-In to the MSB and the Carry-Out from the MSB:
  V = C_n XOR C_{n-1}

Why the XOR Rule works:
- If C_{n-1} = 1 and C_n = 0: A carry spilled into the sign bit but did not exit → Overflow!
- If C_{n-1} = 0 and C_n = 1: A carry exited the sign bit without entering → Overflow!
- If C_{n-1} == C_n (both 0 or both 1): No overflow occurred (V = 0).

3. STEP-BY-STEP WORKED EXAMPLES
--------------------------------------------------------------------------------

EXAMPLE 1: Positive Overflow in 8-Bit (+100 + +50 = +150 > +127)
--------------------------------------------------------------------------------
  +100:  0110 0100
  +50:   0011 0010
  Carries: 0110 0000  (Carry-In to MSB C_7 = 1, Carry-Out C_8 = 0)
  Sum:   1001 0110 = -106 (MSB=1, Positive + Positive = Negative!)

Overflow Calculation:
  V = C_8 XOR C_7 = 0 XOR 1 = 1 (OVERFLOW ASSERTED!)

EXAMPLE 2: Negative Underflow in 8-Bit (-100 + -50 = -150 < -128)
--------------------------------------------------------------------------------
  -100:  1001 1100
  -50:   1100 1110
  Carries: 1001 1100  (Carry-In to MSB C_7 = 0, Carry-Out C_8 = 1)
  Sum: 1 0110 1010 = +106 (MSB=0, Negative + Negative = Positive!)

Overflow Calculation:
  V = C_8 XOR C_7 = 1 XOR 0 = 1 (OVERFLOW ASSERTED!)

--------------------------------------------------------------------------------
4. HOW MODERN SOFTWARE HANDLES SIGNED OVERFLOW
--------------------------------------------------------------------------------
1. Assembly Branching: Conditional jumps test the OF flag:
   - x86: `JO` (Jump if Overflow) and `JNO` (Jump if Not Overflow).
   - ARM: `BVS` (Branch if Overflow Set) and `BVC` (Branch if Overflow Clear).
2. Hardware Exceptions: x86 `INTO` (Interrupt on Overflow) triggers vector 4.
3. Modern Languages:
   - Rust: In debug mode, automatically generates overflow trap panics.
   - C/C++ Built-ins: `__builtin_add_overflow(a, b, &res)` enables zero-overhead checking.
