1. EXECUTIVE OVERVIEW & MATHEMATICAL DEFINITION
--------------------------------------------------------------------------------
1's Complement is a signed binary representation where negative numbers are formed
by inverting every bit of their positive counterpart (transforming all 0s to 1s
and all 1s to 0s). Mathematically, for an n-bit binary number N, the 1's complement
is obtained by subtracting N from (2^n - 1) [a binary string of all 1s].

Formula:
  1's_Comp(N) = (2^n - 1) - N

In 1's Complement:
- Positive numbers start with MSB = 0 (identical to standard binary).
- Negative numbers start with MSB = 1 (bitwise NOT of positive binary).

--------------------------------------------------------------------------------
2. NUMERICAL RANGE & THE DUAL ZERO PROBLEM
--------------------------------------------------------------------------------
For an n-bit 1's Complement system:
- Positive Maximum: 0111...1111 = +(2^(n-1) - 1)
- Negative Minimum: 1000...0000 = -(2^(n-1) - 1)
- Total Range: [-(2^(n-1) - 1) to +(2^(n-1) - 1)]
- Total distinct numerical values = 2^n - 1

Range Examples:
  4-bit:  [-7 to +7]     (8-bit: [-127 to +127])
  16-bit: [-32,767 to +32,767]

DUAL ZERO IN 1'S COMPLEMENT:
  +0 = 0000 0000
  -0 = 1111 1111 (Bitwise inversion of +0)

--------------------------------------------------------------------------------
3. ARITHMETIC WITH 1'S COMPLEMENT & END-AROUND CARRY
--------------------------------------------------------------------------------
1's Complement enables subtraction using standard adder circuits by computing:
  A - B = A + 1's_Comp(B)

THE END-AROUND CARRY RULE (MANDATORY):
1. Add operand A and the 1's complement of B.
2. If an END CARRY is generated out of the MSB:
   - The result is POSITIVE.
   - The carry bit MUST be added back to the Least Significant Bit (LSB).
3. If NO END CARRY is generated:
   - The result is NEGATIVE.
   - The result is in 1's complement form; invert bits to find its magnitude.

--------------------------------------------------------------------------------
4. STEP-BY-STEP WORKED EXAMPLES
--------------------------------------------------------------------------------

EXAMPLE 1: Compute (+28) - (+15) using 8-Bit 1's Complement
--------------------------------------------------------------------------------
+28 = 00011100
+15 = 00001111 → 1's complement (-15) = 11110000

Addition:
    00011100  (+28)
  + 11110000  (-15 in 1's comp)
  ----------
  1 00001100  (End Carry = 1 out of MSB)

Add End-Around Carry to LSB:
    00001100
  +        1
  ----------
    00001101 = (+13)_10. Correct! (28 - 15 = 13)

EXAMPLE 2: Compute (+15) - (+28) using 8-Bit 1's Complement
--------------------------------------------------------------------------------
+15 = 00001111
+28 = 00011100 → 1's complement (-28) = 11100011

Addition:
    00001111  (+15)
  + 11100011  (-28 in 1's comp)
  ----------
    11110010  (No End Carry generated → Result is Negative)

Magnitude Check: Invert bits of 11110010 → 00001101 = 13 → Result is -13. Correct!

5. MODERN CRITICAL APPLICATION: INTERNET CHECKSUM (RFC 1071)
--------------------------------------------------------------------------------
Although 2's complement replaced 1's complement in CPU integer ALUs, 1's complement
addition with end-around carry remains the official algorithm for:
- IPv4 Packet Header Checksums
- TCP and UDP Checksums

WHY THE INTERNET USES 1'S COMPLEMENT CHECKSUMS:
1. Endianness Independence: The 1's complement sum of 16-bit words yields the exact
   same mathematical result whether calculated on a Big-Endian CPU (network order)
   or Little-Endian CPU (x86/ARM) without needing byte-swapping instructions!
2. Inverted Checksum Verification: A receiver can sum all packet words PLUS the
   checksum; if no error occurred, the sum is always all 1s (0xFFFF, negative zero).
