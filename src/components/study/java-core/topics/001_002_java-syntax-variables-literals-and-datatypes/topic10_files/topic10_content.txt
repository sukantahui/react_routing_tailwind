1. HISTORICAL CONTEXT & MOTIVATION
In early versions of Java (Java 1.0 through Java 6), numerical literals had to be written as uninterrupted sequences of digits. For example:
  long nationalDebt = 987654321000L;
  int subnetMask = 0b11111111111111111111111100000000;

When developers reviewed or debugged code with large numerical values, it was easy to miscount zeroes, resulting in off-by-an-order-of-magnitude bugs (e.g. charging ₹1,00,000 instead of ₹10,00,000).

In Java 7 (JSR 334 / Project Coin), the language introduced support for placing one or more underscores (`_`) anywhere between digits in numeric literals.

2. COMPILER & BYTECODE ARCHITECTURE
The underscore feature is purely syntactic sugar handled during the lexical analysis phase of the Java compiler (`javac`):
1. The scanner/lexer encounters an underscore between digits.
2. It strips the underscore character from the token stream.
3. The resulting numeric constant stored in the `.class` constant pool is completely identical to the uninterrupted numeric literal.
4. Consequence: Zero runtime CPU cycles, zero RAM penalty, and 100% backward binary compatibility.

3. GRAMMAR RULES & CONSTRAINTS (JLS §3.10)
Underscores can ONLY be placed BETWEEN DIGITS.
Specifically, underscores CANNOT appear:
1. At the beginning of a literal: `_100` (Parsed as a variable identifier, not a number)
2. At the end of a literal: `100_` (Syntax error: illegal underscore)
3. Adjacent to a decimal point: `3._14` or `3_.14` (Syntax error)
4. Adjacent to a type suffix: `1000_L` or `3.14_f` (Syntax error)
5. Inside or adjacent to a radix specifier: `0_x52`, `0x_52`, `0_b101`, `0b_101` (Syntax error)
6. Adjacent to exponent indicators: `1.5_e3` or `1.5e_3` (Syntax error)

4. PRACTICAL USE CASES
A. Indian Rupee Financial Amounts:
   Using Lakhs and Crores grouping (2, 2, 3 format):
   long barrackporeAnnualBudget = 25_00_000L;       // ₹25 Lakhs
   long kolkataInfrastructure = 500_00_00_000L;    // ₹500 Crores

B. Binary Masks and Network Protocols:
   Grouping by 4-bit nibbles or 8-bit bytes:
   byte ipFlags = (byte) 0b1010_0110;
   int classCSubnet = 0b11111111_11111111_11111111_00000000;

C. 32-bit Hexadecimal Color Codes:
   Grouping by RGBA / ARGB byte pairs:
   int brandColor = 0xFF_57_33_FF; // Alpha=FF, Red=57, Green=33, Blue=FF

D. Identification & Card Numbers:
   long debitCard = 4123_4567_8901_2345L;
   long aadhaar = 9876_5432_1098L;

5. COMMON PITFALL: STRING PARSING AT RUNTIME
A frequent trap for junior developers is expecting standard library string parsers to accept underscores:
  Integer.parseInt("1_000_000"); // THROWS NumberFormatException!
  Double.parseDouble("3.14_15"); // THROWS NumberFormatException!
  new BigDecimal("12_500.50");   // THROWS NumberFormatException!

To parse user-provided input with underscores, sanitize the string first:
  String cleanInput = userInput.replace("_", "");
  int value = Integer.parseInt(cleanInput);

6. CLASSROOM PEDAGOGY
In our Barrackpore center, Swadeep and Tuhina tested two versions of an inventory ledger for local merchants in Ichapur and Shyamnagar. When using raw `5000000` vs formatted `50_00_000` (₹50 Lakhs), code review times dropped by 70% and miscalculation errors were completely eliminated.
