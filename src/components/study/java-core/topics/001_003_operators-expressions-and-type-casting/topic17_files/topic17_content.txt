1. GRAMMAR OF PARENTHESIZED EXPRESSIONS (JLS §15.8.5)
Section 15.8.5 of the Java Language Specification (JLS) defines a Parenthesized Expression:
"A parenthesized expression is a primary expression whose type and value are identical to the type and value of the enclosed expression."

Parentheses alter the grouping structure of the Abstract Syntax Tree (AST) generated by the compiler:
- They explicitly force the enclosed sub-expression to be evaluated as a single unit before its parent operation executes.
- Because primary expressions sit at the pinnacle of the precedence table, parentheses override all default precedence and associativity rules.

2. EVALUATION ORDER GUARANTEE (JLS §15.7)
It is crucial to understand that parentheses do NOT alter Java's strict Left-to-Right operand evaluation guarantee:
In `(computeX() + computeY()) * computeZ()`:
1. `computeX()` evaluates first.
2. `computeY()` evaluates second.
3. The sum is calculated.
4. `computeZ()` evaluates third.
5. The product is calculated.

3. DEFENSIVE CODING PATTERNS USING PARENTHESES
A. String Concatenation Protection:
   `"Total: ₹" + (fee + tax)` forces arithmetic addition before string conversion.
B. Division Denominator Grouping:
   `val / (a * b)` ensures division by the composite product rather than dividing by `a` and multiplying by `b`.
C. Bitwise Isolation:
   `((flags & MASK) != 0)` isolates the bitwise operation from relational comparison.
D. Compound Boolean Clustering:
   `((isStudent && hasCard) || isSpecialGuest)` clearly delineates business logic.

4. COMPILER OPTIMIZATION & ZERO-OVERHEAD GUARANTEE
Parentheses exist solely in source code and during AST construction. Redundant parentheses (e.g. `(((a + b)))`) produce no additional bytecode instructions and incur ZERO memory or CPU execution overhead at runtime.
