1. GRAMMAR AND SEMANTICS OF COMPOUND ASSIGNMENTS
Java defines eleven compound assignment operators in Section 15.26.2 of the Java Language Specification (JLS):
- Arithmetic: `+=`, `-=`, `*=`, `/=`, `%=`
- Bitwise / Logical: `&=`, `|=`, `^=`
- Shift: `<<=`, `>>=`, `>>>=`

2. THE FORMAL JLS EQUIVALENCE THEOREM
A compound assignment expression `E1 op= E2` is equivalent to:
  E1 = (T)((E1) op (E2))
where `T` is the declared static type of `E1`, with the critical architectural caveat that `E1` is evaluated exactly once.

3. THE SINGLE-EVALUATION GUARANTEE & AVOIDANCE OF SIDE-EFFECTS
Consider an array element assignment where the index is determined by a method call with side effects:
  ledgerArray[getNextStudentIndex()] += 500.0;

If written using standard assignment:
  ledgerArray[getNextStudentIndex()] = ledgerArray[getNextStudentIndex()] + 500.0;
The method `getNextStudentIndex()` would be invoked twice, incrementing the internal pointer twice and corrupting two distinct student accounts!
With compound assignment (`+=`), the JVM evaluates `ledgerArray[getNextStudentIndex()]` once, saves the target reference and index on the operand stack, evaluates the right-hand side, and writes back to the exact same cell.

4. PRECEDENCE & ISOLATION OF THE RIGHT-HAND OPERAND
In an expression of the form `x *= y + z`, the binary addition `y + z` is fully evaluated before the multiplication assignment takes place:
  x = (type)(x * (y + z));
This eliminates precedence confusion when mixing multiplicative compound assignments with additive right-hand expressions.
