1. THE SHORT-CIRCUIT EVALUATION PRINCIPLE
Sections 15.23 and 15.24 of the Java Language Specification (JLS) define the conditional operators `&&` and `||` as short-circuiting control constructs:
- Conditional-AND (`&&`): The left-hand operand expression is evaluated first. If the result is `false`, the value of the conditional-AND expression is `false` and the right-hand operand expression is NOT evaluated.
- Conditional-OR (`||`): The left-hand operand expression is evaluated first. If the result is `true`, the value of the conditional-OR expression is `true` and the right-hand operand expression is NOT evaluated.

2. DEFENSIVE GUARD ARCHITECTURES
Short-circuit evaluation is the foundational mechanism for safe programming in Java:
A. Defensive Null-Guard Pattern:
   `if (student != null && student.hasClearedFees())`
   If `student` is `null`, evaluation immediately short-circuits. The JVM never invokes `hasClearedFees()` on a null reference, preventing `NullPointerException`.
B. Array Bounds Guard:
   `if (index >= 0 && index < array.length && array[index] == target)`
   Guarantees that `array[index]` is only evaluated when `index` is strictly within valid bounds, preventing `ArrayIndexOutOfBoundsException`.
C. Arithmetic Division Guard:
   `if (divisor != 0 && (total / divisor > threshold))`
   Guarantees that division is only evaluated when `divisor` is non-zero, preventing `ArithmeticException: / by zero`.

3. THE SIDE-EFFECT PARADOX & CRITICAL HAZARDS
When expressions contain side-effects (e.g. `++counter`, method calls that mutate databases, networks, or file systems), short-circuiting causes non-deterministic behavior:
- `boolean b = (x > 10) && (++x > 0);`
  If `x` is 5, `x > 10` evaluates to `false`, and `++x` is NEVER executed. `x` remains 5.
- `if (isUserAdmin || chargeCreditCard())`
  If the user is an admin, `chargeCreditCard()` is NEVER executed!

Production Design Rule: Keep conditional expressions pure and side-effect free. Execute actions beforehand and test boolean result variables.

4. COMPILER BYTECODE BRANCH JUMPS
In bytecode disassembly:
- `&&` maps to the `ifeq` instruction, branching past the right operand code directly to the false target block.
- `||` maps to the `ifne` instruction, branching directly to the true target block.
This hardware-level branch jumping provides maximum execution throughput.
