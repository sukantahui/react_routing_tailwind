1. THE COMPILATION PARADOX & JLS SPECIFICATION
One of the most frequent surprises for Java developers is the difference between standard arithmetic assignment and compound assignment:
  byte b = 5;
  b = b + 2; // FAILS TO COMPILE
  b += 2;     // COMPILES CLEANLY

Section 15.26.2 of the Java Language Specification (JLS) establishes that:
"A compound assignment expression of the form `E1 op= E2` is equivalent to `E1 = (T)((E1) op (E2))`, where `T` is the type of `E1`."

In the first snippet, `b + 2` undergoes Binary Numeric Promotion, promoting `b` to `int`. Assigning a 32-bit `int` result back to an 8-bit `byte` variable violates Java's static type safety without an explicit cast.
In the second snippet, the Java compiler automatically synthesizes an explicit narrowing cast: `b = (byte)(b + 2)`.

2. THE SILENT OVERFLOW HAZARD & TWO'S COMPLEMENT WRAP-AROUND
Because the narrowing cast is inserted automatically by the compiler, the developer receives ZERO warnings when arithmetic overflows:
- Byte Overflow:
  `byte b = 127; b += 1;`
  Evaluates to `(byte)(128)`. Since `128` exceeds the maximum signed 8-bit value (`+127`), its binary representation `10000000` is interpreted as `-128` (`Byte.MIN_VALUE`).
- Short Overflow:
  `short s = 32767; s += 1;` → Wraps to `-32768`.
- Higher Bit Discard:
  `byte b = 100; b += 300;` → `(byte)(400)`. `400` in binary is `0x0190`. Discarding the upper 24 bits leaves `0x90` (`-112`).

3. FLOATING-POINT DECIMAL TRUNCATION (INT += DOUBLE)
When applying compound assignment across mixed numeric domains:
  int balance = 15000;
  balance += 2700.85; // Desugars to: balance = (int)(balance + 2700.85);

The addition occurs in 64-bit IEEE 754 floating-point format (`17700.85`), but the `(int)` narrowing cast completely discards the decimal fraction (`0.85`), storing `17700`.
In financial and accounting software (Indian Rupees ₹), this causes subtle data loss and rounding discrepancies if not handled with `BigDecimal`.

4. BYTECODE LEVEL IMPLEMENTATION
At the JVM instruction level:
1. `b += 2` loads the byte as an int with `iload`.
2. Adds the integer constant with `iadd`.
3. Truncates the 32-bit integer on top of the operand stack back to 8 bits using the `i2b` (int to byte) instruction.
4. Stores the truncated byte into local variable storage with `istore`.
