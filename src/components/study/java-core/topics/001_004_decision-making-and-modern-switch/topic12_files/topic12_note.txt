1. CORE CONCEPTS & RULES
--------------------------------------------------------------------------------
- The Zero Fall-Through Rule (JLS §14.11.2):
  * When using Arrow Syntax (case X → Y), execution completes as soon as the
    expression or block to the right of '->' completes.
  * Fall-through into subsequent cases is IMPOSSIBLE by grammar design!

- Security & Quality Benefits:
  * Eliminates accidental missing-break security vulnerabilities (e.g. STUDENT
    falling through into SYSTEM_ADMIN code).
  * No need for 'break;' statements inside arrow branches ('break;' is illegal).
  * No compiler warnings (-Xlint:fallthrough) or @SuppressWarnings annotations.

- Multi-Case Code Sharing (No Stacking Needed):
  * In traditional switch: required stacked cases with fall-through (case 1: case 2: ...)
  * In modern arrow switch: use comma-separated lists (case 1, 2, 3 → doAction();)

- Scoping Independence:
  * Each arrow branch has an isolated block scope. Variables declared in one
    case cannot collide with variables in another case.

2. ESSENTIAL CHECKLIST
--------------------------------------------------------------------------------
[✓] Standardize on arrow syntax to prevent accidental fall-through bugs.
[✓] Use comma-separated lists (case 1, 2 ->) to share code across cases.
[✓] Do not write 'break;' inside arrow rules (causes compilation error).
[✓] Enjoy clean, decoupled, unit-testable switch branches.
