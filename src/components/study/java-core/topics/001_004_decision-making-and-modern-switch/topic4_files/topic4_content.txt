1. GRAMMAR AND SYNTACTIC SUGAR OF THE ELSE-IF LADDER
In the Java Language Specification (JLS §14.9), an `else-if` ladder is not a separate keyword or unique grammatical structure; rather, it is an `if-else` statement where the `else` branch contains another `if-else` statement.
The standard formatting:
  if (c1) { s1; }
  else if (c2) { s2; }
  else { s3; }
is syntactically equivalent to:
  if (c1) {
      s1;
  } else {
      if (c2) {
          s2;
      } else {
          s3;
      }
  }
The standard unnested formatting provides immense visual clarity, flattening what would otherwise be a deeply indented pyramid into a linear decision sequence.

2. SEQUENTIAL SHORT-CIRCUIT EVALUATION AND SHADOWING
Because the ladder is evaluated sequentially from top to bottom:
- Branch Starvation / Shadowing occurs if a broader condition precedes a narrower condition.
For example:
  if (score >= 50) { pass(); }
  else if (score >= 90) { honors(); } // DEAD BRANCH!
Any score $\ge 90$ is already $\ge 50$, satisfying the first condition and immediately exiting the ladder.
To guarantee mathematical correctness, range boundaries must strictly descend (or ascend when evaluating upper bounds).

3. BYTECODE DECOMPILATION: CASCADE OF CONDITIONAL JUMPS
When compiled, the JVM translates an `else-if` ladder into a series of inverted conditional jump instructions (`if_icmplt`, `ifeq`) targeting subsequent branch labels, with each branch body ending in an unconditional `goto` pointing to the common termination label (`L_EXIT`).
Worst-Case Time Complexity: $O(N)$ comparisons.

4. REAL-WORLD FINANCIAL MODELING: INCOME TAX SLABS (NEW REGIME)
In financial software in India (₹), tax liability is calculated across progressive slabs:
- ₹0 to ₹3,00,000 : 0%
- ₹3,00,001 to ₹6,00,000 : 5%
- ₹6,00,001 to ₹9,00,000 : 10%
- ₹9,00,001 to ₹12,00,000 : 15%
- ₹12,00,001 to ₹15,00,000 : 20%
- Above ₹15,00,000 : 30%
An `else-if` ladder allows clean progressive threshold categorization.
