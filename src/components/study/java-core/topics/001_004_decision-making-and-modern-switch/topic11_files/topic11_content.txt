1. JEP 361 AND THE EVOLUTION OF SWITCH IN JAVA
For over two decades (Java 1.0 to Java 11), Java's `switch` was solely a control-flow statement inherited from C/C++, fraught with accidental fall-through bugs and excessive boilerplate.
JEP 361 (standardized in Java SE 14 under JLS §14.11 and §15.28) redesigned switch into a modern, dual-form construct:
1. Switch Statement (executes side-effect actions)
2. Switch Expression (evaluates and yields a single value to an enclosing context)

2. GRAMMAR AND SYNTACTIC RULES OF ARROW SYNTAX
In arrow syntax:
  SwitchLabeledRule:
    case CaseConstantList -> Expression ;
    case CaseConstantList -> Block
    case CaseConstantList -> ThrowStatement
    default -> Expression ;
    default -> Block
    default -> ThrowStatement

A. Elimination of Fall-Through:
   By formal definition, the execution of a `SwitchLabeledRule` completes as soon as the expression, block, or throw statement to the right of `->` completes. Control immediately exits the switch.

B. Lexical Block Scoping:
   Unlike traditional colon switches where the entire switch forms a single scope, each arrow rule forms an independent lexical scope:
     case A -> { int x = 10; }
     case B -> { int x = 20; } // 100% Legal! No name collision!

3. EXHAUSTIVENESS AND COMPILE-TIME SOUNDNESS
A Switch Expression must be exhaustive: every possible value of the selector type must be matched by a case label or a `default` label.
- When switching on an enum, if all enum constants are explicitly handled, `default` is optional.
- If a new constant is added to the enum later, the compiler immediately produces an exhaustiveness error, alerting developers to update the switch expression!

4. IMMUTABILITY AND FUNCTIONAL PROGRAMMING ALIGNMENT
Because switch expressions evaluate directly to a value, variables can be declared `final` at the point of declaration:
  final int tuition = switch (track) {
      case JAVA_CORE -> 15000;
      case SPRING_BOOT -> 22000;
      default -> 10000;
  };
This eliminates mutable temporary variables and aligns Java code with functional programming best practices.
