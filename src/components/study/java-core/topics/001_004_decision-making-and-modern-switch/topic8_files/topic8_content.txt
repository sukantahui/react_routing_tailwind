1. GRAMMAR AND SEMANTICS OF DEFAULT LABELS (JLS §14.11)
Section 14.11 of the Java Language Specification (JLS) establishes that a `SwitchBlock` may contain zero or one `default` label:
  SwitchLabel:
    case ConstantExpression :
    default :

Execution Semantics:
1. The selector expression is evaluated to value $V$.
2. The runtime compares $V$ against all `case` constants.
3. If a matching constant is found, execution transfers directly to that `case` label.
4. If NO matching constant is found, and a `default` label is present, execution transfers directly to the `default` label.
5. If NO matching constant is found and NO `default` label is present, the switch statement completes immediately.

2. THE TOP/MIDDLE DEFAULT PLACEMENT TRAP
Because the compiler transfers control directly to `default` only when all cases fail:
- The physical position of `default` does NOT change the fact that matching `case` labels take precedence.
- HOWEVER, once control enters `default`, standard sequential fall-through applies.
If `default` is placed at the top of the block and omits `break;`, execution will cascade into the first `case` label, executing its body.
Architectural Mandate: Always place `default` at the bottom of the switch block.

3. DEFINITE ASSIGNMENT AND EXHAUSTIVENESS (JLS §16)
When assigning a local variable inside switch branches:
  int code;
  switch (day) {
      case "MON": code = 1; break;
      case "TUE": code = 2; break;
      default:    code = 0; break;
  }
Without the `default` block, the compiler cannot prove that `code` is assigned on every execution path, rejecting subsequent reads of `code` with a compile-time error. Adding `default` satisfies Definite Assignment analysis.

4. DEFENSIVE PROGRAMMING: FAILING FAST ON UNKNOWN INPUTS
In enterprise domain modeling, receiving an unhandled selector value is frequently a symptom of an upstream software defect or corrupt payload.
Instead of silently ignoring or swallowing the error:
  default → throw new IllegalArgumentException("Unsupported command code: " + code);
This enforces the Fail-Fast Principle, preventing corrupted states from persisting in databases.
