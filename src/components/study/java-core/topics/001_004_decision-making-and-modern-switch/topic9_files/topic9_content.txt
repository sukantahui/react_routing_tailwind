1. THEORETICAL AND COMPILER-LEVEL COMPARISON
When choosing between `switch` and an `else-if` ladder, developers balance two fundamental dimensions:
A. Expressive Capability:
   - `else-if` can express any Turing-complete boolean expression involving multiple variables, relational operators (`<`, `<=`, `>`, `>=`), logical operators (`&&`, `||`, `!`), and arbitrary object methods.
   - `switch` is constrained to exact equality matching of a single selector expression against compile-time constants.

B. Bytecode Compilation and CPU Pipeline Architecture:
   - `else-if` translates to a chain of conditional jumps (`ifeq`, `if_icmplt`). Each branch incurs a branch prediction cost. Worst-case evaluation requires $O(N)$ comparisons.
   - `switch` compiles to specialized JVM jump table instructions:
     1. `tableswitch`: Emitted when case values are contiguous or dense. Computes the jump destination directly as `table[key - low]` in $O(1)$ constant time.
     2. `lookupswitch`: Emitted when case values are sparse. Performs an $O(\log N)$ binary search over sorted integer keys in bytecode.

2. COGNITIVE COMPLEXITY AND MAINTAINABILITY
When evaluating a single variable against 4 or more discrete values:
- An `else-if` ladder repeats the variable name and comparison operator (`if (opt == 1) ... else if (opt == 2) ...`), increasing visual noise and susceptibility to typographical bugs.
- A `switch` statement encapsulates the selector once at the header and presents an aligned, tabular list of cases, vastly improving cognitive readability.

3. PERFORMANCE BENCHMARKING NUANCES
In micro-benchmarks with 10+ branches:
- `tableswitch` consistently achieves sub-nanosecond direct dispatch times.
- `else-if` chains exhibit linear degradation as matching cases move deeper down the ladder.
However, for 2 or 3 branches, modern CPU branch predictors (such as TAGE predictors on modern x86/ARM architectures) achieve $>95\%$ prediction accuracy, making the performance difference negligible.

4. MODERN JAVA 14+ SWITCH EXPRESSIONS AS THE SYNTHESIS
Modern Java 14+ switch expressions resolve historical complaints against switch (verbose syntax, accidental fall-through) by providing:
  final int fee = switch (courseCode) {
      case "JAVA" -> 15000;
      case "SPRING" -> 22000;
      default -> 10000;
  };
This provides the safety of functional expressions combined with $O(1)$ jump table performance.

5. CLASSROOM PEDAGOGY IN BARRACKPORE
In our Barrackpore laboratory, Swadeep, Tuhina, Abhronila, and Debangshu benchmarked a high-frequency course admission and tuition rate lookup engine in Indian Rupees (₹). Comparing `tableswitch` against an 8-stage `else-if` ladder across 1,000,000 iterations, their benchmarks proved that `tableswitch` achieved 3.5x higher throughput with zero branch pipeline stalls across servers in Naihati and Shyamnagar.
