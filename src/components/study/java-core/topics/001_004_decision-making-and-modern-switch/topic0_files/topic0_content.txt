1. FOUNDATIONS OF CONTROL FLOW AND THE BÖHM-JACOPINI THEOREM
Control flow represents the path that the Java Virtual Machine's execution thread follows through the bytecode instructions of a program.
In 1966, Italian mathematicians Corrado Böhm and Giuseppe Jacopini published the Structured Programming Theorem, proving that any computable algorithm can be expressed using three canonical control structures:
1. Sequence: Linear execution where instruction $I_{n+1}$ immediately succeeds $I_n$.
2. Selection (Branching): Choosing between two or more execution paths based on a boolean predicate.
3. Iteration (Repetition): Executing an instruction block repeatedly while a condition remains true.

2. HARDWARE CPU AND JVM BYTECODE MECHANICS
At the hardware level, a CPU contains a Program Counter (PC) register that holds the memory address of the next instruction to fetch and execute:
- Under sequential flow, the PC increments automatically by the instruction byte length.
- Under conditional branching, the JVM emits conditional jump instructions:
  * `ifeq` (Branch if value is 0 / false)
  * `ifne` (Branch if value is non-zero / true)
  * `if_icmpeq`, `if_icmpne`, `if_icmpgt`, `if_icmplt` (Integer comparison branches)
  * `tableswitch` (Dense $O(1)$ indexed jump table for switch statements)
  * `lookupswitch` (Sparse $O(\log N)$ binary search table for switch statements)

3. CLASSIFICATION OF DECISION-MAKING IN JAVA
Java provides a rich hierarchy of selection mechanisms:
A. The `if` and `if-else` family:
   Evaluates dynamic boolean expressions with short-circuit evaluation.
B. The traditional `switch` statement:
   Matches discrete integral, string, or enum constants, governed by manual `break` control and fall-through behavior.
C. Modern Java 14+ Switch Expressions:
   Functional, value-producing expressions using arrow syntax (`case X → Y`), multiple labels, and the `yield` keyword, eliminating accidental fall-through bugs.

4. CLEAN CODE ARCHITECTURE: GUARD CLAUSES VS DEEP NESTING
In enterprise software engineering, deeply nested `if-else` blocks (the "Arrow Anti-Pattern" or "Pyramid of Doom") drastically elevate Cyclomatic Complexity, rendering code difficult to unit-test.
Best Practice: Implement Guard Clauses (early exits/returns) at the beginning of methods to validate preconditions, flattening the execution structure.
