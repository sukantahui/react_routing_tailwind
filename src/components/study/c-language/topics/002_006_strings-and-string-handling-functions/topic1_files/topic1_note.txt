1. THE DANGER OF GETS() (CWE-120: BUFFER OVERFLOW)
--------------------------------------------------------------------------------
- `gets(str)` does NOT take a buffer capacity limit.
- If a user inputs 100 characters into `char str[10]`, it overwrites stack
  memory, causing system crashes and severe security exploits.
- `gets()` was permanently REMOVED from the ISO C standard in C11!

2. THE SAFE REPLACEMENT: FGETS()
--------------------------------------------------------------------------------
- Signature: `char *fgets(char *str, int num, FILE *stream);`
- Usage for Console:
    char name[50];
    fgets(name, sizeof(name), stdin);
- Note: `fgets()` captures the trailing newline `\n`.
  Sanitize with: `name[strcspn(name, "\n")] = '\0';`

3. SCANF LIMITATIONS & BOUNDED SPECIFIERS
--------------------------------------------------------------------------------
- `scanf("%s", str)`: Stops reading at first whitespace (cannot read full names).
- Bounded Width Specifier: `scanf("%29s", str);` (Prevents buffer overflow).
- Scanset Specifier: `scanf(" %49[^\n]", str);` (Reads full line with spaces).

4. INPUT STREAM FLUSHING (STDIN)
--------------------------------------------------------------------------------
- NEVER use `fflush(stdin)` (Undefined Behavior in ISO C).
- Standard Flush Idiom:
    int c;
    while ((c = getchar()) != '\n' && c != EOF);

5. SECURITY CHECKLIST
--------------------------------------------------------------------------------
[✓] Always prefer `fgets()` over `scanf("%s")`.
[✓] Always remove trailing `\n` after `fgets()`.
[✓] Use `snprintf()` instead of unsafe `sprintf()`.
[✓] Never write `printf(userInput);` (Format string exploit). Use `printf("%s", userInput);`.
