1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Remember the BODMAS or PEMDAS rule from your childhood school mathematics? In 2 + 3 * 4, you do the multiplication first (3 * 4 = 12) and then the addition (2 + 12 = 14), unless you use parentheses: (2 + 3) * 4 = 20. JavaScript has an exact ranking table called Operator Precedence that decides which operator runs first!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Abhronila wrote a condition: let result = false && true || true; She wondered: 'Does it evaluate (false && true) first, or (true || true) first?' I showed the class how && has a higher precedence ranking than ||. So JavaScript evaluated (false && true) → false, and then false || true → true. I told the class: 'Never force your teammates to memorize 20 precedence levels. Always use explicit parentheses ( ... ) to make your logic unmistakable!'

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Operator Precedence:
Determines the order in which different operators are evaluated in an expression.
Highest Precedence:
1. Grouping: ( ... )
2. Member Access & Invocations: obj.prop, fn()
3. Unary operators: ++, --, !, typeof, +
4. Exponentiation: **
5. Multiplication & Division: *, /, %
6. Addition & Subtraction: +, -
7. Comparisons: <, <=, >, >=
8. Equality: ===, !==
9. Logical AND: &&
10. Logical OR: ||, ??
11. Ternary: ? :
12. Assignment: =, +=, -=
Lowest Precedence

2. Associativity (Left-to-Right vs Right-to-Left):
- Most operators (like +, -, *, /) are Left-to-Right: 10 - 5 - 2 becomes (10 - 5) - 2 = 3.
- Exponentiation (**) and Assignment (=) are Right-to-Left: 2 ** 3 ** 2 becomes 2 ** (3 ** 2) = 2 ** 9 = 512.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Clear Intent with Parentheses ---
// Ambiguous and hard to read:
let confusing = 5 + 10 * 2 > 20 && 3 === 3;

// Clean, explicit grouping with parentheses:
let clear = ((5 + (10 * 2)) > 20) && (3 === 3);
console.log("Result:", clear); // true

Teacher's Note on Example 1:
Parentheses eliminate ambiguity and guarantee that calculations happen in your intended order.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Assuming left-to-right for everything: Exponentiation (**) and assignment (=) evaluate right-to-left.

[!] Writing un-parenthesized complex conditions: Group related conditions with ( ) so code is readable and bug-free.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Operator precedence dictates execution hierarchy (like BODMAS in math).
• Logical && has higher precedence than || and ??.
• Always use parentheses ( ... ) to explicitly document your intent.
