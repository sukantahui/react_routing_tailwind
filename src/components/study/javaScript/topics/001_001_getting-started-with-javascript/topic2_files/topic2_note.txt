1. TOPIC OVERVIEW & DETAILED CONCEPT DISCUSSION
--------------------------------------------------------------------------------
- The Web Platform Triad:
  1. HTML (HyperText Markup Language): The structural skeleton defining elements, 
     semantics, forms, tables, and document hierarchies.
  2. CSS (Cascading Style Sheets): The presentation layer defining colors, typography, 
     flexbox/grid layouts, responsive breakpoints, and animations.
  3. JavaScript: The dynamic behavioral engine intercepting user interactions, mutating 
     the DOM/CSSOM trees, handling business logic, and fetching data over network streams.
- The Critical Rendering Path (CRP):
  * Step 1: HTML bytes → Tokens → Nodes → DOM (Document Object Model) Tree.
  * Step 2: CSS bytes → Tokens → Nodes → CSSOM (CSS Object Model) Tree.
  * Step 3: DOM + CSSOM are combined into the Render Tree (visible elements only).
  * Step 4: Layout (Reflow) calculates precise geometry (x, y, width, height) of each box.
  * Step 5: Paint (Rasterization) fills pixels with colors, borders, images, and text.
  * Step 6: Composite merges distinct GPU layers onto the physical display.

2. IN-DEPTH TECHNICAL KNOW-HOW & ENGINE RUNTIME MECHANICS
--------------------------------------------------------------------------------
- Script Loading Mechanics:
  * Default (<script src="app.js">): HTML parser pauses immediately, downloads the script, 
    compiles and executes it, and only then resumes HTML parsing.
  * Defer (<script src="app.js" defer>): Downloads in parallel with HTML parsing. 
    Executes in guaranteed document order immediately after HTML parsing completes 
    (before DOMContentLoaded).
  * Async (<script src="app.js" async>): Downloads in parallel with HTML parsing. 
    Executes the exact moment download completes (can execute out of order).
- Layout Thrashing (Forced Synchronous Layout):
  Occurs when JS queries layout geometry (e.g. offsetHeight, getBoundingClientRect) 
  immediately after modifying DOM styles, forcing the browser to compute Layout on the fly.

3. EXCEPTIONS, CORNER CASES, COERCIONS & QUIRKS
--------------------------------------------------------------------------------
[!] TypeError: Cannot read properties of null (reading 'addEventListener'): 
    Thrown when a script placed in the HTML <head> attempts to access DOM elements 
    before the parser has constructed them. Fix with 'defer' or 'DOMContentLoaded'.
[!] Flash of Unstyled Content (FOUC): Caused by executing DOM/CSS mutations after the 
    initial paint.
[!] CSS Specificity Collisions: JS inline styles (element.style.color = "red") possess 
    higher specificity than external CSS classes, making them difficult to override.

4. 💎 SPECIAL LANGUAGE FEATURES & SENIOR PRO SECRETS
--------------------------------------------------------------------------------
- CSS Houdini Typed OM: Bypasses string-based style manipulation using CSSUnitValue 
  (e.g., el.attributeStyleMap.set('opacity', CSS.number(0.5))), boosting animation performance.
- CSS Custom Property Reactivity: Mutate CSS variables directly in JS via 
  document.documentElement.style.setProperty('--primary-color', '#f59e0b') for zero-reflow theming.
- DocumentFragment Batching: Assemble multiple DOM elements in an off-screen fragment 
  before appending to the live document, reducing reflows to exactly 1.

5. PRACTICAL ENTERPRISE USE-CASES & CODE EXAMPLES
--------------------------------------------------------------------------------
Example 1: Safe DOM Access with DOMContentLoaded
document.addEventListener("DOMContentLoaded", () => {
  const btn = document.getElementById("submit-btn");
  btn.addEventListener("click", () => console.log("Submitted"));
});

Example 2: Batch DOM Injection via DocumentFragment
const fragment = document.createDocumentFragment();
["Swadeep", "Tuhina", "Abhronila"].forEach(name => {
  const li = document.createElement("li");
  li.textContent = name;
  fragment.appendChild(li);
});
document.getElementById("student-list").appendChild(fragment);

Example 3: CSS Variable Dynamic Theming
function setAccentTheme(hexColor) {
  document.documentElement.style.setProperty("--accent-theme", hexColor);
}

Example 4: Preventing Layout Thrashing
// Batch all reads first
const heights = cards.map(c => c.offsetHeight);
// Batch all writes
cards.forEach((c, i) => c.style.height = `${heights[i] + 10}px`);

Example 5: ClassList Toggle for State-Driven CSS
function toggleModal(isOpen) {
  const modal = document.getElementById("auth-modal");
  modal.classList.toggle("opacity-100", isOpen);
  modal.classList.toggle("pointer-events-none", !isOpen);
}

7. INTERVIEW & VIVA QUICK-FIRE KNOWLEDGE POINTS
--------------------------------------------------------------------------------
Q1: What is the difference between Reflow (Layout) and Repaint?
A1: Reflow recalculates the geometric dimensions and positions of elements on the page; 
    Repaint redraws pixels (colors, visibility, backgrounds) without altering geometry.

Q2: Why should scripts generally use the 'defer' attribute?
A2: 'defer' allows HTML parsing to complete without blocking, executes scripts in guaranteed 
    order, and ensures the DOM is fully constructed before script evaluation.

Q3: What causes 'Layout Thrashing' and how do you fix it?
A3: Alternating between reading layout properties (offsetWidth) and writing styles (style.width) 
    in a loop; fix by batching all reads first, then batching all writes.

Q4: What is the DOM and CSSOM?
A4: DOM (Document Object Model) is the tree representation of HTML elements; CSSOM is the tree 
    representation of CSS rules and computed cascade styles.
