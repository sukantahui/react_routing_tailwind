1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Imagine you are baking a cake following a recipe book. If you have to stop every 2 minutes to run down the street to the grocery store to fetch an ingredient, your baking stops completely until you return. In web pages, when the browser encounters a script tag, it stops reading HTML to fetch and execute that script. How we connect our script determines whether our webpage feels lightning fast or painfully slow!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Abhronila was building her first portfolio page. She placed a huge external script right at the very top inside the <head> tag. When she opened the page on a mobile connection, the screen stayed completely blank white for 4 seconds before any text appeared! She asked, 'Sir, why is my page loading so slowly?' I showed the class how the browser parses HTML line by line from top to bottom. When it hit the script tag in the <head>, it froze the HTML parser until the script downloaded. We added the 'defer' keyword, and instantly the page text rendered without a single millisecond of delay.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Three Ways to Write JavaScript in Webpages:
a) Inline JavaScript: Placed directly inside HTML element attributes (e.g. onclick="alert('Hi')"). (Avoid in modern code as it mixes logic with structure).
b) Internal Script: Written inside a <script> tag inside your HTML document. (Great for quick tests and small exercises).
c) External Script: Written in a separate .js file and linked using <script src="app.js">. (The professional industry standard).

2. The Head vs Body Dilemma:
If you place scripts at the bottom before </body>, the browser reads all HTML first, so users see the page immediately.

3. Modern Loading Attributes for <script>:
- Normal <script src="...">: Blocks HTML parsing while downloading and executing.
- <script async src="...">: Downloads in parallel in the background, but executes IMMEDIATELY as soon as downloaded, which pauses HTML parsing at that moment. (Use for independent scripts like analytics).
- <script defer src="...">: Downloads in parallel in the background, but WAITS until the entire HTML document is fully parsed before executing in exact order. (The best practice for application scripts!).

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Using async when scripts depend on each other: 'async' scripts execute in whichever order they finish downloading, which can cause 'undefined variable' errors if script B loads before script A.

[!] Placing un-deferred heavy scripts in the <head>: This creates a render-blocking delay where users see a blank screen.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• External .js files keep your code organized, reusable, and clean.
• Use 'defer' for standard application scripts that need HTML elements to exist first.
• Use 'async' only for independent third-party scripts (like Google Analytics).
