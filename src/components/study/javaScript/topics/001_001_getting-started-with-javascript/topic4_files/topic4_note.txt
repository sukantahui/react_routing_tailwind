1. TOPIC OVERVIEW & DETAILED CONCEPT DISCUSSION
--------------------------------------------------------------------------------
- Execution Pathways for JavaScript:
  1. Browser DevTools Console: A live REPL (Read-Eval-Print-Loop) for testing statements, 
     inspecting DOM elements, and debugging runtime states instantly.
  2. Inline Scripts (<script> ... </script>): Embedding executable JS code directly inside 
     the HTML document body or head.
  3. External Scripts (<script src="app.js"></script>): Referencing separate .js source 
     files stored on disk or CDNs, allowing browser caching and clean separation of concerns.
  4. ES Modules (<script type="module" src="main.js">): Modern JavaScript module systems 
     supporting native 'import' and 'export' syntax with strict mode enabled by default.

2. IN-DEPTH TECHNICAL KNOW-HOW & ENGINE RUNTIME MECHANICS
--------------------------------------------------------------------------------
- Script Parsing & Execution Lifecycle:
  * Document Parsing Interruption: In classic <script>, the HTML parser halts completely 
    while the browser fetches and executes the script.
  * Scope Isolation:
    - Classic scripts pollute the global 'window' namespace with var declarations and 
      top-level function names.
    - ES Modules (type="module") possess their own file-level lexical scope; variables 
      never leak into the global window object.
  * Execution Context Stack: Top-level scripts create the Global Execution Context (GEC), 
    allocating global lexical environments and binding variables.

3. EXCEPTIONS, CORNER CASES, COERCIONS & QUIRKS
--------------------------------------------------------------------------------
[!] TypeError: Cannot read properties of null: Occurs when a script in <head> queries 
    DOM elements before the HTML parser has built the <body>. Fix: Use 'defer'.
[!] CORS block on file:// with ES Modules: <script type="module"> cannot load local files 
    when opened directly from file explorer. Fix: Launch with Live Server (HTTP).
[!] Console Persistence: Code run in the DevTools Console is temporary and vanishes 
    upon page reload unless preserved via DevTools Local Overrides.

4. 💎 SPECIAL LANGUAGE FEATURES & SENIOR PRO SECRETS
--------------------------------------------------------------------------------
- Dynamic import() Function: Dynamically load JavaScript modules on demand at runtime 
  (e.g., const { chart } = await import('./chart.js')) for massive bundle size reductions.
- DevTools $_ and $0 Magic: In the Console tab, $_ returns the value of the last evaluated 
  expression, and $0 references the currently inspected DOM node.
- Script nomodule Fallback: Provide modern bundles to modern browsers (<script type="module">) 
  and legacy bundles (<script nomodule>) to older browsers seamlessly.

5. PRACTICAL ENTERPRISE USE-CASES & CODE EXAMPLES
--------------------------------------------------------------------------------
Example 1: Dynamic Script Injection
function injectScript(url) {
  return new Promise((resolve, reject) => {
    const script = document.createElement("script");
    script.src = url;
    script.onload = () => resolve(`Loaded ${url}`);
    script.onerror = () => reject(new Error(`Failed to load ${url}`));
    document.head.appendChild(script);
  });
}

Example 2: ES Module Import / Export
// mathUtils.js:
export const add = (a, b) => a + b;
// app.js:
import { add } from "./mathUtils.js";
console.log("Sum:", add(10, 20));

Example 3: Safe DOM Ready Listener
if (document.readyState === "loading") {
  document.addEventListener("DOMContentLoaded", initApp);
} else {
  initApp();
}

Example 4: DevTools Console Tabular Profiling
const students = [
  { name: "Swadeep", lab: "Barrackpore", grade: "A+" },
  { name: "Tuhina", lab: "Naihati", grade: "A+" }
];
console.table(students, ["name", "grade"]);

Example 5: Modern Dynamic Import with Async/Await
async function loadAnalytics() {
  const module = await import("./analytics.js");
  module.trackPageView("/home");
}

7. INTERVIEW & VIVA QUICK-FIRE KNOWLEDGE POINTS
--------------------------------------------------------------------------------
Q1: What are the advantages of external script files over inline scripts?
A1: External files enable browser HTTP caching, clean separation of concerns, easier 
    code maintenance, and reuse across multiple HTML pages.

Q2: How do ES Modules (<script type="module">) differ from classic scripts?
A2: ES Modules are scoped to the file (no global pollution), execute in strict mode by default, 
    support import/export, and are deferred automatically without blocking HTML parsing.

Q3: What is the DevTools Console REPL?
A3: Read-Eval-Print-Loop: It reads the user's input expression, evaluates it via the V8 engine, 
    prints the result to the console, and loops waiting for the next input.

Q4: What happens if an external script fails to load (404 error)?
A4: The browser fires an 'error' event on the script tag, logs a 404 network error in the Console, 
    and halts execution of that script without crashing other independent scripts.
