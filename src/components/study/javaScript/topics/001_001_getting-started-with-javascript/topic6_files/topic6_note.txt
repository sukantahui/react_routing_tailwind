1. TOPIC OVERVIEW & DETAILED CONCEPT DISCUSSION
--------------------------------------------------------------------------------
- Purpose: Introduced in ECMAScript 5 (ES5), Strict Mode ('use strict') opts into a 
  restricted, safer variant of JavaScript that converts silent bugs into explicit exceptions, 
  prevents accidental global variable leaks, secures 'this' binding, and allows JavaScript 
  engines to perform aggressive TurboFan JIT compiler optimizations.
- Activation Scopes:
  1. Entire Script Level: Placing "use strict"; at the very top of a classic script.
  2. Function Level: Placing "use strict"; inside a specific function body.
  3. Automatic Strict Mode: ES6 Modules (<script type="module">) and ES6 Classes (class {}) 
     execute in Strict Mode by default automatically.

2. IN-DEPTH TECHNICAL KNOW-HOW & ENGINE RUNTIME MECHANICS
--------------------------------------------------------------------------------
- What Strict Mode Enforces at Engine Level:
  1. Eliminates Accidental Global Leaks: Assigning to an undeclared identifier throws 
     ReferenceError instead of creating a window property.
  2. Eliminates Silent Assignment Failures: Mutating read-only properties, non-writable 
     descriptors, or Object.freeze() objects throws TypeError.
  3. Disallows Deleting Undeletable Properties: delete Object.prototype throws TypeError.
  4. Forbids Duplicate Parameter Names: function add(a, a, b) throws SyntaxError.
  5. Forbids Legacy Octal Literals: 010 is illegal (must use modern ES6 0o10).
  6. Disallows the 'with' Statement: with(obj) {} throws SyntaxError.
  7. Secures 'this' Context: In plain function calls, this is 'undefined' instead of 
     coercing to the global window object.
  8. Encapsulates eval(): Variables declared inside eval() do not leak into the calling scope.
  9. Restricts 'eval' and 'arguments' Identifiers: Cannot be used as variable or parameter names.

3. EXCEPTIONS, CORNER CASES, COERCIONS & QUIRKS
--------------------------------------------------------------------------------
[!] Script Concatenation Hazard: If a build tool concatenates a strict-mode file before 
    a legacy non-strict file, the entire bundle becomes strict, potentially crashing legacy code.
[!] 'this' is undefined in Event Callbacks if Bound Carelessly: In strict mode, unbound 
    standalone callbacks have this === undefined instead of window.
[!] eval() Lexical Scope: While strict eval doesn't leak variables outward, it CAN read 
    outer variables in its enclosing lexical scope.

4. 💎 SPECIAL LANGUAGE FEATURES & SENIOR PRO SECRETS
--------------------------------------------------------------------------------
- Automatic Strict Mode in ES6: You do not need to write "use strict"; in React, Next.js, 
  or Vite projects because all ES Modules (import/export) and Classes are strict by specification.
- TurboFan Optimization Boost: Strict mode guarantees no dynamic scope pollution via with/eval, 
  allowing V8 TurboFan to inline variable lookups with zero runtime overhead.
- Safe Global Object Extraction: (function() { "use strict"; return this; })() reliably 
  detects if strict mode is currently active.

5. PRACTICAL ENTERPRISE USE-CASES & CODE EXAMPLES
--------------------------------------------------------------------------------
Example 1: Accidental Global Leak Prevention
"use strict";
function saveScore(score) {
  // studentScore = score; // ReferenceError: studentScore is not defined!
  const studentScore = score; // Clean & Safe
}

Example 2: Object.freeze Mutation Exception
"use strict";
const appConfig = Object.freeze({ lab: "Barrackpore", maxCapacity: 50 });
// appConfig.maxCapacity = 60; // Throws TypeError!

Example 3: Securing Function this Context
"use strict";
function checkContext() {
  console.log(this); // undefined
}
checkContext();

Example 4: Preventing Parameter Collisions
// function calculate(val, val) {} // Throws SyntaxError in strict mode!
function calculate(val1, val2) {
  return val1 + val2;
}

Example 5: Safe Strict Mode Verification Utility
const isStrictModeActive = (function() {
  "use strict";
  return this === undefined;
})();
console.log("Is Strict Mode Active?:", isStrictModeActive);

7. INTERVIEW & VIVA QUICK-FIRE KNOWLEDGE POINTS
--------------------------------------------------------------------------------
Q1: What is 'use strict' in JavaScript and why is it used?
A1: 'use strict' enables strict mode, converting silent errors into throwing exceptions, 
    preventing global scope pollution, securing 'this', and optimizing runtime compilation.

Q2: What happens when assigning to an undeclared variable in strict mode?
A2: A ReferenceError is thrown immediately, preventing accidental leaks into the global window.

Q3: What is the value of 'this' in a standalone function in strict mode?
A3: 'this' is 'undefined' in strict mode, whereas in sloppy mode it coercively binds to window.

Q4: Do ES6 Classes and ES Modules require the 'use strict' directive?
A4: No. ES6 Modules (<script type="module">) and ES6 Class bodies are automatically in strict 
    mode by ECMAScript specification.
