1. TOPIC OVERVIEW & DETAILED CONCEPT DISCUSSION
--------------------------------------------------------------------------------
- What is Lexical Grammar?
  Lexical grammar defines the basic set of rules that the JavaScript engine's Lexer / Scanner 
  uses to transform raw source characters into meaningful tokens (Identifiers, Keywords, 
  Literals, Punctuators, and Comments).
- Key Lexical Elements:
  1. Identifiers: Must start with a Unicode letter, '$', or '_', followed by letters, digits, 
     '$', or '_'. Cannot be reserved keywords (e.g. class, return, const).
  2. Whitespace: Spaces, tabs, and newlines separate tokens and are mostly ignored by the parser 
     (except where Automatic Semicolon Insertion applies).
  3. Comments: Single-line (//) and Multi-line (/* ... */) comments ignored at runtime.
  4. JSDoc: Standardized block comments (/** ... */) providing TypeScript-like type checking 
     and rich editor IntelliSense.

2. IN-DEPTH TECHNICAL KNOW-HOW & ENGINE RUNTIME MECHANICS
--------------------------------------------------------------------------------
- Automatic Semicolon Insertion (ASI) Rules:
  JavaScript automatically inserts semicolons at specific line endings during parsing when:
  1. The next token is an unexpected token or closing brace (}).
  2. The parser encounters a Restricted Production where a newline is forbidden:
     - return [no LineTerminator] Expression;
     - throw [no LineTerminator] Expression;
     - break [no LineTerminator] Label;
     - continue [no LineTerminator] Label;
     - yield [no LineTerminator] Expression;
     - Postfix ++ and -- operators.
- When ASI FAILS (The Leading Token Trap):
  If a line begins with (, [, +, -, /, or template literals, the engine does NOT insert a semicolon 
  before it. It assumes the previous line was a function call or property lookup!

3. EXCEPTIONS, CORNER CASES, COERCIONS & QUIRKS
--------------------------------------------------------------------------------
[!] The Return Object Trap:
    return
    { id: 101 };
    → Parsed as 'return;' followed by an isolated block. Returns undefined!
    Fix: Place opening brace on same line: return { id: 101 };
[!] Leading Parenthesis TypeError:
    const a = 1
    (function() {})()
    → Parsed as: const a = 1(function() {})(); → Throws TypeError: 1 is not a function!
[!] Regex Division Ambiguity: A slash '/' can represent division or a RegExp literal. 
    Whitespace and semicolons resolve ambiguity.

4. 💎 SPECIAL LANGUAGE FEATURES & SENIOR PRO SECRETS
--------------------------------------------------------------------------------
- Leading Semicolon Defensive Pattern: When authoring standalone IIFEs in un-semicoloned 
  codebases, prefix with a defensive semicolon: ;(function() { ... })(); to prevent collisions.
- JSDoc @typedef and @type Annotations: Gain complete TypeScript type-checking, code completions, 
  and parameter safety in pure vanilla .js files without needing a TypeScript compiler build step!
- Numeric Separators (ES2021): Use underscores in numbers for readability: const fee = 1_000_000;.

5. PRACTICAL ENTERPRISE USE-CASES & CODE EXAMPLES
--------------------------------------------------------------------------------
Example 1: Safe Object Return Syntax
// ✓ ALWAYS keep opening brace on the same line as return
function createStudent(name, roll) {
  return {
    name,
    roll,
    verified: true
  };
}

Example 2: Defensive Semicolon with IIFE
// Leading semicolon prevents collision with previous statement
;(function() {
  const localAppSecret = "Barrackpore_Key";
  console.log("Safe IIFE executed");
})();

Example 3: Rich JSDoc Type Annotations
/**
 * @typedef {Object} CourseConfig
 * @property {string} title
 * @property {number} price
 */

/** @type {CourseConfig} */
const jsCourse = {
  title: "JavaScript Professional Masterclass",
  price: 4999

7. INTERVIEW & VIVA QUICK-FIRE KNOWLEDGE POINTS
--------------------------------------------------------------------------------
Q1: What is Automatic Semicolon Insertion (ASI)?
A1: ASI is a parser mechanism in JavaScript that automatically inserts virtual semicolons 
    at certain line boundaries when omitting them would cause syntax errors.

Q2: Why does placing a newline after 'return' return undefined?
A2: 'return' is a Restricted Production in ECMAScript. The parser forbids a newline after it 
    and automatically inserts a semicolon, making it 'return;' which yields undefined.

Q3: When does omitting semicolons cause runtime errors in JavaScript?
A3: When a subsequent line starts with '(', '[', '+', '-', or '/', causing the parser to treat 
    it as a function call, array index, or operator continuing the previous line.

Q4: What is JSDoc and why is it valuable in JavaScript development?
A4: JSDoc provides structured documentation comments that enable IDE IntelliSense, parameter hints, 
    and type checking in vanilla JavaScript without TypeScript transpilation.
