1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
In the English language, punctuation changes everything. Notice the difference between: 'Let's eat, grandfather!' and 'Let's eat grandfather!' A single missing comma completely changes the meaning! In JavaScript, semicolons and line breaks are the punctuation marks that tell the engine where one instruction ends and the next begins.

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Swadeep wrote a return statement on one line and the return value on the next line. When he ran the function, it returned undefined! He showed it to the class: 'Sir, I clearly wrote the number on the next line, so why is it returning undefined?' I drew the lines on the whiteboard. I explained that JavaScript has a feature called Automatic Semicolon Insertion (ASI). Because he pressed Enter after the word return, the JavaScript engine automatically inserted a hidden semicolon right after return;, causing the function to exit immediately before even looking at the value on the next line!

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Lexical Grammar:
The set of basic syntactic rules that govern how code text is parsed into tokens (keywords, identifiers, literals, operators).

2. Whitespace and Indentation:
JavaScript ignores extra spaces, tabs, and empty lines. However, clean, consistent indentation (usually 2 or 4 spaces) is essential for human readability.

3. Comments in JavaScript:
Comments are ignored by the engine and are used to explain why code was written:
- Single-line comment: // This is a single line comment
- Multi-line comment: /* This spans multiple lines */

4. Automatic Semicolon Insertion (ASI):
In JavaScript, semicolons (;) mark the end of statements. If you omit a semicolon, the parser automatically inserts one under certain rules, especially when it encounters a line break.
The Famous ASI Return Trap:
Never put a line break between return and the value you are returning!
- Wrong:
  return
  500; // Becomes 'return;' -> returns undefined
- Right:
  return 500;

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Writing Clean Statements with Semicolons ---
// Clean, unambiguous statements
let studentName = "Swadeep";
let rollNumber = 101;
console.log(studentName, rollNumber);

Teacher's Note on Example 1:
Explicit semicolons ensure your intentions are 100% clear to the engine and your teammates.

--- Example 2: Demonstrating the Return Statement Rule ---
// Correctly placing the return value on the same line
function calculateFees() {
  return 4500 + 500; // Same physical line!
}
console.log("Calculated Fees:", calculateFees()); // 5000

Teacher's Note on Example 2:
Keeping the returned expression on the same line avoids the ASI return trap.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Breaking lines after return, throw, break, or continue: ASI will insert a semicolon immediately, causing unreachable code.

[!] Relying entirely on ASI: Always use explicit semicolons or configure an automatic formatter like Prettier to enforce safe code.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Comments (// and /* */) document logic and are ignored by the JavaScript engine.
• Whitespace is ignored by the engine, but consistent indentation keeps code clean.
• ASI automatically inserts semicolons at line breaks, but can cause subtle bugs if you place newlines after 'return'.
