1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about an electrical plug. The electricity flowing through the wires is the exact same, but if you plug a blender in your kitchen, you get chopped fruit; if you plug a lamp in your bedroom, you get light. JavaScript is the electricity, and the runtime environment (Browser, Server, or Background Worker) is the appliance providing specific capabilities.

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Tuhina wrote a small script that used alert('Hello') and then tried to run it inside Node.js on her terminal. Suddenly, a big red error popped up: ReferenceError: alert is not defined. She was confused: 'Sir, isn't alert a part of JavaScript?' I explained on the board that core JavaScript (ECMAScript) gives you math, variables, and logic. But alert(), window, and document are provided exclusively by Web Browsers. Node.js does not have a screen, so it doesn't have alert() or window; instead, it gives you process and file system access.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The ECMAScript Core vs The Host Environment:
- Core JavaScript: Variables, numbers, strings, conditionals, loops, functions. (Identical everywhere!).
- Host APIs: Extra tools injected into JavaScript by the environment where it is running.

2. Browser Environment:
- Global Object: window
- Specialized APIs: document (DOM), localStorage, fetch, navigator, alert.

3. Node.js Environment:
- Global Object: global (or globalThis)
- Specialized APIs: process, fs (file system), http (server network), Buffer.

4. Web Workers:
- Background threads in browsers that run heavy calculations without freezing the visual webpage UI. They have no access to the visual document object.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Universal Global Object: globalThis ---
// globalThis works consistently in both Browser and Node.js
console.log("Current Runtime Global:", typeof globalThis);

Teacher's Note on Example 1:
globalThis was introduced in modern ECMAScript to give developers a universal way to access the global scope across all environments.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Assuming 'window' or 'document' exists in Node.js: Node.js has no visual browser window.

[!] Assuming 'process.env' exists in the browser: The browser has no direct operating system process access for security reasons.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Core JavaScript syntax is universal across all environments.
• Browsers provide web APIs (window, DOM, alerts) for user interfaces.
• Node.js provides server APIs (process, file system) for backend operations.
