1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about the rules of cricket or football. If every stadium in every country made up its own rules for pitch size or scoring points, international matches would be chaos! That is why international governing bodies (like ICC or FIFA) write the official rulebook. In the JavaScript world, that official rulebook is called ECMAScript.

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Tuhina asked during our morning theory class: 'Sir, if Google makes Chrome and Apple makes Safari, why doesn't my JavaScript code break when I switch from a Mac to a Windows laptop?' I took out a piece of chalk and wrote 'ECMA-262' on the board. I explained how back in the late 1990s, Netscape and Microsoft had different versions of script which caused websites to break on rival browsers. To fix this forever, the community formed a technical committee called TC39 under the ECMA standards organization to maintain a universal rulebook.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. What is ECMAScript?
ECMAScript (abbreviated as ES) is the formal specification (the blueprint/rulebook) of the JavaScript language. JavaScript is the real-world implementation that complies with this standard.
- ES5 (2009): The classic standard supported everywhere.
- ES6 / ES2015: The massive revolution that introduced modern features.
- ES2016 through ES2026+: Annual updates introducing refined syntax.

2. Who Decides New Features? The TC39 Process:
TC39 (Technical Committee 39) consists of browser vendors, engine implementers, and language researchers. Every new proposed feature goes through 5 strict stages:
- Stage 0 (Strawman): An early idea or proposal.
- Stage 1 (Proposal): Formal problem statement and initial syntax design.
- Stage 2 (Draft): Precise specification draft of semantics.
- Stage 3 (Candidate): Specification complete; browsers begin implementing experimental support.
- Stage 4 (Finished): Fully standardized and merged into the upcoming yearly release.

3. The Engines that Run the Rules:
- Google Chrome & Node.js: V8 Engine (C++)
- Mozilla Firefox: SpiderMonkey (C++/Rust)
- Apple Safari: JavaScriptCore (C++)

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Thinking ECMAScript is a separate programming language: ECMAScript is the standard document; JavaScript is the living language in your hands.

[!] Assuming all experimental features work in every browser: Only Stage 4 finalized features are guaranteed to be universally supported.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• ECMAScript (ECMA-262) is the official specification governing JavaScript.
• TC39 is the committee that votes on and matures new language proposals through Stages 0 to 4.
• Engines (V8, SpiderMonkey, JavaScriptCore) follow this specification to execute code consistently.
