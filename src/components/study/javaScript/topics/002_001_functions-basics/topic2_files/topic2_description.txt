1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about sending a registered speed post letter at the post office. When you hand your parcel to the postal clerk, the clerk weighs it, stamps it, and hands you an official Printed Tracking Receipt (the Return Value). If the parcel is improperly sealed, the clerk stops you immediately at the counter and hands it back (an Early Return Guard Clause) without making you wait in line for 20 minutes!

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The Return Statement:
- The return keyword exits the function immediately and passes a value back to the caller.
- If a function finishes without an explicit return statement, it returns undefined by default.

2. Early Returns & Guard Clauses:
- Validate failure conditions at the very start of the function and return immediately.
- Keeps the 'happy path' (core success logic) clean and un-indented at the base level.
- Prevents deep nested arrow-shaped code.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Defensive Early Return Guard ---
function calculateDiscountedPrice(price, discountPercent) {
  // Guard 1: Invalid price
  if (price <= 0) return 0;
  
  // Guard 2: No discount applicable
  if (discountPercent <= 0) return price;
  
  // Guard 3: Cap maximum discount at 50%
  if (discountPercent > 50) discountPercent = 50;
  
  // Core Happy Path:
  let discountAmount = price * (discountPercent / 100);
  return price - discountAmount;
}

console.log('Final Price: ₹' + calculateDiscountedPrice(1000, 20)); // ₹800
console.log('Invalid Price: ₹' + calculateDiscountedPrice(-50, 10)); // ₹0

Teacher's Note on Example 1:
Guard clauses at the top validate inputs and return immediately on boundary conditions.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Forgetting that return stops execution: Any code written after a return statement on the same execution path is completely unreachable.

[!] Placing newline after return: return with newline triggers Automatic Semicolon Insertion and returns undefined!

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• return exits the function and sends data back to the caller.
• Guard clauses at the top eliminate nested indentation and simplify error handling.
• Functions without return statements return undefined by default.
