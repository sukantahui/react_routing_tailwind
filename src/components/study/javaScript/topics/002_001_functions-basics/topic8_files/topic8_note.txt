3. EXCEPTIONS, CORNER CASES, COERCIONS & QUIRKS
--------------------------------------------------------------------------------
[!] TypeError on Non-Callable Bind: Calling `.call()` or `.bind()` on an undefined or non-function property throws TypeError.
[!] Re-binding a Bound Function: Calling `.bind()` on an already bound function does NOT change the original bound `this`; subsequent binds are ignored.
[!] Sloppy vs Strict Mode Null thisArg: Passing `null` or `undefined` as `thisArg` in non-strict mode coerces `this` to global window; in strict mode it remains null/undefined.

7. INTERVIEW & VIVA QUICK-FIRE KNOWLEDGE POINTS
--------------------------------------------------------------------------------
Q1: What is the primary purpose of Function.prototype Methods: call(), apply(), and bind() with Custom Contexts?
A1: Explicitly control function context in JavaScript using call, apply, and bind: method borrowing, partial application, and handling dynamic this bindings.

Q2: How does the V8 engine execute this under the hood?
A2: It resolves bindings via the Lexical Environment Record and executes on the Call Stack.

Q3: What common bug do junior developers encounter here?
A3: Attempting to Re-Bind an Already Bound Function: Once a function is bound via `.bind()`, its `this` context is permanently locked.

Q4: What is the Senior Pro recommendation?
A4: Use Arrow Functions or Higher-Order Wrappers for Dynamic Context: When dynamic re-contextualization is required, use explicit wrappers rather than stacked binds.
