1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about a mathematical calculator. If you type '5 + 5', it gives you '10'. If you press the button 100 times tomorrow, it still gives you '10'. It doesn't secretly change your bank balance, send an email, or play loud music. It takes inputs, computes the result, and returns it. That is a Pure Function!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Abhronila was debugging a billing app. Whenever she printed an invoice, the student's original course fee in the database mysteriously got doubled! We discovered her discount function was directly mutating the global studentFee variable (studentFee = studentFee * 0.9) instead of calculating on a local copy. I taught the class: 'A pure function never touches outside variables (No Side Effects). Given the same inputs, it always returns the exact same output.'

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. What is a Pure Function?
A function that satisfies two strict mathematical criteria:
a) Deterministic: Given the exact same arguments, it ALWAYS returns the exact same result.
b) Zero Side Effects: It does NOT modify any external state, change outside variables, alter arguments, or perform I/O operations.

2. What is a Side Effect?
Any observable change outside the function's own local scope (e.g. modifying global variables, mutating input objects/arrays, writing to disk, logging to console).

3. Benefits of Pure Functions:
- Extremely easy to test and debug.
- Reusable and predictable in large enterprise software systems.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Impure vs Pure Function ---
// ❌ Impure (Modifies external state):
let totalRevenue = 1000;
function impureAdd(amount) {
  totalRevenue += amount; // Side effect!
  return totalRevenue;
}

// ✓ Pure (Self-contained, deterministic):
function pureAdd(currentTotal, amount) {
  return currentTotal + amount;
}

console.log(pureAdd(1000, 500)); // 1500 (Always predictable)

Teacher's Note on Example 1:
Pure functions compute results without modifying any external variable.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Mutating input parameters directly: Never modify arguments directly; create and return a new calculated value.

[!] Relying on Math.random() or Date.now() inside a pure function: These introduce non-deterministic external state.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Pure functions are deterministic and have zero side effects.
• They make code predictable, bug-free, and effortless to test.
• Always return new values rather than mutating existing data.
