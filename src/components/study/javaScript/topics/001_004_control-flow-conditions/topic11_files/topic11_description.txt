3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. What is the Early Return Pattern?
A coding style where failure, validation, and boundary conditions are checked first at the top of a function with immediate `return` statements.

2. Key Benefits:
- Eliminates the 'Arrow Anti-Pattern' (Pyramid of Doom).
- Reduces cognitive load: you can read validation rules individually.
- The core 'happy path' business logic sits cleanly at the base indentation level.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Flattening Nested Logic with Early Returns ---
function processCourseEnrollment(student, course) {
  // Guard 1: Missing student
  if (!student) return { success: false, reason: 'Student profile required' };
  
  // Guard 2: Course full
  if (course.isFull) return { success: false, reason: 'Course batch is full' };
  
  // Guard 3: Fee not paid
  if (!student.feePaid) return { success: false, reason: 'Payment pending' };
  
  // Core Happy Path:
  course.enrolledCount += 1;
  return { success: true, message: `Enrolled ${student.name} in ${course.title}!` };
}

console.log(processCourseEnrollment({ name: 'Swadeep', feePaid: true }, { title: 'JS Pro', isFull: false, enrolledCount: 10 }));

Teacher's Note on Example 1:
Early return guards isolate error paths and keep success logic flat and clear.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Inverting guards improperly: Ensure each guard condition checks for the FAILURE condition to exit early.

[!] Duplicating cleanup logic: If cleanup is needed before exiting, extract cleanup into a helper function.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Early returns check failure conditions first and exit immediately.
• Eliminates deep indentation and nested pyramids.
• Keeps the core success logic clean and readable at the base level.
