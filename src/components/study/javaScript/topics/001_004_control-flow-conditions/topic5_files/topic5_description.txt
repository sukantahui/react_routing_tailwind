1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Imagine entering an office building with 5 security gates. In a poorly designed building (the 'Arrow Anti-Pattern'), each security guard sends you into a deeper, narrower nested room with another door, and you end up trapped 5 rooms deep. In a well-designed building (Early Return), if your badge is invalid, the guard stops you at the front desk immediately and asks you to leave, while valid visitors walk straight down a wide, open corridor.

Swadeep showed me a function with 5 nested if statements. The code indented so far to the right that it looked like a giant sideways arrow (>), pushing his actual logic off the edge of his screen! 3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The Arrow Anti-Pattern (Pyramid of Doom):
When code nests if-statements inside if-statements:
if (isLoggedIn) {
  if (hasPaid) {
    if (isCourseActive) {
      // actual logic trapped 4 levels deep!
    }
  }
}

2. The Early Return Solution:
Invert the conditions and return immediately on failure:
if (!isLoggedIn) return "Please login";
if (!hasPaid) return "Please pay fee";
if (!isCourseActive) return "Course expired";

// Main logic sits cleanly at the top level!
return "Welcome to class!";

3. Benefits:
- Drastically reduces cyclomatic complexity (fewer branching paths).
- Keeps the 'happy path' un-indented and easy to follow.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Refactoring Nested Code with Early Returns ---
function verifyAdmission(age, hasPassedExam, hasPaidFees) {
  // Early Exit 1: Age check
  if (age < 18) {
    return "Admission Rejected: Must be at least 18 years old.";
  }
  
  // Early Exit 2: Exam check
  if (!hasPassedExam) {
    return "Admission Rejected: Entrance exam not cleared.";
  }
  
  // Early Exit 3: Fees check
  if (!hasPaidFees) {
    return "Admission Pending: Fees payment required.";
  }
  
  // Happy Path: Clean, un-nested success logic!
  return "Admission Confirmed! Welcome to Coder & AccoTax.";
}

console.log(verifyAdmission(20, true, true)); // "Admission Confirmed!"
console.log(verifyAdmission(16, true, true)); // "Admission Rejected: Must be at least 18..."

Teacher's Note on Example 1:
Early exits eliminate nested pyramid structures and make each validation rule explicit.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Keeping large nested blocks when an early return is possible: Whenever a failure condition is detected, exit immediately.

[!] Forgetting return values in early exits: Make sure your early return passes back a meaningful status or value.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Early returns invert error conditions to exit immediately.
• Eliminates deep indentation (the Arrow Anti-Pattern).
• Keeps the core success logic clean and readable at the root level.
