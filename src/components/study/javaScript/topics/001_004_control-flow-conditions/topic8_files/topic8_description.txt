1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Imagine a road sign that says 'Bridge Open = True' where the painter accidentally painted a single `=` sign instead of `===`. A single missing equal sign turns a question ('Is the bridge open?') into a forced command ('Force open the bridge!'). In JavaScript, the Assignment vs Equality trap is the #1 source of subtle beginner bugs!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Swadeep had a condition: `let isAdmin = false; if (isAdmin = true) { console.log('Welcome Admin'); }`. The console printed 'Welcome Admin' even though `isAdmin` was false! Swadeep was bewildered. I pointed out that single `=` assigned `true` to `isAdmin`, and the assignment evaluated to `true`! We enabled ESLint and strict mode, and wrote `isAdmin === true`. Swadeep promised never to confuse `=` with `===` again.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The Assignment in Condition Trap:
Writing `if (x = 5)` assigns 5 to x, evaluates to 5 (truthy), and always executes the if branch!
Always use `if (x === 5)`.

2. The Falsy Zero Trap:
Using `if (score)` or `score || 10` when `score` is 0 skips the condition because 0 is falsy.
Always write `if (score !== undefined)` or use `score ?? 10`.

3. The NaN Comparison Trap:
`if (val === NaN)` is ALWAYS false because `NaN === NaN` is false. Always write `if (Number.isNaN(val))`.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Fixing Common Condition Traps ---
// ❌ Bug: Single = assignment inside if
// if (userRole = 'ADMIN') { ... }

// ✓ Fix: Strict equality ===
let userRole = 'STUDENT';
if (userRole === 'ADMIN') {
  console.log('Admin Access Granted');
} else {
  console.log('Student Portal Active'); // Correctly enters else!
}

Teacher's Note on Example 1:
Strict comparison prevents accidental variable overwrites inside conditionals.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Single `=` inside `if()`: Always double check for `===` in conditions.

[!] Checking `x === NaN`: Always use `Number.isNaN(x)`.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Never use single `=` assignment inside conditional expressions.
• Be cautious with falsy 0, empty strings, and false.
• Always use `Number.isNaN()` to check for NaN.
