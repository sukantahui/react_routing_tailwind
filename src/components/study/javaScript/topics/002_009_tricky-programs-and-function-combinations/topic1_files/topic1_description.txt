1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Imagine an automated cash register at a grocery store in Barrackpore. Customer 1 drops a coin `add(10)`, customer 2 drops another coin `(20)`, customer 3 drops another `(50)`. The machine can keep accepting coins infinitely. If you stop dropping coins and press the Total button `()`, it prints the total ₹80. Or if you convert the machine to a string, it automatically displays ₹80! That is Infinite Currying.

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Tuhina was asked in a mock technical interview: 'Implement `add(1)(2)(3)...(n)` such that `add(1)(2)(3) == 6`'. She knew standard currying with fixed arguments, but was puzzled how a function could return another function forever while still acting as a number. I showed her two patterns: 1. Empty parenthesis termination `sum(1)(2)(3)()`; 2. Custom value serialization by overriding `valueOf` and `toString` on the returned function. Tuhina was thrilled by this elegant JavaScript metaprogramming technique.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Terminated Infinite Currying (`sum(1)(2)()`):
- If an argument is provided, return a new accumulator function.
- If called with empty parentheses `()`, return the accumulated total.

2. Value-Of Infinite Currying (`add(1)(2)(3) == 6`):
- The function always returns a new function for chaining.
- Overriding `fn.valueOf` or `fn[Symbol.toPrimitive]` allows JavaScript to automatically coerce the function into its numeric total during comparisons (`==`, `+`, `Number()`).

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Both Infinite Currying Implementations ---
// Pattern 1: Empty Parenthesis Termination
function sum(a) {
  return function(b) {
    if (b === undefined) return a; // Stop on empty call
    return sum(a + b);            // Chain with running sum
  };
}
console.log('sum(1)(2)(3)() =', sum(1)(2)(3)()); // 6

// Pattern 2: Overriding valueOf for Comparison Coercion
function add(x) {
  const next = function(y) {
    return add(x + y);
  };
  next.valueOf = () => x;
  next.toString = () => String(x);
  return next;
}

console.log('add(1)(2)(3) + 4 =', Number(add(1)(2)(3)) + 4); // 10

Teacher's Note on Example 1:
Demonstrates empty-call termination and prototype valueOf type coercion.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Strict equality `===` with valueOf currying: `add(1)(2) === 3` is false because a Function reference is never strictly equal to a Number. Use `Number(add(1)(2)) === 3` or loose equality `add(1)(2) == 3`.

[!] Omitting toString override: Overriding only valueOf might not format cleanly in template literals.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Infinite currying accumulates values across dynamic, arbitrary call chains.
• Use empty call `()` to terminate and return the accumulated result.
• Use `valueOf` and `toString` to customize automatic primitive coercion.
