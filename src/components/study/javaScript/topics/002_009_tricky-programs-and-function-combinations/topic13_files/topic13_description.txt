3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The Unbounded Concurrency Danger:
Firing hundreds of simultaneous asynchronous requests (`fetch`, database queries, file reads) crashes servers, causes socket exhaustion, and triggers rate-limits.

2. The Pool Limiter Architecture:
- Maintains an active running set of Promises capped at `limit`.
- As each task resolves, it removes itself from the active pool and triggers the next task from the queue.
- Uses `Promise.race()` or callback continuations to maintain maximum pool saturation.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Async Concurrency Pool Limiter ---
async function asyncPool(concurrencyLimit, items, asyncWorkerFn) {
  const results = [];
  const executing = new Set();
  
  for (const item of items) {
    const promise = Promise.resolve().then(() => asyncWorkerFn(item));
    results.push(promise);
    executing.add(promise);
    
    const cleanUp = () => executing.delete(promise);
    promise.then(cleanUp, cleanUp);
    
    if (executing.size >= concurrencyLimit) {
      await Promise.race(executing); // Wait for the fastest task to finish!
    }
  }
  
  return Promise.all(results);
}

// Mock worker task:
const mockDownload = (id) => new Promise(res => {
  setTimeout(() => { console.log(`Downloaded #${id}`); res(`Data #${id}`); }, 50);
});

asyncPool(2, [1, 2, 3, 4, 5], mockDownload).then(allData => {
  console.log('All downloads complete:', allData);
});

Teacher's Note on Example 1:
Maintains a constant maximum pool of concurrent active promises using Promise.race.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Uncaught rejections in the active pool: Always attach both success and failure cleanup handlers (`.then(clean, clean)`) so rejected tasks don't get stuck in the active set.

[!] Setting concurrency limit to 0 or negative: Guard inputs to ensure limit >= 1.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Concurrency pool limiters throttle simultaneous async operations.
• Prevents server rate-limiting, socket exhaustion, and out-of-memory crashes.
• Essential for web scrapers, batch uploaders, and high-throughput microservices.
