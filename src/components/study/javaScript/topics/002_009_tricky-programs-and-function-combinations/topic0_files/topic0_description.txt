1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Imagine giving 3 students in a classroom 3 sticky notes and telling them: 'In 5 minutes, write down whatever number is currently written on the main whiteboard'. While the clock ticks for 5 minutes, the teacher keeps counting 1... 2... 3... and leaves the number '3' on the board. When the 5 minutes expire, all 3 students look at the board and all write '3'! That is the famous `var` in `setTimeout` loop trap in JavaScript!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Swadeep wrote a loop: `for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 100); }`. He expected `0, 1, 2`. Instead, the console printed: `3, 3, 3`! Swadeep panicked: 'Sir! Where did 0 and 1 go?' I drew the Event Loop, Call Stack, and Lexical Scope on the board. Because `var` is function-scoped, all 3 timeout callbacks share the single `i` variable in memory. By the time the timeouts run, `i` has already reached 3! I demonstrated 5 different solutions (ES6 `let`, IIFE closure, `setTimeout` parameter passing, `bind`, and HOF helpers).

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The Root Cause of the Trap:
`var` is not block-scoped. The loop shares a single binding for `i`. The asynchronous callbacks in the Task Queue execute only after the loop completes and `i` has reached its terminal value.

2. The 5 Universal Solutions:
1. Modern ES6 `let`: `let` creates a fresh, distinct binding of `i` for every iteration block.
2. IIFE Closure: `(function(j) { setTimeout(..., 100); })(i);` captures `i` by value in a private scope.
3. setTimeout Parameter Passing: `setTimeout(fn, 100, i)` passes the current value directly.
4. Explicit Function Binding: `setTimeout(console.log.bind(null, i), 100)` binds the value permanently.
5. Custom Helper HOF: Wrapping logic inside a higher-order executor.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: The Problem vs The Solutions ---
// ❌ The Trap (Prints: 3, 3, 3):
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var trap:', i), 50);
}

// ✓ Solution 1: ES6 Block Scope (Prints: 0, 1, 2)
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let fix:', j), 100);
}

// ✓ Solution 2: setTimeout Argument Passing (Prints: 0, 1, 2)
for (var k = 0; k < 3; k++) {
  setTimeout((val) => console.log('param fix:', val), 150, k);
}

Teacher's Note on Example 1:
let creates per-iteration bindings; timeout args capture snapshot values.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Using var in any asynchronous loops: Always use `let` in loops containing asynchronous callbacks or event listeners.

[!] Assuming setTimeout(..., 0) runs synchronously: Even with 0ms delay, the callback is sent to the Task Queue and runs after the synchronous loop finishes.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• `var` creates a single shared scope across all loop iterations.
• `let` creates a fresh lexical binding for each loop lap.
• The classic interview question testing deep knowledge of closures and the event loop.
