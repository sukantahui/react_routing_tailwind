1. TOPIC OVERVIEW & ARCHITECTURAL COMPARISON
--------------------------------------------------------------------------------
JavaScript provides 4 primary mechanisms for repeating execution over data structures:
1. Traditional for Loop: Imperative, index-driven counter loop with total flow control.
2. for...of Loop (ES6): Declarative iteration protocol consumer yielding element values.
3. for...in Loop (ES3): Object property key enumerator that walks the prototype chain.
4. Array.prototype.forEach (ES5): Functional higher-order callback applicator.

Understanding the internal runtime mechanics, execution context stack frames,
and V8 optimization pipelines of each loop separates junior code writers from
senior software architects.

2. IN-DEPTH TECHNICAL KNOW-HOW & RUNTIME MECHANICS
--------------------------------------------------------------------------------
A. Traditional for Loop (`for (let i = 0; i < len; i++)`):
   - Execution: Compiles to direct CPU register increments and index comparisons.
   - V8 Engine: Optimizes memory reads on contiguous Fast SMI (Small Integer) array backing stores.
   - Control Flow: Native support for `break`, `continue`, and early `return` from outer function.
   - Scope: `let i` creates a new lexical environment binding per iteration step.

B. for...of Loop (`for (const item of iterable)`):
   - Protocol: Invokes `iterable[Symbol.iterator]()` to obtain an iterator instance.
   - Loop Step: Repeatedly calls `iterator.next()` extracting `{ value, done }` until `done: true`.
   - Supported Targets: Arrays, Strings, Sets, Maps, NodeLists, TypedArrays, Generators.
   - Control Flow: Supports `break`, `continue`, `return`, and `await` (in async functions).
   - Early Exit: Automatically invokes `iterator.return()` on abrupt loop termination.

C. for...in Loop (`for (const key in object)`):
   - Scope: Enumerates all enumerable property keys of an object as STRINGS.
   - Prototype Chain: Traverses up the `[[Prototype]]` chain visiting inherited enumerable properties.
   - Order: Iterates integer-like keys in ascending numerical order, then string keys in insertion order.
   - Arrays: Dangerous on arrays because indices are strings (`"0" + 1 = "01"`) and prototype methods are visited.

D. Array.prototype.forEach (`arr.forEach((item, index, array) => ...)`):
   - Mechanism: Invokes a callback function per existing element in the array.
   - Call Stack: Pushes a new execution frame onto the Call Stack for every single element.
   - Limitations: Cannot use `break` or `continue`. `return` only exits the current callback iteration.
   - Async: Does NOT await promises; executes async callbacks in concurrent fire-and-forget mode.

3. EXCEPTIONS, CORNER CASES, QUIRKS & TRAPS
--------------------------------------------------------------------------------
[!] TRAP 1: Using for...in on Arrays
    - Prototype Pollution: If `Array.prototype.customHelper = ...` is defined, for...in will visit it!
    - String Index Coercion: `typeof key` is ALWAYS 'string'. `key + 1` produces `'01'`, not `1`.
    - Defense: Always use `for...of` or traditional `for` on arrays.

[!] TRAP 2: Attempting to break out of forEach
    - `break` or `continue` inside forEach produces `SyntaxError: Illegal break statement`.
    - `return` merely acts as a `continue` for the current callback invocation.
    - Defense: Use `Array.prototype.some()` (returns true to break) or `for...of`.

[!] TRAP 3: Async/Await inside forEach
    - `arr.forEach(async item => await save(item))` will NOT pause the enclosing function.
    - Outer code runs ahead immediately while async requests resolve unpredictably in the background.
    - Defense: Use `for (const item of arr) { await save(item); }`.

[!] TRAP 4: for...of on Plain Objects
    - `for (const x of { a: 1 })` throws `TypeError: { a: 1 } is not iterable`.
    - Defense: Use `Object.entries(obj)`, `Object.keys(obj)`, or `Object.values(obj)`.

[!] TRAP 5: Sparse Arrays (Array Holes)
    - Given `const arr = [1, , 3]`:
      * `for...of` visits the hole yielding `undefined`.
      * `forEach` and `for...in` SKIP the hole entirely.

4. 💎 SPECIAL LANGUAGE FEATURES & SENIOR PRO SECRETS
--------------------------------------------------------------------------------
- Secret 1: Dual Index & Value Traversal with for...of:
  `for (const [idx, val] of arr.entries()) { console.log(idx, val); }`
- Secret 2: Asynchronous Streams with `for await...of`:
  Consume Node.js Readable streams and AsyncGenerators with backpressure flow control.
- Secret 3: Custom Iterable Protocol:
  Add `[Symbol.iterator]()` to any custom class or object to make it natively iterable with `for...of`.
- Secret 4: Unicode-Safe String Traversal:
  `for...of` iterates over Unicode code points without splitting multi-byte emoji surrogate pairs.

5. COMPARATIVE SPECIFICATION MATRIX
--------------------------------------------------------------------------------
+----------------------+--------------------+-------------------+--------------------+--------------------+
| Loop Type            | Target Target      | Yielded Value     | Break / Continue   | Async Await Support|
+----------------------+--------------------+-------------------+--------------------+--------------------+
| Traditional for      | Arrays / Strings   | Manual via arr[i] | YES (Full Control) | YES (Sequential)   |
| for...of             | All Iterables      | Element Value     | YES                | YES (Sequential)   |
| for...in             | Plain Objects      | String Key Names  | YES                | YES (Sequential)   |
| Array.prototype.forEach| Arrays Only      | Value, Index, Arr | NO (Never Breaks)  | NO (Concurrent)    |
+----------------------+--------------------+-------------------+--------------------+--------------------+

6. SENIOR ARCHITECTURAL CHEAT-SHEET
--------------------------------------------------------------------------------
- Default Choice for Data Collections: `for...of`
- Default Choice for Hot / High-Performance Math Loops: Traditional `for` (`for (let i = 0...)`)
- Default Choice for Plain Object Key Inspection: `for...in` with `Object.hasOwn(obj, key)`
- Default Choice for Fluent Functional Pipelines: `arr.map().filter().forEach()`
