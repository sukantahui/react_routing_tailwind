3. EXCEPTIONS, CORNER CASES, COERCIONS & QUIRKS
--------------------------------------------------------------------------------
[!] TypeError: Reduce of empty array with no initial value: Invoking `reduce()` on an empty array without an initial value throws immediately.
[!] Missing Return in Reducer: Forgetting to `return acc;` from the reducer callback sets the accumulator to `undefined` on the next iteration.
[!] Accumulator Mutation vs Reallocation: In performance-heavy loops, mutating the accumulator object (`acc[key] = val`) is faster than spreading (`{ ...acc, [key]: val }`).

const actions = [
  { type: "DEPOSIT", amount: 500 },
  { type: "WITHDRAW", amount: 200 },
  { type: "DEPOSIT", amount: 1000 }
];
const balanceReducer = (balance, action) => {
  switch (action.type) {
    case "DEPOSIT": return balance + action.amount;
    case "WITHDRAW": return balance - action.amount;
    default: return balance;
  }
};
const finalBalance = actions.reduce(balanceReducer, 0);
console.log("Calculated Balance:", finalBalance); // 1300

Q2: How does V8 optimize array memory for this operation?
A2: By maintaining contiguous packed element buffers and using fast C++ native methods.

Q3: What common bug occurs with junior developers?
A3: Using Object Spread inside reduce() Accumulator: `acc = { ...acc, [k]: v }` creates O(N^2) memory allocations, killing performance for large datasets.

Q4: What is the Senior Pro recommended pattern?
A4: Mutate the Local Accumulator Directly: Mutating the locally constructed accumulator inside the reducer is pure and O(N) fast.
