1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about storage containers in your kitchen. Some containers are cardboard boxes where anyone can scribble notes, overwrite the label, or accidentally spill contents (that is 'var'). Some are modern Tupperware containers with secure airtight lids that only exist in the kitchen cabinet where you placed them (that is 'let'). And some are solid glass jars sealed with a tamper-proof lock that can never be refilled with something else once sealed (that is 'const')!

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The Evolution: var vs let vs const
- var (Legacy ES5): Function-scoped or globally-scoped. Ignores { block } boundaries. Can be redeclared and updated anytime. Hoisted and initialized to undefined.
- let (Modern ES6): Block-scoped (lives strictly inside the nearest { ... } braces). Cannot be redeclared in the same scope. Can be updated.
- const (Modern ES6): Block-scoped. Cannot be reassigned once set. Must be initialized with a value at the time of declaration.

2. The Temporal Dead Zone (TDZ):
When JavaScript reads a block containing a let or const variable, the engine knows the variable exists from the start of the block, but places it in a 'Dead Zone' where accessing it throws a ReferenceError until the line where it is formally declared.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Block Scoping with let ---
{
  let labRoom = "Room 101";
  console.log("Inside block:", labRoom); // Room 101
}
// console.log(labRoom); // ReferenceError: labRoom is not defined outside!

Teacher's Note on Example 1:
Variables declared with let are securely trapped inside their enclosing block.

--- Example 2: Constants with const ---
const BATCH_ID = "JS-2026";
// BATCH_ID = "JS-2027"; // TypeError: Assignment to constant variable!
console.log("Batch ID:", BATCH_ID);

Teacher's Note on Example 2:
const guarantees that the identifier cannot be reassigned.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Using var in modern code: Avoid var entirely; use const by default and let when re-assignment is needed.

[!] Accessing let/const before declaration: This triggers the Temporal Dead Zone ReferenceError.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Use const for values that never get reassigned.
• Use let for variables whose values change over time.
• Avoid var to prevent accidental scope leaks and variable collisions.
