3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. BigInt Primitive:
- Represents integers of arbitrary precision beyond `Number.MAX_SAFE_INTEGER` (2^53 - 1).
- Append `n` to the integer literal or call `BigInt(str)`.
- Cannot mix BigInt and standard Number in arithmetic operations without explicit conversion.

2. Symbol Primitive:
- Guaranteed unique, immutable primitive value.
- Created with `Symbol('desc')` (never `new Symbol()`).
- Ideal for private object keys and library metadata.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Using BigInt and Symbols ---
const maxSafe = Number.MAX_SAFE_INTEGER; // 9007199254740991
const bigNum1 = 9007199254740991n + 5n; // BigInt math!
console.log('BigInt sum:', bigNum1.toString()); // '9007199254740996'

const keyA = Symbol('id');
const keyB = Symbol('id');
console.log('Are symbols equal?', keyA === keyB); // false!

Teacher's Note on Example 1:
BigInt maintains exact integer precision; Symbols are 100% unique.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Mixing Number and BigInt: `10n + 5` throws TypeError. Convert explicitly: `10n + BigInt(5)`.

[!] JSON.stringify does not serialize BigInt: `JSON.stringify({ n: 10n })` throws TypeError.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• BigInt handles integers beyond 9 quadrillion without rounding loss.
• Symbols create guaranteed unique object property keys.
• Both are immutable primitive types.
