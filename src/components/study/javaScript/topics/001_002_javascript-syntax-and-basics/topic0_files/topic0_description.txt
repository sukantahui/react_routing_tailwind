1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about writing a recipe for a cup of tea: Step 1: Boil water. Step 2: Add tea leaves. Step 3: Add milk and sugar. If you mix the instructions together on a single line without full stops or periods, a new cook will get confused. In programming, each individual instruction you give to the computer is called a 'Statement', and semicolons and clean indentation are the formatting that makes your recipe effortless to read.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. What is a Statement?
A statement is an independent instruction that performs an action. For example:
- Declaring a variable
- Assigning a value
- Printing to console

2. Statements vs Expressions:
- An Expression produces a value (e.g. 5 + 3, or "Hello" + " World").
- A Statement executes a complete command (e.g. let score = 5 + 3;).

3. Code Formatting & Indentation:
- Standard convention: 2 spaces or 4 spaces per indentation level.
- Put spaces around operators (a + b, not a+b).
- Keep variable names descriptive and in camelCase (e.g. studentAge, courseFee).

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Clean vs Messy Statements ---
// Messy and hard to read:
let x=10;let y=20;console.log(x+y);

// Clean, professional code style:
let itemPrice = 10;
let deliveryCharge = 20;
let finalBill = itemPrice + deliveryCharge;
console.log("Final Bill:", finalBill);

Teacher's Note on Example 1:
Descriptive names and clean line breaks make your code self-documenting.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Writing everything on one line: Separate distinct statements onto separate physical lines.

[!] Inconsistent indentation: Mixing 2 spaces, 4 spaces, and tabs randomly makes code messy.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Statements are complete instructions executed in order.
• Use camelCase for variables and consistent 2-space indentation.
• Clear formatting prevents bugs and simplifies debugging.
