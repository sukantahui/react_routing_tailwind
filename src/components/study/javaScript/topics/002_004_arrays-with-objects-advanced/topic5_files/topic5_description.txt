1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think of an airplane pre-flight checklist. The captain checks: Is EVERY engine operational? (every). Is EVERY emergency door locked? (every). Is ANY fire warning light blinking? (some). In JavaScript, `some()` and `every()` allow you to validate compliance rules across entire collections of records with short-circuit speed!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Tuhina was building a course batch completion validator. Before issuing certificates to the batch, she had to verify: Did EVERY student clear the passing marks (>= 40)? And did ANY student commit plagiarism? She wrote 2 loops. I showed her `const isBatchPassed = students.every(s => s.marks >= 40)` and `const hasPlagiarism = students.some(s => s.isFlagged)`. Tuhina was amazed at how concise and expressive the validation logic became.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Enterprise Validation Rules:
- every(predicateFn): Returns true if ALL objects satisfy the rule; stops immediately on the first failure.
- some(predicateFn): Returns true if AT LEAST ONE object satisfies the rule; stops immediately on the first match.

2. Real-World Applications:
- Form completeness checks (every required field filled?)
- Security access checks (has user any admin permissions?)
- Inventory alerts (is any product out of stock?)

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Validating Batch Fees and Exam Clearance ---
const batchStudents = [
  { name: 'Swadeep', feePaid: true, marks: 85 },
  { name: 'Tuhina', feePaid: true, marks: 92 },
  { name: 'Abhronila', feePaid: true, marks: 78 },
  { name: 'Debangshu', feePaid: false, marks: 95 }
];

// 1. Check if all students cleared fees:
const allFeesCleared = batchStudents.every(s => s.feePaid);
console.log('All fees paid?', allFeesCleared); // false (Debangshu has not paid)

// 2. Check if any student scored 90+ honors:
const hasHonorsStudent = batchStudents.some(s => s.marks >= 90);
console.log('Has honors student?', hasHonorsStudent); // true (Tuhina & Debangshu)

Teacher's Note on Example 1:
every ensures 100% compliance; some detects if at least one record qualifies.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Inverting logic accidentally: Forgetting that `!students.every(...)` is NOT the same as `students.some(...)` without inverting the predicate condition.

[!] Empty collection truthiness: `[].every(...)` is always true (vacuous truth).

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• every() validates that all object records comply with a rule.
• some() checks if any object in the collection triggers a flag.
• Both methods short-circuit early for maximum performance.
