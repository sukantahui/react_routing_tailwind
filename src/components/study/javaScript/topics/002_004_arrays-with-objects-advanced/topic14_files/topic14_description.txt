1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about keys to a hotel room. A strong keycard (Standard `Map`/`Set`) keeps the hotel room booked forever as long as you hold the card in your pocket. Even if the hotel guest checks out and leaves town, the room cannot be cleaned because you still hold a strong reference. A temporary digital keycard (WeakMap/WeakSet) automatically deactivates and frees the room for housekeeping the instant the guest leaves town (Garbage Collection)!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Swadeep was creating an in-memory cache to store metadata for DOM elements. When elements were deleted from the webpage, his cache kept holding strong references in a standard `Map`, causing memory leaks. I introduced him to `WeakMap`. With `WeakMap`, the instant an element is removed from the DOM, JavaScript's Garbage Collector automatically cleans up its cache entry in memory with zero manual cleanup code.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Map vs Set:
- Set: Collection of UNIQUE values (automatically eliminates duplicates).
- Map: Key-Value dictionary where keys can be ANY data type (including objects and functions!).

2. WeakMap and WeakSet (Garbage-Collection Safe):
- Keys MUST be Objects (cannot use primitives).
- Holds 'weak' references to keys: If no other reference to the key object exists, the entry is automatically garbage-collected from memory.
- Not Iterable (no `.size`, no `.keys()`, no `forEach`) because garbage collection timing is non-deterministic.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Unique Sets and WeakMap Private Metadata ---
// 1. Instant Array De-duplication with Set:
const duplicateRolls = [101, 102, 101, 103, 102, 104];
const uniqueRolls = [...new Set(duplicateRolls)];
console.log('Unique Rolls:', uniqueRolls); // [101, 102, 103, 104]

// 2. Private Metadata with WeakMap:
const privateMetadata = new WeakMap();
let studentObj = { name: 'Swadeep' };

privateMetadata.set(studentObj, { secretPin: '9942', attendanceScore: 98 });
console.log('Secret PIN:', privateMetadata.get(studentObj).secretPin);

Teacher's Note on Example 1:
Set ensures uniqueness; WeakMap stores private metadata without memory leaks.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Trying to iterate WeakMap: WeakMap has no .forEach or .size. It is designed solely for private key-based lookups.

[!] Primitive keys in WeakMap: Writing `weakMap.set('key', val)` throws a TypeError: Invalid value used as weak map key.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Set stores unique values; Map stores key-value pairs with arbitrary key types.
• WeakMap and WeakSet hold weak object references, preventing memory leaks.
• Use [...new Set(arr)] for instant, clean array de-duplication.
