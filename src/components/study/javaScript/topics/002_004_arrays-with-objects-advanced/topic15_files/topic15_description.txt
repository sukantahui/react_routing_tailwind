3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Multi-Key Indexing Architecture:
Maintaining dedicated lookup Maps for each indexed field:
- `byRoll: Map<Roll, Student>`
- `byEmail: Map<Email, Student>`
- `byCourse: Map<Course, Set<Student>>`

2. CRUD Operations on Indexed Stores:
When a student is added, updated, or removed, all corresponding index maps must be updated synchronously to maintain relational integrity.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Multi-Key In-Memory Index Store ---
class StudentStore {
  constructor() {
    this.byRoll = new Map();
    this.byEmail = new Map();
  }
  
  addStudent(student) {
    this.byRoll.set(student.roll, student);
    this.byEmail.set(student.email.toLowerCase(), student);
  }
  
  findByRoll(roll) { return this.byRoll.get(roll); }
  findByEmail(email) { return this.byEmail.get(email.toLowerCase()); }
}

const store = new StudentStore();
store.addStudent({ roll: 101, name: 'Swadeep', email: 'swadeep@lab.com' });

console.log('Found by Roll:', store.findByRoll(101).name); // 'Swadeep'
console.log('Found by Email:', store.findByEmail('swadeep@lab.com').name); // 'Swadeep'

Teacher's Note on Example 1:
Dual Map indexes provide O(1) lookups across different search fields.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Stale index entries on deletion: Deleting a record from the master array without deleting it from secondary index maps leaves ghost records in memory.

[!] Case sensitivity in email lookups: Always normalize search strings (e.g. .toLowerCase().trim()) before indexing.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Multi-key indexing supports multiple fast search criteria simultaneously.
• Synchronize all index maps during create, update, and delete operations.
• Powers high-performance client-side search engines and in-memory caches.
