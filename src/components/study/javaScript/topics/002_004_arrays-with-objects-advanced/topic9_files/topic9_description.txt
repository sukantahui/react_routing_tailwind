1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Think about ranking athletes at the Olympic Games. If two athletes finish a race with the exact same time (Tie on Field 1), how do you decide who gets the silver medal? You look at their photo-finish milliseconds (Field 2). If those are equal, you look at their qualifying score (Field 3). In JavaScript, Multi-Field Sorting compares secondary fields whenever primary fields tie!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Tuhina and Debangshu tied with the exact same marks (95 marks) in the final exam. When sorting by marks alone, JavaScript left their order arbitrary. The lab director requested: 'If marks are equal, sort alphabetically by student name!'. I showed Tuhina the multi-field comparator: `(a, b) => (b.marks - a.marks) || a.name.localeCompare(b.name)`. Because `b.marks - a.marks` is 0 (falsy), the `||` operator short-circuits to the alphabetical check!

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. Multi-Field Comparator Pattern:
`const compare = (a, b) => (primaryComparison) || (secondaryComparison) || (tertiaryComparison)`
- If primary comparison is non-zero (truthy), it decides the order immediately.
- If primary comparison is 0 (tied/falsy), `||` cascades to evaluate the secondary comparison.

2. String Sorting with localeCompare:
Always use `a.name.localeCompare(b.name)` for accurate alphabetical sorting with proper Unicode and language accents.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Multi-Field Sort: Highest Marks first, then Alphabetical on Ties ---
const leaderboard = [
  { name: 'Swadeep', marks: 88, attendance: 90 },
  { name: 'Tuhina', marks: 95, attendance: 92 },
  { name: 'Debangshu', marks: 95, attendance: 88 },
  { name: 'Abhronila', marks: 88, attendance: 95 }
];

// Sort: Marks DESC → If tied, Name ASC (Alphabetical)
const sortedLeaderboard = leaderboard.toSorted((a, b) => 
  (b.marks - a.marks) || a.name.localeCompare(b.name)
);

console.log('Final Merit List:');
sortedLeaderboard.forEach((s, i) => console.log(`#${i + 1} ${s.name} - ${s.marks} Marks`));

Teacher's Note on Example 1:
Short-circuit OR cascades to name comparison only when marks are identical.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Using subtraction on strings: `a.name - b.name` results in `NaN`! Always use `a.name.localeCompare(b.name)` for strings.

[!] Mutating source array during analysis: Always use `.toSorted()`.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Multi-field sorting cascades using the `(compareA) || (compareB)` pattern.
• Use `localeCompare()` for robust alphabetical string comparisons.
• Essential for merit lists, leaderboards, and complex data analysis.
