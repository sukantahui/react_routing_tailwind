1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Imagine locking an office document: Level 1 (Prevent Extensions): You can edit and delete existing pages, but cannot staple any NEW pages to the document. Level 2 (Seal): You can still edit the text on existing pages, but cannot add NEW pages OR tear out existing pages. Level 3 (Freeze): The document is encased in unbreakable solid ice—no adding, no deleting, no editing of any kind! In JavaScript, these are the 3 tiers of Object Immutability.

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Abhronila was building an application configuration object: `const CONFIG = { API_URL: 'https://api.lab.com' };`. A junior developer accidentally overwrote `CONFIG.API_URL = 'http://hacked.com'`. Abhronila panicked: 'I used `const`, so why was the property modified?' I explained that `const` only prevents variable reassignment; it does NOT freeze the object's inner properties! I showed her `Object.freeze(CONFIG)`. Now, any attempt to modify `CONFIG` was blocked completely.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The 3 Immutability Levels:
- Object.preventExtensions(obj): Disallows adding new properties. Existing properties can still be modified or deleted.
- Object.seal(obj): Disallows adding new properties and deleting existing properties. Existing properties can still be edited if `writable: true`.
- Object.freeze(obj): Highest immutability level. Sets `writable: false` and `configurable: false` on all own properties. No adding, deleting, or editing allowed!

2. Shallow Freezing Warning:
`Object.freeze()` is shallow! Nested objects inside a frozen object are still mutable unless deep-frozen recursively.

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Testing Object.freeze and Object.seal ---
const appConfig = Object.freeze({
  center: 'Barrackpore',
  maxStudents: 50
});

// Attempts to modify are blocked in strict mode:
// appConfig.maxStudents = 100; // TypeError in strict mode!
console.log('Frozen maxStudents:', appConfig.maxStudents); // 50
console.log('Is Frozen?', Object.isFrozen(appConfig));     // true

Teacher's Note on Example 1:
Object.freeze creates completely immutable object records.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Confusing const with Object.freeze: `const` prevents reassigning the variable pointer. `Object.freeze` prevents mutating properties inside the object.

[!] Shallow freeze trap: Frozen objects do NOT freeze nested objects. Write a deepFreeze helper if nested freezing is required.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Object.preventExtensions() blocks additions.
• Object.seal() blocks additions and deletions.
• Object.freeze() blocks additions, deletions, and modifications (100% read-only).
