1. THE REAL-WORLD HOOK & INTUITIVE ANALOGY
--------------------------------------------------------------------------------
Imagine checking if a student is carrying a pen. Case 1: The student has their OWN personal pen in their pocket (Own Property). Case 2: The student borrowed a pen from the classroom teacher sitting on the table (Inherited Prototype Property). How do you know if the pen belongs personally to the student or was inherited? In JavaScript, `Object.hasOwn()` checks for personal ownership!

2. BARRACKPORE LAB CLASSROOM SCENARIO & PERSONAL IMPROVISATION
--------------------------------------------------------------------------------
Swadeep had an object created with `Object.create({ course: 'JavaScript' })`. When he checked `'course' in student`, it returned `true`. But when he checked `Object.hasOwn(student, 'course')`, it returned `false`! Swadeep asked why. I diagrammed the Prototype Chain: The `in` operator checks both the object itself AND all its prototype ancestors. `Object.hasOwn()` checks strictly if the object owns that property personally.

3. STEP-BY-STEP CONCEPTUAL BREAKDOWN (WHITEBOARD EXPLANATION)
--------------------------------------------------------------------------------
1. The Three Existence Checks:
- `key in obj`: Returns true if property exists anywhere on the object OR its prototype chain.
- `obj.hasOwnProperty(key)`: Legacy ES5 method checking own properties (can fail if object overrides hasOwnProperty or has null prototype).
- `Object.hasOwn(obj, key)`: Modern ES2022 standard static method that reliably checks own properties across all objects safely.

2. Checking for Undefined vs Existence:
If an object has `const obj = { age: undefined };`, `obj.age !== undefined` is `false`, but `'age' in obj` is `true`!

4. GROUNDED PRACTICAL CODE EXAMPLES (PROGRESSIVE LEARNING)
--------------------------------------------------------------------------------
--- Example 1: Testing Property Existence Safely ---
const prototypeTeacher = { school: 'Coder & AccoTax' };
const student = Object.create(prototypeTeacher);
student.name = 'Swadeep';
student.marks = undefined; // Explicitly set to undefined

// 1. in operator (checks own + prototype chain):
console.log('school in student:', 'school' in student); // true (Inherited)
console.log('name in student:', 'name' in student);     // true (Own)

// 2. Object.hasOwn (checks OWN properties only):
console.log('hasOwn name:', Object.hasOwn(student, 'name'));     // true
console.log('hasOwn school:', Object.hasOwn(student, 'school')); // false
console.log('hasOwn marks:', Object.hasOwn(student, 'marks'));   // true (Exists despite undefined!)

Teacher's Note on Example 1:
Object.hasOwn reliably verifies direct property ownership.

5. COMMON TRAPS, ROOKIE MISTAKES & SENIOR PRO BEST PRACTICES
--------------------------------------------------------------------------------
[!] Using `obj.hasOwnProperty` on null-prototype objects: `Object.create(null).hasOwnProperty('a')` throws a TypeError! Always use `Object.hasOwn(obj, 'a')`.

[!] Checking existence with `if (obj.prop)`: Fails if the property value is 0, false, or '' (all falsy). Use `Object.hasOwn()` or `'prop' in obj`.

6. KEY TAKEAWAYS & REVISION SUMMARY
--------------------------------------------------------------------------------
• Use `in` to check if a property exists on the object or its prototype chain.
• Use `Object.hasOwn(obj, prop)` (ES2022) to safely check direct property ownership.
• Never use falsy checks `if (obj.key)` to test for property existence.
