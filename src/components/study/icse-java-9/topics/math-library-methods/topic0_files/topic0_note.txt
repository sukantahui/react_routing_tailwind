ICSE CLASS 9 COMPUTER APPLICATIONS - STUDY NOTES
CHAPTER: MATHEMATICAL LIBRARY METHODS (java.lang.Math)
TOPIC 0: Math.pow(x, y) - Exponential Power Method

1. METHOD SPECIFICATION:
   - Signature: public static double pow(double a, double b)
   - Belongs to: java.lang.Math (automatically imported in all Java files)
   - Purpose: Returns the value of the first argument raised to the power of the second argument (a^b).
   - Return Type: ALWAYS 'double', regardless of whether arguments are int, float, or double.

2. CORE RULES & RETURN BEHAVIOR:
   a) Math.pow(2, 3) evaluates to 8.0 (NOT integer 8).
   b) Storing in an integer variable requires explicit type casting:
      int p = (int) Math.pow(2, 3);
   c) Any number raised to 0 is 1.0:
      Math.pow(99, 0) -> 1.0
      Math.pow(0, 0)  -> 1.0
   d) Negative base with even power produces positive double:
      Math.pow(-4, 2) -> 16.0
   e) Negative base with odd power produces negative double:
      Math.pow(-4, 3) -> -64.0
   f) Negative exponent produces reciprocal:
      Math.pow(4, -1) -> 0.25 (1.0 / 4.0)

3. ALGEBRAIC TO JAVA EXPRESSION CONVERSION:
   - x^2 + y^2        => Math.pow(x, 2) + Math.pow(y, 2)
   - (a + b)^3        => Math.pow(a + b, 3)
   - 2 * r^2          => 2 * Math.pow(r, 2)
   - x^(1/3) (Warning)=> Math.pow(x, 1.0 / 3.0) [Note: 1/3 in integer division is 0!]

4. COMMON ICSE BOARD EXAMINATION TRAPS:
   - Trap 1: Writing 'int ans = Math.pow(3, 2);' -> Results in Type Mismatch Compile Error (double cannot be converted to int without cast).
   - Trap 2: Missing the 'Math.' class prefix. Calling 'pow(x, y)' directly without static import will cause compilation error.
   - Trap 3: Writing Math.pow(8, 1/3). Since 1/3 is integer division evaluating to 0, Math.pow(8, 0) results in 1.0 instead of 2.0! Always write 1.0/3.0.
